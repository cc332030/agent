= Agent 规范安装

在目标项目根目录创建入口文档，文件名取值：默认 `AGENTS.adoc`；根目录**已存在** `AGENTS.md` 时紧随其后用 `AGENTS.md`（先查 `AGENTS.adoc`，再查 `AGENTS.md`）。

**入口文档是本流程唯一持久化到目标项目的产物**：一次会话结束后，下一个会话（或另开的新实例）只能看到**落到项目里的文件**——故凡"要跨会话、跨实例继续成立"的信息（规范副本的落点、本机与项目共用的那些约定）**一律写进入口文档内容**，不得只留在安装过程或会话里。**该写什么、不写什么**的判据（最小集、与临时产物的分界）见 `specs/general/entry-doc.adoc`——那是判据的唯一真源，本文件不重复其条文。

**本流程可重复执行、且以远程为准**：安装脚本（本文件与随规范分发的取文件抓手）会持续更新，任何时候再执行一次都应拿到**当前最新**的一份——入口文档按下面的形态幂等核对后**就地更新为最新入口占位**（保留项目自身内容），本地规范副本按**远程内容**核对、远程改过即以远程为准（详见「重复执行（更新）时的行为」）。

== 取规范到本地副本

入口的"取到本地副本"不要手工逐条下载：规范集合由 `script/fetch-specs.py`（跨环境脚本）承载**一次取全**，各平台入口已备好、调用方只给脚本名即可。本节只给**安装流程要用到的落点与取回口径**；参数、行为与副作用等脚本自身的规格以**脚本头部注释**为准（那是它的唯一真源，本节不复述），解释器兜底见下一条：

* 脚本地址：https://agent.c332030.com/script/fetch-specs.py（Linux/macOS 另有 `fetch-specs.sh`、Windows 另有 `fetch-specs.bat`，与脚本同目录、主名相同）。
* 用法：把脚本（与其平台入口）取到上面那个路径下，在**项目根目录**执行一次即可；来源可用 `--base` 改；**默认以远程为准**——每份文件取回的字节与本地不同才落盘，远端改过就刷新、一致则不动，重复执行**即是更新**（要"不动本地那份"加 `--keep`）。**取不到时按退出码判**（0 成功、1 有文件没取到、2 参数或前置条件错误），非 0 就别把副本当已就绪。
* **落点只有一处**：上面模板里写的那个 `~/.cache/agent-specs`（用户家目录下的一处）——不分系统、不分环境都是这一个路径；其下按来源地址分槽，**同一台机器上的所有项目共用这一份**——同一个文件不因项目数而下载多遍；换过来源的副本互不覆盖。脚本**不删除落点里的任何文件**（要清理由人来做）。家目录取不到时**报错退出**（不静默换个地方落副本，"副本在哪"才对得上入口文档写的那一个路径）。
**下载的东西一律只落这一个地方**：规范副本、取规范脚本（`fetch-specs.py` 及其同名入口 `fetch-specs.sh` / `fetch-specs.bat`）、清理脚本 `clean_tmp.py`——凡从本仓库下载来的文件**都落在这一个路径下**，既不在项目里另留副本，也不手工挪去别处。取规范脚本一次运行即把这几份安装脚本一并落到该处（安装脚本落在落点根下、跨来源共用；规范副本落在按来源地址分的槽里），下次重装直接跑那里的入口即可，不必再手工下载一遍。
* **清单从入口自身解析**：脚本按 `AGENTS_COMMON.adoc` 的加载调度器登记自动解析要取哪些 `specs/...`，故新增一份规范**不需要改脚本、也不会漏取**——不要自己另外拼一份文件清单。
* 这份本地副本只用于读取（相对解析基准不变），**不替代入口地址**；网络正常时也可直接读远程入口。

* **解释器兜底（不必先自己装 python）**：两个入口都按次序探测解释器、用探测到的那个运行逻辑代码：
** Linux/macOS：先取 `python3`、没有再取 `python`——覆盖**只装了 python2** 的发行版（CentOS/RHEL 8 及更早、老 macOS）。
** Windows：先取 `py -3` 启动器、再取 `python3`、最后 `python`——覆盖只装了官方 py 启动器、或只有 Store 别名的机器。
** **连一个都没有**时脚本报一句错并退出非 0，**不静默继续**。此时按你的环境装一个 python 3 再重跑，或直接读远程入口地址。

== 取规范时连 python 都没有

上面那一步需要**一个 python 解释器**（逻辑层是 Python 脚本；两个入口已按次序探测）。**机器上一个 python 都没有**时，取规范这一步会**报一句错并退出非 0**（错误信息与**退出码**：脚本报错、**非 0** 退出，**不得静默继续**）——**此时规范仍然要取到**，按下面的次序走：

注意这里说的是**一个都没有**：只装了 python2 的发行版不算，上一条的次序会取到 `python`，脚本照样能跑。

* **先按本平台既有的软件分发方式装一个 python 3**（Linux 用发行版包管理器、macOS 用 Homebrew/官方安装器、Windows 用 `py` 启动器的官方安装器）。这是**人**的一步，**不是脚本的一步**——入口**不得**代为安装/下载运行时：它会改变系统状态、要管理员权限、失败方式因环境而异，且"装什么、从哪装、改了什么"对调用方不可预期。
* **本脚本报错退出，不等于"这一步可以跳过"**：退出码 1/2 是给调用方判定的信号，**不是**"继续往下走也差不多"。
* **让 AI 在能看见命令与报错的会话里去做**：这类"环境缺件"的处置交给 agent 在本机正常执行即可，但**不得**在入口或非交互执行里静默进行。
* **不装解释器的替代路径**：如果连装一个运行时都不允许（离线、无权限、精简镜像），**直接读远程入口地址**即可——本规范在网络上就是这套文件，不取副本也能读。**不建议**改用 `curl … | python3 -` 那条远程执行形态绕开：**它同样要 python**。

**取不到不该是终点，但取到的方式不该由入口决定**：把"怎么让这个运行时可用"留给**人**（或能看见报错的会话里的 agent），入口只负责"没有就报清楚、退出非 0"。这样"取规范"这一步失败时，你能一眼看出卡在**环境缺件**、而不是卡在规范本身。

== 重复执行（更新）时的行为

安装不是一次性的（见开头"本流程可重复执行、且以远程为准"）：任何时候都可以再执行一次，**判据是内容、不是时间**：

* **入口文档（幂等）**：先按上面的规则判命中哪个文件名（`AGENTS.adoc` → `AGENTS.md`，取**第一个命中者**），再核对其内容：
** 已含上段代码块的入口占位、且**与最新模板逐字一致**（含换行与空行）：不动。
** 已含入口占位但**与最新模板不一致**：**就地更新为最新模板的那几行**，保留其后的项目自身内容；**不得**因此改名、迁移或另建第二个入口文档。
** **没有**入口占位：**在开头融合**（它可能与项目自身规范合写在同一文件里，此时不新增文件、只在开头补上入口占位）；若该文件已指向本入口，不重复追加。
** **用户改过的行以用户改过的为准**：**用户手工编辑过的模板内容一律照原文保留**——不符合本模板时**不自动改回**，只在汇报里指出不一致、等用户定（**不得**拿模板盖掉人的手写，见 `specs/general/scope.adoc`「只改当前工作空间」与「拒绝的形态」：未获用户声明时，"按模板修正"也算改动用户的文件）。
** 用户/项目自己在入口文档里追加的内容：**只补缺的、不覆盖已填入的**（模板不预填与项目无关的清单）。
** 该文件的其余内容**（项目自身规范、约定）：**原样保留**。
* **规范副本（以远程为准）**：在项目根目录再跑一次取文件抓手即可——落点、取回与更新口径见上「取规范到本地副本」，此处不重复。
* **报红就地修复**：任何一步非 0 或与预期不符，先如实说明卡在哪一步（网络、解释器缺失、参数），**不要**把"以前取到过一份"当成"这次装好了"。
* **与项目自身规范的关系（重复执行同样成立）**：项目自身规范优先于通用规范。本项目自己写的规则**不因重新执行安装而被改写或删除**；本流程只动入口占位与规范副本这两处。

* 融合做法：保留原文档全部内容，在开头添加上面的入口占位；若原文档已指向本入口，则不重复追加。项目自身规范优先于通用规范。
