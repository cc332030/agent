== 取规范到本地副本

入口的"取到本地副本"不要手工逐条下载：规范集合由 `script/fetch-specs.py`（跨环境脚本）承载**一次取全**，各平台入口已备好、调用方只给脚本名即可：

* 脚本地址：https://agent.c332030.com/script/fetch-specs.py（Linux/macOS 另有 `fetch-specs.sh`、Windows 另有 `fetch-specs.bat`，与脚本同目录、主名相同）。
* 用法：把脚本（与其平台入口）取到任意位置，在**项目根目录**执行一次即可；来源可用 `--base` 改；**默认以远程为准**——每份文件取回的字节与本地不同才落盘，远端改过就刷新、一致则不动，重复执行**即是更新**（要"不动本地那份"加 `--keep`，那时它也退化成"只补缺失项"）。**取不到时按退出码判**（0 成功、1 有文件没取到、2 参数或前置条件错误），非 0 就别把副本当已就绪。
* **落点默认是本机用户级缓存**：默取平台用户级缓存目录（Linux/macOS 取 `XDG_CACHE_HOME`、未设时用 `~/.cache`；Windows 取 `%LOCALAPPDATA%\.cache`）下按来源分槽的目录，**同一台机器上的所有项目共用这一份**——同一个文件不因项目数而下载多遍；缓存内容按来源分槽，换过来源的副本互不覆盖；脚本**不删除缓存里的任何文件**（要清理由人来做）。加 `--local` 改取**项目内临时目录 `tmp/agent-specs/`**（入口模板里的退路落点，按临时产物随项目清理，故 `tmp*` 须加进 `.gitignore`）；缓存不可得（环境变量与家目录都取不到）或来源是本机地址（`localhost`/回环 IP，内容可能每次都在变）时**自动退回项目内落点**；可用 `--cache-dir` 或环境变量 `AGENT_SPECS_CACHE` 改缓存落点。
* **清单从入口自身解析**：脚本按 `AGENTS_COMMON.adoc` 的加载调度器登记自动解析要取哪些 `specs/...`，故新增一份规范**不需要改脚本、也不会漏取**——不要自己另外拼一份文件清单（实测失效：手工清单漏掉了 `specs/`，且内联命令的转义逐次出错）。
* 这份本地副本只用于读取（相对解析基准不变），**不替代入口地址**；网络正常时也可直接读远程入口。

* **解释器兜底（不必先自己装 python）**：两个入口都按次序探测解释器、用探测到的那个运行逻辑代码，都不是"必须先装好某个解释器"：
** Linux/macOS：先取 `python3`、没有再取 `python`——覆盖**只装了 python2** 的发行版（CentOS/RHEL 8 及更早、老 macOS），这类机器上 `python` 是 python2，取到它总比取不到强。
** Windows：先取 `py -3` 启动器、再取 `python3`、最后 `python`——覆盖只装了官方 py 启动器、或只有 Store 别名的机器（这类机器上 `python3` 常常解析不到）。
** **连一个都没有**（机器上没装任何 python）时脚本报一句错并退出非 0，**不静默继续**——静默继续会把"没取到规范"混进"取到了"。此时按你的环境装一个 python 3 再重跑，或直接读远程入口地址。

注意这里说的是**一个都没有**：只装了 python2 的发行版（CentOS/RHEL 8 及更早、老 macOS）不算，上一条的次序会取到 `python`，脚本照样能跑。

* **先按本平台既有的软件分发方式装一个 python 3**（Linux 用发行版包管理器、macOS 用 Homebrew/官方安装器、Windows 用 `py` 启动器的官方安装器）。这是**人**的一步，**不是脚本的一步**——入口**不得**代为安装/下载运行时：它会改变系统状态、要管理员权限、失败方式因环境而异，且"装什么、从哪装、改了什么"对调用方不可预期。
* **本脚本报错退出，不等于"这一步可以跳过"**：退出码 1/2 是给调用方判定的信号，**不是**"继续往下走也差不多"——按上文说明处置完（装解释器、或改读远程入口）再继续；跳过它去装配其他东西，最后会落一份**残缺的规范副本**。
* **让 AI 在能看见命令与报错的会话里去做**：这类"环境缺件"的处置交给 agent 在本机正常执行即可（它看得见报错、能按上面那条选到本平台的分发方式），但**不得**在入口或非交互执行里静默进行。真取不到时如实说明卡在哪一步，不要默默跳过。
* **不装解释器的替代路径**：如果连装一个运行时都不允许（离线、无权限、精简镜像），**直接读远程入口地址**即可——本规范在网络上就是这套文件，不取副本也能读（代价是受网络质量影响、也拿不到"一次取全"的本地副本）。**不建议**改用 `curl … | python3 -` 那条远程执行形态绕开：**它同样要 python**，只是把"取不到"换成了"执行不了"。

**取不到不该是终点，但取到的方式不该由入口决定**：把"怎么让这个运行时可用"留给**人**（或能看见报错的会话里的 agent），入口只负责"没有就报清楚、退出非 0"。这样"取规范"这一步失败时，你能一眼看出卡在**环境缺件**、而不是卡在规范本身。

== 重复执行（更新）时的行为

安装不是一次性的：本文件与随规范分发的抓手都在更新，故**任何时候都可以再执行一次**，按"**以远程为准**"把事情做对——判据是**内容**、不是时间，也不是"本地以前取过什么"：

* **入口文档（幂等）**：先按上面的规则判命中哪个文件名（`AGENTS.adoc` → `AGENTS.md`，取**第一个命中者**），再核对其内容：
  ** 已含上段代码块的**入口占位，且**与最新模板逐字一致**（含换行与空行）：不动。
  ** 已含入口占位但**与最新模板不一致**（本流程更新过、模板行被改过）：**就地更新为最新模板的那几行**，保留其后的项目自身内容；**不得**因此改名、迁移或另建第二个入口文档。
  ** **没有**入口占位：**在开头融合**（它可能与项目自身规范合写在同一文件里，此时不新增文件、只在开头补上入口占位）；若该文件已指向本入口（`AGENTS_COMMON.adoc` 或其 URL），不重复追加。
  ** 模板末尾的**「本项目持久化到入口文档的信息」这一节**：**只补缺失的那一节、**不覆盖已被填入的项目内容**——入口文档是项目自己的文件，那一节记的是**本项目**要跨会话保留的信息（见 `specs/general/entry-doc.adoc`）。
  ** 该文件的其余内容**（项目自身规范、约定）：**原样保留**。
* **规范副本（以远程为准）**：在项目根目录再跑一次取文件抓手即可（只给脚本名，默认取到用户级缓存、落不到则取项目内 `tmp/agent-specs/`，用法见下节）。它把清单内每份文件**取回的字节与本地比较**，**不同才落盘**——远端改过就刷新、一致就一个字节都不动；取不回来时**保留本地已有的那一份**并如实报失败（不会把副本删掉换成没有）。结果分三态打印（新取 / 刷新 / 内容一致），按**退出码**判成败（0 成功、1 有文件没取到、2 参数或前置条件错误）。
* **要"不动本地那份"时**加 `--keep`（本地已有且非空即不取、只补缺失项）：它换来的是"本地副本可能落后于远端"，故**安装流程按默认的"以远程为准"走、不加它**；确实需要保留本地改动的副本时，另用 `--out` 取到别的落点、把原落点腾出来给规范用。
* **报红就地修复**：任何一步非 0 或与预期不符，先如实说明卡在哪一步（网络、解释器缺失、参数），**不要**把"以前取到过一份"当成"这次装好了"。
* **与项目自身规范的关系（重复执行同样成立）**：项目自身规范优先于通用规范。本项目自己写的规则**不因重新执行安装而被改写或删除**；本流程只动入口占位与规范副本这两处。

* 安装过程只新增入口占位与临时副本，不改动目标项目的其他文件；副本按临时产物处理（默认落在用户级缓存，项目内 `tmp/` 那份是缓存不可用时的退路，故 `tmp*` 已加进 `.gitignore`）。
