= Agent 规范安装

在目标项目根目录创建入口文档，文件名取值：默认 `AGENTS.adoc`；根目录**已存在** `AGENTS.md` 时紧随其后用 `AGENTS.md`（先查 `AGENTS.adoc`，再查 `AGENTS.md`）。

下面代码块内的内容必须**逐字原样**复制到新建的入口文档中：保留全部换行与空行，不得合并、折叠、删除或重排任何一行，不得改写任何文字——逐字符与代码块内容完全一致（仅去除代码块定界符 `----` 与语言标识 `[source,asciidoc]`）。

创建入口文档，内容为：

[source,asciidoc]
----
= Agent 规范入口

本项目的 agent 执行规范入口为：

https://agent.c332030.com/AGENTS_COMMON.adoc

优先取到临时目录 tmp（避免网络原因无法访问；需要最新规范再更新）：在项目根目录运行一次该抓取脚本，它会把本入口与其引用的 specs/ 规范一并取到 `tmp/agent-specs/`（只给脚本名即可，无需逐条下载）。

读取该入口及其引用的 specs/ 规范，并持续遵守其全部要求。

规范属强制约束：**开工前必须先读取规范再执行**，不得因未读取/记不全而跳过或放宽任何条款。
----

同时将 tmp* 加入到 .gitignore

== 取规范到本地副本

入口的"取到本地副本"不要手工逐条下载：规范集合由 `script/fetch-specs.py`（跨环境脚本）承载**一次取全**，各平台入口已备好、调用方只给脚本名即可：

* 脚本地址：https://agent.c332030.com/script/fetch-specs.py（Linux/macOS 另有 `fetch-specs.sh`、Windows 另有 `fetch-specs.bat`，与脚本同目录、主名相同）。
* 用法：把脚本（与其平台入口）取到项目内任意位置，在**项目根目录**执行一次即可；来源可用 `--base` 改；已存在的文件默认跳过（增量），需要最新内容加 `--force`。**取不到时按退出码判**（0 成功、1 有文件没取到、2 参数或前置条件错误），非 0 就别把副本当已就绪。
* **落点默认是共享缓存，不在每个项目里各存一份（推荐）**：默认落到**平台用户级缓存目录**（Linux/macOS 取 `XDG_CACHE_HOME`、未设时用 `~/.cache`；Windows 取 `%LOCALAPPDATA%\Cache`；可用 `--cache-dir` 或环境变量 `AGENT_SPECS_CACHE` 改），**同一台机器上的所有项目共用这一份**——同一个文件不因项目数而下载多遍，缓存跨项目复用；缓存内容按来源地址分槽，换过来源的副本互不覆盖；脚本**不删除缓存里的任何文件**（要清理由人来做）。需要项目内副本时加 `--local`（落到当前项目下的 `tmp/agent-specs/`，可用 `--out` 改），该副本按临时产物随项目清理；来源是本机地址（`localhost`/回环 IP）时自动退回项目内落点（本地服务端内容可能每次都在变，不缓存）。
* **清单从入口自身解析**：脚本按 `AGENTS_COMMON.adoc` 的加载调度器登记自动解析要取哪些 `specs/...`，故新增一份规范**不需要改脚本、也不会漏取**——不要自己另外拼一份文件清单（实测失效：手工清单漏掉了 `specs/`，且内联命令的转义逐次出错）。
* 这份本地副本只用于读取（相对解析基准不变），**不替代入口地址**；网络正常时也可直接读远程入口。

* **解释器兜底（不必先自己装 python）**：两个入口都按次序探测解释器、用探测到的那个运行逻辑代码，都不是"必须先装好某个解释器"——Linux/macOS 取 `python3`、没有再取 `python`（覆盖只装 python2 的发行版，如 CentOS/RHEL 8 及更早）；Windows 取 `py -3` 启动器、再取 `python3`、最后 `python`（覆盖只有 Store 别名或只装了 py 启动器的机器）。**连一个都没有**（机器上没装任何 python）时脚本报一句错并退出非 0（不静默继续）——此时按你的环境装一个 python 3 再重跑即可，或直接读上面的远程入口地址。

== 取规范时连 python 都没有

上面那一步需要**一个 python 解释器**（逻辑层是 Python 脚本；两个入口已按次序探测，见上条）。**机器上一个 python 都没有**时，取规范这一步会报一句错并退出非 0（退出码按脚本头部说明；不静默失败）——**此时规范仍然要取到**，按下面的次序走：

* **先按本平台既有的软件分发方式装一个 python 3**（Linux 用发行版包管理器、macOS 用 Homebrew/官方安装器、Windows 用 `py` 启动器的官方安装器）。这是**人**的一步，**不是脚本的一步**——入口**不得**代为安装/下载运行时：它会改变系统状态、要管理员权限、失败方式因环境而异，且"装什么、从哪装、改了什么"对调用方不可预期。
* **让 AI 在能看见命令与报错的会话里去做**：这类"环境缺件"的处置交给 agent 在本机正常执行即可（它看得见报错、能按上面那条选到本平台的分发方式），但**不得**在入口或非交互执行里静默进行。真取不到时如实说明卡在哪一步，不要默默跳过。
* **不装解释器的替代路径**：如果连装一个运行时都不允许（离线、无权限、精简镜像），**直接读远程入口地址**即可——本规范在网络上就是这套文件，不取副本也能读（代价是受网络质量影响、也拿不到"一次取全"的本地副本）。**不建议**改用 `curl … | python3 -` 那条远程执行形态绕开：**它同样要 python**，只是把"取不到"换成了"执行不了"。

**取不到不该是终点，但取到的方式不该由入口决定**：把"怎么让这个运行时可用"留给**人**（或能看见报错的会话里的 agent），入口只负责"没有就报清楚、退出非 0"。这样"取规范"这一步失败时，你能一眼看出卡在**环境缺件**、而不是卡在规范本身。

== 已存在 AGENTS 文档

先检查目标项目根目录是否已存在 agent 规范文档，按 `AGENTS.adoc` → `AGENTS.md` 顺序取**第一个命中者**：

* 都不存在：新建 `AGENTS.adoc` 并写入上面的入口占位。
* `AGENTS.adoc` 存在：就在它上面融合，**不覆盖、不删除**、不另建 `AGENTS.md`。
* 仅 `AGENTS.md` 存在：在它上面融合（文件名保持 `AGENTS.md`，**不重命名、不迁移**成 `AGENTS.adoc`）。
* 融合做法：保留原文档全部内容，在开头添加上面的入口占位；若原文档已指向本入口（`AGENTS_COMMON.adoc` 或其 URL），则不重复追加。项目自身规范优先于通用规范。

== 约束

* 只创建入口占位，不复制规范本体。
* 入口文档一律按**固定格式**（`= Agent 规范入口` 标题 + 入口地址 + 遵守要求）书写：`AGENTS.md` 同样承载该入口占位，不因扩展名不是 `.adoc` 就降级成一句"读某地址"或改写成别的格式。
* 代码块内容须逐字原样保留（换行与空行不得丢失），禁止改写格式或压缩排版。
* 安装过程只新增入口占位与临时副本，不改动目标项目的其他文件；副本按临时产物处理（`tmp/` 已在 `.gitignore` 内）。

完成后告知用户已创建或已融合（并说明落在 `AGENTS.adoc` 还是 `AGENTS.md`）。
