= 公共内容被加载时的可控性（维护方自查）

本文件只保留**维护方**需要的一节：**公共内容被未知项目加载时的可控性**（运行契约）——它是本仓库最有价值的初衷，也是"加得越多越容易忘掉"的那一条。

**其余内容已随公共内容归位**：「为什么控制上下文（业界依据）」「读取范围（最小必要）」「长会话治理」「执行前自检」写在 `specs/core/execution.adoc`「范围控制」与 `specs/general/context.adoc`（对任何项目成立）——本文件不重复表述。本文件由维护方的项目规范入口登记，**只在维护这套规范集合的项目中加载**。

== 运行契约（公共内容被未知项目加载时的可控性）

**判据本体在** `specs/general/verify.adoc`「运行契约」——三维（① 影响面 / ② 成本 / ③ 可控性）的定义、逐条判据与依据行都只在那里写一份，本文件**不重复其条文**（同一件事只在一处给真源，见 `specs/general/review.adoc`「精炼性」）。

本文件只写**维护方这一侧的落点差异**，其余一律按判据本体执行：

* **本仓库的"未知项目"具体指谁（L1）**：不是抽象读者，而是**按公共入口加载本仓库内容的任何一个引用方**——它看不到本仓库的工作副本、项目结构与内部约定。判定三维时以**"引用方拿到的只有入口 + `specs/` + `prompts/`"** 为基准，不以"本仓库里读得到"为基准。
* **改动说明的落点（L1）**：`specs/general/verify.adoc`「运行契约」要求的新条目接纳面留证，在本仓库落在**本次改动的提交说明或 PR 汇报**里（本仓库**不额外维护一份接纳面台账文件**——那会变成同一事实的第二处落点）。
* **越出三维的例外（L1）**：本仓库特有的私有物（`specs-project-maintainer/`、`library/`、`script/` 与随规范分发的取文件抓手）**不在引用方的加载面内**——公共内容里出现它们的**路径**即为死链（判据属上面那条的「不得让引用方依赖本仓库私有物」），但**依据图书馆里的落点引用不在此列**：图书馆按 `library/README.adoc`「依据的定位协议」由**固定地址**取值，不占引用方的加载面。
