= 公共内容被加载时的可控性（维护方自查）

本文件只保留**维护方**需要的一节：**公共内容被未知项目加载时的可控性**（运行契约）——它是本仓库最有价值的初衷，也是"加得越多越容易忘掉"的那一条。

**其余内容已随公共内容归位**：「为什么控制上下文（业界依据）」「读取范围（最小必要）」「长会话治理」「执行前自检（防越界）」写在 link:../specs/core/execution.adoc[]「范围控制」（必加载层，对任何项目成立）——本文件不重复表述。本文件登记在上层目录的 `AGENTS.adoc`，**只在维护这套规范集合的项目中加载**。

== 运行契约（公共内容被未知项目加载时的可控性）

公共内容（`AGENTS_COMMON.adoc` + `specs/` + `prompts/` + 会被引用方加载的工具）**不随本仓库的上下文生效，而是被未知项目加载**——本仓库看不到它的项目结构、已经存在的项目规范、依赖与工具链。故"加一条规则"不止要问"这条对不对"，还要问"**它落到一个未知项目里会发生什么**"：加得越多、优化越多，越容易忘掉这个初衷（引用方加载后出现不可控或未知效果）。

判定按**三维**逐维过（判据的语义复核落点见 link:../specs/general/testing.adoc[]「验证与运行契约」之「规范验证」之③接纳面；依据：ISO/IEC Directives Part 2 要求规范性文件引用现行文件、不作隐含要求；ISO/IEC/IEEE 29148 的需求须可追溯到干系人；ISO 9241-110 的交互原则——可控、可预期、不阻断）：

* **① 影响面（L1）**：这条规则会改变引用方的哪些既有行为？**与引用方自身规范的冲突次序**是否写明（公共规范与项目规范冲突以项目自身规范为准，见 `AGENTS_COMMON.adoc`「访问与解析」）；**不得出现"静默推翻引用方既有约定"的条目**——凡收紧/推翻既有做法者须显式授权（用户声明或引用方自身规范声明），并给出"不采用时怎么办"。
* **② 成本（L1）**：加载与遵守的代价是否说得清——**加载面体积**（每次会话都加载的部分应设可机械核对的上限，只写"要注意体积"不构成上限）、加载后的时延/token 开销、引入的依赖或工具链要求（含版本要求，且须给出不可用时的降级路径，见 link:../specs/core/execution.adoc[]「范围控制」（无能力走降级路径、不空自评））；**不得以"不贵"含糊带过**（ISO/IEC/IEEE 25010 性能效率）。
* **③ 可控性（L1）**：引用方是否**能预期、能关闭、能自行执行**——①**不得依环境自动动作**：不默认改动/格式化引用方文件、不默认代为提交、不默认清理其临时产物（须由其显式触发或用户声明）；②**不得让引用方依赖本仓库私有物**：条目不得引用引用方看不到的本仓库脚本名、仓库结构或私有约定（link:spec-lifecycle.adoc[]「规范集合的自身重构」"删"）；③**不得阻断**：规则不得让引用方在正常路径上无法完成工作（无降级路径的硬性前置一律不合规）。

* **新条目的接纳面须留证（L1）**：新增/调整公共内容时，须在改动说明（提交说明或汇报）中逐维写明"影响面 / 成本 / 可控性"的核对结论；**未核对不得计入验证通过**（本节的逐维判据与 link:../specs/general/testing.adoc[]「验证与运行契约」之「规范验证」③接纳面同源）。
