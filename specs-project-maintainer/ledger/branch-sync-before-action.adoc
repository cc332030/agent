== 落到哪

* 判据本体：`specs/general/git.adoc` 新增一节「动手前先确认当前分支与上游同步」（六条：触发面与后果、取值、不得丢本地成果、不成立时须明说、按任务核一次、与并入目标分支的分工）。
* 常驻层：`specs/core/CORE.adoc`「底线」新增一句（要求 + 取值 + 频次 + 回指）——**每次会话真正读到的只有这一层**，故两处都钉；判据正文不搬进常驻层。
* 检查侧：`check_branch_sync_guard` 两组规则数据（git 节内锚点六组 + CORE 的 bullet 锚点）；反例用例 `TestCheckBranchSyncGuard` 13 条（1 正例 + 12 反例：整节被删、触发面、取值、假绿形态、本地领先、不得丢本地成果、无上游、按任务核一次、与目标分支分工、常驻层整句被删、常驻层取值被抽、文件缺失）。
* 判准维度：同步本身按**严格执行**（二值），取不到远端那一支按**尽力而为**（须尝试、须说明、不记通过），见 `specs/general/verify.adoc`「判准维度」。

== 为什么落在通用层而不是常驻层

常驻层的准入判据是「每次都用得上的**底线**」：本条只有一句要求与一个取值可用，判定标准、边界（无上游 / 取不到远端 / 按任务核一次 / 与目标分支分工）与依据都要占篇幅——放进常驻层会把每次会话的加载体积抬上去，而它并不是"每一步都要照着念"的纪律，而是**动手前的一道闸**。故常驻层留一句、正文归通用层。

== 三视角复核后改了什么

复核指出四处会在未知项目里稳定失效，均已改：

* **判据可零成本自证**：`@{u}` 是本地跟踪引用（上次取回时的值），不取远端时 `HEAD..@{u}` 恒为 0——只看它，本条不取远端也算通过。改为「**先取远端当前指向**，再核上游一侧为空」，并把这一句钉进守卫锚点（不留这条，守卫等于固化一条错判据）。
* **与「并入目标分支」撞词**：`version-control.adoc`「压缩提交」与提示词 `baseline` 片段里的"同步"指**目标分支**，与本条（**上游**）不是同一件事。补了一条分工与取值（`@{u}` 一侧为空 ≠ 已并入目标分支最新），避免同一件事出现两种判准。
* **边界不写会把 L1 吞成免责话**：无上游、平台已 checkout 的一次性工作区都会命中——写明「不适用、不阻断」；取不到远端写明按**尽力而为**（尝试 + 说明 + 不记通过 + 不因此停下），与「做得到就不许停下来问」同向。
* **触发面过宽**：原写的"据代码现状给结论"覆盖一切问答式交互；收窄为「**据代码现状作判断并据此推进任务**」，纯解释不触发。
* 常驻层那句补了「在 git 工作区里」「当场取远端」「同一任务核一次」——只读常驻层的人也能拿到取值与频次，不会把本条读成"每步都 fetch"。
