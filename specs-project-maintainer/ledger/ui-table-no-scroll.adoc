| 本轮（表格尽量别出横纵滚动条；用真实数据渲染每张表、移除不必要滚动、必要时换行且不超三行、列宽自适应+上限，长值悬浮限量或单击详情） | 无（沿用 `check_ui_spec_guard` 扩面，不另建第二真源） | 219 → **219** | 用户口径：表格尽可能避免滚动条（水平与纵向）、验证时用真实数据渲染每张表展示真实效果、移除不必要滚动条，必要时列数据可换行（按实际定高度、一般不超过三行），列宽按数据实际取，最好是一套公共表格组件——列宽自适应+最大宽度（过长省略、悬浮显示内容且提示自身限宽不铺满屏幕），或单击单元格展示详情弹窗。判据本体落通用层 `specs/general/ui.adoc`「承载与呈现」新增条「表格优先不出现滚动条：先用真实数据证伪，再逐档处置」：同一产品共用一套公共表格组件（列宽算法、行高上限、长值处置、空/加载/错误态一处定义），默认目标横纵皆不滚，先用真实数据（实际条数+最长值，含长 URL/长标识/复合值）渲染核对，再按五档处置——调列宽 → 容长值换行（行高≤三行、取令牌一处）→ 省略号+悬浮全文（提示自身按视口限宽）→ 单击单元格开详情弹窗 → 真放不下才留纵向/横向滚动（固定表头一处、冻结标识列、两层纵向滚动禁止）。判定标准六条覆盖：预设滚动、短样例冒充无滚动、为消滚动压截断或撑到横滚、提示不限宽或省略号无全文入口、每张表各写一套、两层纵向滚动或冻结列缺失。边界：结果集本就长时固定表头下数据区纵向滚动属例外；验法回指 `specs/general/verify.adoc`「可判据的界面检查」（DOM/计算样式断言优先、取不到再取渲染快照），本仓库只给判据不落实现代码或检测脚本。取值口径落模板 `specs/general/ui-patterns.adoc`「四、高密度表格」：表格行「全部列都宽」改为先降列/换行、滚动是最后档，新增五档处置阶梯与公共表格组件一段；核对清单补一行；前端载体 `specs/stack/web.adoc`「表单与控件的尺寸（载体）」补一条表格无滚动条落点（不预设 overflow、长值处置链、断言优先）。加载门沿用「选容器或排表（含定控件宽高、表格要不要滚动条、这一格用什么控件）」与「会随数据长起来的界面」，常驻层只改四字、不加行。机械侧扩既有 `check_ui_spec_guard`：`UI_SPEC_PATTERN_ANCHORS` 补一组（min 22→34），ui-spec.toml 模板与栈层各补一组核点，`TestCheckUiSpecGuard` 补六条反例（本体/真实数据/悬浮限宽/模板阶梯/栈层载体/加载门）；有效性台账该条同步补覆盖说明。只钉文本与落点——「某张表真实数据下能不能排进一屏、某条提示该不该展开」属运行时事实与语义判断，交人/子 agent 复核。
| 返工一轮（列少时优先按数据宽度比例铺满整宽，是偏好不是必须） | 无（沿用 `check_ui_spec_guard` 扩面） | 219 → **219** | 用户补充口径：表格列少时可选择铺满整个宽度（是选择不是必须，也可按实际情况不铺满，取决于界面设计，但优先铺满），按数据宽度比例分宽度（不是几列等分），窗口大小由布局与设计决定、不为铺满去撑宽或出滚动。本体落 `specs/general/ui.adoc` 处置阶梯①「调列宽」后：列少（短样例、各列无长值压力）优先让各列按数据宽度比例铺满容器整宽、仍不越单列绝对上限，标为偏好非硬判据、由界面设计取舍，只在为消滚动硬撑长值列时才回到「不均分短字段」；核对清单补一句。取值口径落 `specs/general/ui-patterns.adoc` 处置阶梯①（按内容宽度比例分、不是等分、是偏好不是必须）；前端落点 `specs/stack/web.adoc` 补「按各列数据宽度比例铺满容器整宽」为公共组件默认偏好（`flex` 按内容宽度比例分配一类）、受单列上限约束。机械侧沿用 `check_ui_spec_guard`：`UI_SPEC_PATTERN_ANCHORS` 与 ui-spec.toml 模板组/栈层组各补锚点，`TestCheckUiSpecGuard` 补两条反例（本体偏好锚点、模板取值口径锚点被抽），有效性台账该条同步补覆盖说明。只钉文本与落点——「某张表是否铺满、铺满后好不好看」属界面设计与运行时事实，交人/子 agent 复核。
