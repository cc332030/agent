== 为什么这三格都该去掉，而不是换个地方记

* **序号**：次序已经在 `CHECKS` 序列里了——它是**位置**。再往表里写一遍数字，插入一项就得改其后每一行。
* **总数**：反例用例的类数由测试类名数得出来（`TestCheckXGuard` → `check_x_guard`）。抄一份的代价不只是多一处——同文件内删一条加一条也能维持总数，**删了什么一个也看不见**；而"这道防线还有没有反例"由**目录里那一份在不在**回答。
* **索引文件**：一份"谁在第几行、谁和谁一对"的表，等于把**同层同名**这条命名约定抄了一遍。

== 零字节标记文件的正当性

`<防线名>.adoc` 是**零字节**：那一格的话（判据、例外、边界）在它旁边 `.toml` 的注释里。
这个文件只回答一个问题——**这道防线有没有一份行正文**。于是它有三个好处、没有一个是"为了少改一处"换来的：

* 删防线时它一并消失；留着就是"不对应任何防线"的尸块，判据当场报红（**删了什么看得见**）。
* 新增防线时把两个文件放进同一层目录就完了，谁都不用登记（**目录即清单**）。
* 正文只有一处（在 `.toml` 里），`git log`/`git blame` 指着那份 `.toml` 就说得出这一格改了什么。

== 仍然会撞、且没有合并策略可解的那一处

新增/删除一道防线**本身**要同时动 `CHECKS`、自己那一份行正文、清单表表体——那是**独占动作**
（`specs/general/coding-file-role.adoc`「文件的角色」的例外①），各轮排队做，不为它去拆别处。
