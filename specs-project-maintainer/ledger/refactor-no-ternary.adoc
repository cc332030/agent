= 重构时也不许用三段式（写法判据在重构里同样成立）

|===
| 轮次 | 新增/删除防线 | 接线数 | 承接了什么

| 本轮（用户口径：『重构时也不允许三段式，我记得规范里写了，但是偶尔还是会使用』）
| **新增一道**：`check_refactor_style_guard`（「三元表达式为最低优先级」条**自己的正文**：L1 判定面 + 「重构也照此办」的适用面与判定标准 + 例外面 + 存量边界）
| 197 → **198**
| 把「三元表达式为最低优先级」升为 L1 并加写「**重构也照此办**」：该条对**任何**写下来的代码生效、不区分写新代码与重写既有代码（判定标准两条：新增或改写的那一行出现三段式；以「保持原样、减少 diff」为由保留该处）；例外面＝只搬动不改内容且确实换不动时原样搬动不算违规，存量边界＝未触达的存量随动迁移。要治的失效是**「写新代码」与「重写代码」被当成两套规则**——重构时只盯行为不变，同一句三段式被原样搬进新结构，规则对本次写的代码等于不成立。

| 第二轮（用户口径：『严禁三元，只允许简单三元，不带任何运算、任何函数调用』）
| 不新增防线，**加严既有那道**：`check_refactor_style_guard` 的锚点 10 → 13
| 198 → **198**
| 「可用的那一档」当场收窄成**简单三元**：`条件 ? 值 : 值` 的三个位置**各是一个原子**（变量、字面量、常量、字段取值），**三个位置都不带任何运算、不带任何函数调用**；带运算或带调用的（`a + b`、`x?.y()`、`i++`、长度/大小取值、多级 `.xxx()` 串联）与嵌套三元、多分支一律改 if-else 或工具方法；判「简单」按三条逐位置核（运算符 / 调用括号 / 索引或属性串联），任一命中即不是简单三元。要治的失效是**例外面被读成万能口子**——原来那句「仅限简单判断」没钉住"简单"指什么，带运算、带调用的三段式照样被当成"简单"留下来。
|===

== 落到哪

* 判据本体：`specs/general/coding-shape.adoc`「表达式与调用写法」的「三元表达式为最低优先级」条（通用层、跨语言）。
* 机械抓手：`script/specs-rules/coding/guards/check_refactor_style_guard.toml`（规则数据）+ `script/check_specs.py` 的 `check_refactor_style_guard`（接线在 `CHECKS` 序列）+ 反例用例 `TestCheckRefactorStyleGuard`。
* 「只允许简单三元」与「重构也照此办」在**同一道**防线里：两轮治的是同一处失效面（三段式的最低优先级档），拆成两道会让"简单"的判据与"重构也不豁免"的适用面各自漂移。
