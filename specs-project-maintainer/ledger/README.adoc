= 逐轮记账（一轮一个文件）

**为什么按轮次分文件、不挤在同一张表里**：每一轮都要记"这轮新增/删除了哪些防线、两个基线
落到多少"。写进同一张表的同一个位置时，**两个并行改动必然撞在同一行上**——与本仓库把
`GUARD_TEST_BASELINE` 改成按防线分片（`script/specs-rules/_guard_test_floor.toml`）同一个成因。
按轮次分文件后，各人各加自己的文件，谁都不碰谁。

* **文件名**：`<轮次主题>.adoc`，小写连字符，与提交主题同源（例：`compact-form-sizing.adoc`）。
* **内容**：一个二级标题 + 一张表（轮次 / 新增防线 / 接线数 / 承接了什么）。轮次里若有
"删了哪道防线"，一并写在这里。
* **不记"用例总数"**：反例用例按防线分片记在 `script/specs-rules/_guard_test_floor.toml`
（一道防线一行）。这里若再写一列全局总数，等于把那个必然冲突的单值挪个地方——
"总数"这个数本身不要了，需要时由脚本现算。
* **接线数从本目录读**：`check_guard_manifest` 核的就是这里各轮记的 `a → **b**` 与
`GUARD_WIRING_BASELINE` 是否对得上（取最大值），故这一列是**真被核的**，不是自说自话。
* **不回溯改旧文件**：旧轮次记的是**当时**的基线，按定义不得改写（同 `specs/general/changelog.adoc`）。
* **接线数仍只有一个数**（`GUARD_WIRING_BASELINE`）：它只在增删防线时变动，而增删防线是
**独占动作**（同时要动 `CHECKS`、清单表、台账三处），本就不是能并行的活；反例用例的记账
则已按防线分片，不在这里。
