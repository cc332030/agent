= 验证的维护方落点（维护方自查）

本文件只写**维护方**在维护这套规范集合时的验证义务：**把公共验证口径落到本仓库自己的动作上**，以及**把哪些验证要求转成机械防线**（否则会「只在文本上成立、执行时不会发生」）。

**验证的规则正文不在这里**：编译/运行验证、判准维度、验证的适用边界、验证的效力等级、验证总纲、规范验证（三视角复核）与运行契约已随公共内容写在 link:../specs/general/testing.adoc[]「验证与运行契约」里——本文件不重复表述（重复会各自漂移），只写"维护方自己要做什么"。

* 验证**按改动性质分层取值、不搞一锅端**（**维护方落点**）：通用口径见 link:../specs/general/testing.adoc[]「验证与运行契约」之「验证的适用边界」——**代码类改动**（改本仓库校验脚本等维护工具的实现细节）按机械判据判过不过（`check_specs.py` + 单测通过即可），**不做**三视角、**不做**全局核对；**规范类改动**（改 `AGENTS_COMMON.adoc`、`specs/`、`prompts/`、`PROMPTS.adoc`、随规范分发的工具行为）才触发「完整性校验」的三视角深度验证。**判据只有一个问句**："这次改动会不会被未知项目加载、会不会改变别人的行为？"——会（或不确定）按规范类走，明确不会按代码类走，**不得因改动小就降级**。**不得互串**：代码类改动不做概念性验证（把可控的事做成不可控的多步流程），规范类改动不得只跑机械校验（机械校验覆盖不到判据是否被压成口号）。
* 验证**不单独抽出一个"验证规范"**（**维护方落点**）：验证口径落在 link:../specs/general/testing.adoc[]「验证与运行契约」（公共内容，涉及验证时加载），**不再新增验证类规范文件**——验证本身也是规范，再抽一层只会多一个没人维护、判据空转的东西；是否该抽的判据见 link:spec-lifecycle.adoc[]「一条规范何时该拆分」（三条硬条件须同时成立，且"不拆就真的坏"须能指出实害）。
* 子 agent 复核**必须自带硬超时**（**维护方落点**）：通用口径见 link:../specs/general/collab.adoc[]「资源限制与感知」——每次派发设可判定的时限，到点即"放弃 + 如实标悬置"，**不得无限等待**（维护方实证：把语义复核派给外部评审 NPC，多轮停在同一步 1 小时以上未回传）。**子 Agent 强制与执行者同 Agent（维护方落点）**：本仓库需要子 Agent（子任务/复核）时，**一律用与执行者相同的 Agent（同入口、同调度器）、且可用的一次性调用承担**；**不得点名外部 Agent / 外部 NPC**、也不得把外部复核者当备选（本项目实证：外部评审 NPC 镜像不存在、派发即失败；另一次派出去卡 1 h+ 未回传，结论无从采信）。
* **复核职责不绑定特定执行者**（**维护方落点**）：规范要求的是"有独立、干净上下文的复核发生"，**执行者一律同 Agent、不得点名外部 NPC**；同 Agent 的子执行者不可用时，由维护方按同一判据组织等价复核（**由主 Agent 在同一会话内串行承担**，见公共 link:../specs/general/collab.adoc[]「协作方式」），并如实标注独立性边界（与改动方同一上下文/同一模型的复核，独立性弱于第三方）。
* 语义复核的**留证是三态台账**（**维护方落点**）：结论须逐项落成 **通过**（附判据与取值）／**未发现问题**（附已复核角度与样本）／**悬置**（附原因与剩余风险）三态，不得写成散文结论、不得合并三态；**"查不出"与"没做"须能分辨**。台账随复核结论一并发布（PR 评论或提交说明），维护方**不做**对评论正文的机械解析（解析他人可编辑的正文属脆弱抓手），故**台账的"实际填写"由发布前的完成前自检 + 人 review 承担**；**维护方侧的具名抓手**是 `check_checklist_guard`——它钉的是**该条要求的多处要素是否齐全**（"三态台账"+"未发现问题"+"不得合并"、"悬置"附原因等），**不是**"关键词出现过一次"，故**要求被抽掉而只留字样会被拦下**；它管不到的是"某次台账实际填没填"（那属产物内容，见上）。
* 子 agent 复核的**时限取在维护方可判定的量级**（**维护方落点**）：维护规范集合的项目的语义复核派发按"**分钟级**"设限（实证：把三视角复核做成一次性、无工具的模型调用，两次分别 28 s 与 57 s 返回；反之把复核交给会自行探查仓库的 NPC，多轮停在同一步 1 h+ 未回传）——故派发时优先选**一次性、边界明确、可超时**的形式，超时即放弃并如实标悬置。 **不得为了"形式上的独立性"把复核派给外部来源**——既违反"子任务一律同 Agent、不得点名外部 NPC"，其可用性、判据一致性与耗时也一律不可核对，本项目已有"派出去卡住 1 h+ 未回传"与"镜像不存在"两次实证（见公共 link:../specs/general/collab.adoc[]「资源限制与感知」「agent 协作规范」）。
* 任务节点的自查**必须指向当前有效的落点**（**维护方落点**）：通用节点的自查清单在 link:../specs/core/execution.adoc[]「任务生命周期与节点自查」；维护规范集合的项目对应的是「完整性校验」「定义未执行核验」两条（见下「规范调整」），以及"改完规范后的复盘"落在 link:spec-lifecycle.adoc[]「级别变更与复盘」。**索引指向的落点失效即等于没有这条要求**，故由 `check_lifecycle_guard` 机械核对各节点仍在、且其引用的落点仍存在。
* 改完规范的**完整性校验**（**维护方落点**，每次改完必做）：①运行本仓库的机械校验与单测（全量扫描，不得只查变更文件）；②对内容实质性调整，在**隔离上下文**开启**干净子 agent** 按三视角一并语义复核（一次读取、结论分栏），**三视角都过才可交付**；概念项查不出的部分标**悬置**、写明已复核角度，**不得当作阻断交付的条件**。动作与判据见 link:../specs/general/testing.adoc[]「验证与运行契约」之「验证总纲」「规范验证」。
* 验证口径的**自检**：验证**不依赖用户提示**，不得以"用户未要求/改动很小/项目简单"为由跳过（仅用户明确豁免时除外）。
