= 验证的维护方落点（维护方自查）

本文件只写**维护方**在维护这套规范集合时的验证义务：**把公共验证口径落到本仓库自己的动作上**，以及**把哪些验证要求转成机械防线**（否则会「只在文本上成立、执行时不会发生」）。

**验证的规则正文不在这里**：编译/运行验证、判准维度、验证的适用边界、验证的效力等级、验证总纲、规范验证（三视角复核）与运行契约已随公共内容写在 `specs/general/verify.adoc` 里——本文件不重复表述，只写"维护方自己要做什么"。

* **验证按改动性质分层取值、不搞一锅端（维护方落点）**：通用口径见 `specs/general/verify.adoc`「验证的适用边界」——**代码类改动**按机械判据判过不过，**不做**三视角、**不做**全局核对；**规范类改动**才触发三视角深度验证；**不改内容的操作**（只改提交/历史或文件路径、内容逐字节不变）**不重跑全量校验**，按该操作自身的确定性判据核对。**判据只有一个问句**："这次改动会不会被未知项目加载、会不会改变别人的行为？"——**不得因改动小就降级**。**不得互串**：代码类改动不做概念性验证，规范类改动不得只跑机械校验。
* **验证不单独抽出一个"验证规范"（维护方落点）**：验证口径落在 `specs/general/verify.adoc`，**不再新增验证类规范文件**——验证本身也是规范，再抽一层只会多一个没人维护、判据空转的东西；是否该抽的判据见 `spec-lifecycle.adoc`「一条规范何时该拆分」。
* **同 Agent 复核的适用面（维护方落点）**："子任务须由与执行者相同的 Agent 承担"**不是无条件前提**——它**只在承载该任务的平台层写明该前提成立时才按强制判**（本仓库的平台落点：`specs/platform/cnb.adoc`「评论唤起新实例」；CNB 上被唤起的 NPC 与执行者本就是同一个产品）。**环境不提供同 Agent 的子执行者时不得据此拒做或停任务**——按 `specs/general/collab.adoc`「协作方式」的降级路径由主 agent 串行承担并标注独立性边界、或如实标悬置，**复核与交付不因此缺失**；"非 CNB"本身不构成降级、跳过或中断交付的理由。
* **子 agent 复核必须自带硬超时（维护方落点）**：通用口径见 `specs/general/collab.adoc`「资源限制与感知」——每次派发设可判定的时限，到点即"放弃 + 如实标悬置"，**不得无限等待**。**子 Agent 强制与执行者同 Agent（维护方落点）**：本仓库需要子 Agent（子任务/复核）时，**一律用与执行者相同的 Agent（同入口、同调度器）、且可用的一次性调用承担**；**不得点名外部 Agent / 外部 NPC**、也不得把外部复核者当备选。
* **复核职责不绑定特定执行者（维护方落点）**：规范要求的是"有独立、干净上下文的复核发生"；同 Agent 的子执行者不可用时，由维护方按同一判据组织等价复核（由主 Agent 在同一会话内串行承担），并如实标注独立性边界（与改动方同一上下文/同一模型的复核，独立性弱于第三方）。
* **语义复核的留证是三态台账（维护方落点）**：结论须逐项落成 **通过**（附判据与取值）／**未发现问题**（附已复核角度与样本）／**悬置**（附原因与剩余风险）三态，不得写成散文结论、不得合并三态；**"查不出"与"没做"须能分辨**。台账随复核结论一并发布，维护方**不做**对评论正文的机械解析（解析他人可编辑的正文属脆弱抓手），故台账的"实际填写"由发布前的完成前自检 + 人 review 承担；**维护方侧的具名抓手**（如 `check_checklist_guard`）钉的是**该条要求的多处要素是否齐全**——它管不到的是"某次台账实际填没填"。
* **子 agent 复核的时限取在维护方可判定的量级（维护方落点）**：语义复核派发按"**分钟级**"设限（实证：把三视角复核做成一次性、无工具的模型调用，两次分别 28 s 与 57 s 返回；反之把复核交给会自行探查仓库的 NPC，多轮停在同一步 1 h+ 未回传）——故派发时优先选**一次性、边界明确、可超时**的形式，超时即放弃并如实标悬置。**不得为了"形式上的独立性"把复核派给外部来源**。
* **任务节点的自查必须指向当前有效的落点（维护方落点）**：通用节点的自查清单在 `specs/core/execution.adoc`「任务生命周期与节点自查」；维护规范集合的项目对应的是「完整性校验」「定义未执行核验」两条，以及"改完规范后的复盘"落在 `spec-lifecycle.adoc`「级别变更与复盘」。**索引指向的落点失效即等于没有这条要求**，故须机械核对各节点仍在、且其引用的落点仍存在。
* **改完规范的机械手段（维护方落点，每次改完必做）**：本仓库的「全部既定校验手段」＝`check_specs.py` + `check_specs_test.py` + `check_effective.py` + `check_effective_test.py`，**全量扫描**、不得只查变更文件（通用判据见 `specs/general/verify.adoc`「改完规范必做的五件事」①，本文件不复述）。
* **改完规范必做的五件事（维护方落点）**：公共判据见 `specs/general/verify.adoc`「改完规范必做的五件事（机械手段必跑，干净子 agent 复核不可漏）」，本文件只写**本仓库的落点**：① 机械手段＝上一条那四套脚本（全量扫描）；② 干净子 agent 复核＝本仓库已有该要求（见上两条「同 Agent 复核的适用面」「子 agent 复核必须自带硬超时」），按已有那份执行、不重复写第二份；③④⑤ 无本仓库专属取值，按公共判据执行；**三态台账的"实际填没填"**由发布前的完成前自检承担（本仓库不做对评论正文的机械解析）。**"有了就忽略、没有就加"**：项目规范里已有对应要求时按已有那份执行；**没有时须补在项目自身规范里**，**不得**补进公共内容。
* **验证口径的自检**：验证**不依赖用户提示**，不得以"用户未要求/改动很小/项目简单"为由跳过（仅用户明确豁免时除外）。
