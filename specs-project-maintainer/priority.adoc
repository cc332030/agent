= 最高关注项与不可降级清单（维护方自查）

本文件只写**维护方**在维护这套规范集合时的两件事：①**最高关注项清单**（重构/去重/精简/迁移时绝对不能动什么）；②**维护方必须为哪些东西设机械防线**（否则会「只在文本上成立、执行时不会发生」）。

**规则的正文不在这里**：分级定义（L1/L2/L3）、最高关注项的完整判据与「强调的正确做法」已随公共内容写在 link:../specs/core/execution.adoc[]「分级与最高关注项」与 link:../specs/general/testing.adoc[]「验证与运行契约」里——本文件不重复表述（重复会各自漂移），只做维护方侧的自查清单。

== 最高关注项（不可降级，重构/精简时首保）

以下是**最高关注项**：跨重构、去重、精简、迁移**必须保持，只能加强不得削弱**。每项给出**判定标准**（可执行）、**依据**（业界标准名/编号，只留一行）与"重构时如何判断它没被误改"；**失效原理与取舍论证归思考/决策侧**（见 link:spec-lifecycle.adoc[]「同一条规则有两种读法」），常驻层不铺开——但**不得省掉依据**（只压缩为名称/编号）。

最高关注项**级别不是同一档**，"最高关注项"与"条款本身是 L1"是两件事——这正是"优先级混用"的典型来源，须分清（两者按 link:spec-lifecycle.adoc[]「如何给一条规范定级」分别判定；依据：ISO/IEC Directives Part 2 要求与建议不得混用；RFC 2119 的 `MUST` 不因"描述的是常见失效"而变强）：

* **规范性铁律（P1/P2/P3/P5，条款本身 L1）**："该怎么做"没有裁量空间——`git mv`、校验必须真执行、内容不得减少、不可逆操作先确认且不得编造，任何理由都不得偏离；机械防线钉的是铁律本体。
* **纪律性铁律（P4，条款本身 L2）**：约束的是"读多少、在什么上下文里做"这类**行程安排**，存在正当豁免（读取范围按任务定、成本与收益可权衡），按定级四问只能到 L2；但它**极易被无声违反、违反后整条任务链的方向与准确率一起偏**，故与规范性铁律**同列最高关注项**。**列为最高关注项 ≠ 条款本身是 L1**：不可降级保护的是"不得从清单删除、不得改为'非最高关注项'、不得削弱其必加载层引用与机械防线"，而非把它的条款强度拔高。

=== P1. 文件移动/重命名必须用 `git mv`，禁止 delete+create

* **要求（L1，最高）**：不得用「新增新文件 + 删除旧文件」代替移动/重命名，否则 git 历史断裂。
* **依据**：rename 跟踪的可追溯性靠版本控制机制原语（`git mv` = 移动 + 记录重命名），delete+create 会永久断链且**事后无法恢复**——不可逆损伤（依据：配置管理对变更可追溯的要求，ISO 10007；变更须保持既有信息不丢，见 link:../specs/general/git.adoc[]）。
* **判定标准**：`git diff --cached -M --summary` 对移动显示 `rename`；`git status`/`git diff --name-status` 不应出现"同一批改动里 `D`（删除）+ `A`（新增）且内容高度相似"（**只读状态行**，不需工作区文件内容）。完整规则与自检命令见 link:../specs/general/git.adoc[]「文件移动与重命名」，必加载层重申见 link:../specs/core/execution.adoc[]「文件操作强制检查」。
* **重构防误改**：本条**不因去重而删除**。多文件/多层重复出现时，**保留一处完整定义（link:../specs/general/git.adoc[]）**，其余位置用**一行引用**指向它（见「强调的正确做法」）；**禁止以"内容重复"为由删除任何一处对最高关注项的引用**。

=== P2. 调整规范必须保证完整性，且校验要真正执行

* **要求（L1，最高）**：调整规范不得丢失规则；**规范类改动**改完必须跑机械校验 + 干净子 agent 语义复核，不得"定义了校验却不执行"（本条是最高关注项——**其存在与不可降级对任何改动生效**；其规定的三视角动作按改动性质取值，见下「判定标准」）。**复核须一并回答三视角、都过才算完成，且由同一个干净子 agent 一次读取、结论分栏**（判据见 link:../specs/general/testing.adoc[]「验证与运行契约」之「规范验证」）。
* **依据**：规范集合属受配置管理约束的资产，变更须可追溯、防止误删（ISO 10007、ISO 9001 文件信息控制）；需求变更须保持完整性并可追溯（ISO/IEC/IEEE 29148）；评审也可作为核验手段（IEEE 1028）。判定标准引用的「验证与运行契约」各节见 link:../specs/general/testing.adoc[]。
* **判定标准**（**两件事分开读**）：①**本条的存在与不可降级对任何改动生效**（任何提交都不得删改本条，见下「重构防误改」）；②**本条规定的三视角动作只适用于规范类改动**——规范类改动须通过机械校验（引用/链接/节名/登记等确定性项）**加**一次隔离上下文的语义复核（**①完整性 + ②有效性与认知质量 + ③接纳面**三视角都过、各有留证），只跑机械校验不算完成；**代码类改动不走三视角**，按同节「验证的适用边界」的机械判据判过不过（**能过即过**）；**同一提交含两类改动时按更严一侧取验证范围**，但**三视角只覆盖其中的公共内容部分**、代码部分仍按机械判据判过不过。**"验证了什么、怎么算过、依据哪个标准"须能逐项枚举**（口径、标准出处、留证三态、三视角判别式、②四维与③逐维判据见同节「验证总纲」「验证的效力等级」「规范验证」），**被未知项目加载后的影响面/成本/可控性**（同节「运行契约」）也在核对范围内——防"跑绿脚本就算验证过"与"加得越多次越脱离初衷"。**结论强度按对象分档（L1，仅适用于按上款走规范类验证的改动）**：复核**只到"未发现问题"，不得写成"通过"**——有确定性判据的对象才谈"通过/不通过"；概念性对象**查不出不等于没有**，须标**悬置**并写明已复核角度，**且不得当作阻断交付的条件**（口径见同节「验证的效力等级」）。**维护规范集合的项目**须把本文件最高关注项的存在性（与定级口径的存在性）**转为机械防线**；写入与登记的完整动作见 link:spec-lifecycle.adoc[]「写入与登记」。
* **重构防误改**：本条与最高关注项的存在性**必须由机械防线钉住**（存在性可确定性核对，故属该设抓手的一类；只在文档里写"不得删除"而不设检查，属 link:../specs/general/self-check.adoc[] 意义上的"定义了却不执行"）。**抓点具名与泛化的边界（L1）**：公共内容里**不得**写某项目私有的抓手名、脚本名与仓库结构（引用方看不到），也**不得声明"已由机械防线钉住"或"存在某道防线"**——那属维护规范集合的那一方自己的事，引用方既拿不到、也无从执行；公共内容只保留"须由机械防线钉住"这类**要求**。**把具名抓手改成泛化要求而项目侧没有对应具名检查，属把"必须 + 判据"压成"原则 + 方向"的可执行性降级**

=== P3. 文档/注释内容不得减少（迁移只换承载位置）

* **要求（L1，最高）**：文档内容可写在代码文档注释或独立文档，但**要求记录的内容一项不能少**；不得以"精简""去重"为名删简真实内容。
* **依据**：记录内容是事实与决策的载体，删除即失去可追溯性（ISO/IEC/IEEE 29148 的可追溯要求、ISO 9001 的文件化信息控制）。**去重针对"重复表述"，不针对"必要内容"**——这是本条与「规范组织/去重」最容易混淆的边界。
* **判定标准**：按 link:../specs/general/doc.adoc[]「注释与文档」的「必记录项」①-⑩ 逐项核对，缺一即未完成；迁移后仍须逐项齐全。
* **重构防误改**：去重前必须先确认"删的是重复表述、不是必要内容"；对无法确定的内容**保留**（宁可冗余不可缺失）。

=== P4. 读取按最小必要，长会话简单任务须在干净上下文执行

* **要求（L2 建议，最高关注项）**：任务开始前先定出**最小必要信息集**并只读该集合内的内容；会话执行过多个任务后，切换任务时**应当**把历史上下文与新任务隔离，简单任务优先在**干净上下文**中执行。**定级理由**：本条约束"读多少、在什么上下文里做"这类行程安排，存在正当豁免（读取范围取决于任务且可权衡成本收益），且该节内的逐条规则本身即按 L1/L2 分级（读取范围边界为 L1、委派与落盘等安排为 L2）；但**存在破坏面大的典型失效**（简单任务在长会话里读一大堆无关内容、准确率与成本一起恶化），故列为最高关注项。**完整规则见 link:../specs/core/execution.adoc[]「范围控制」**（本条为重申，不重复其正文）。
* **依据**：上下文越长，信息召回与长程推理越差、token 成本与时延越高（注意力预算与 `context rot`；Anthropic 工程博客《Effective context engineering for AI agents》）；只加载必要的高信号内容（Agent Skills 开放规范的 progressive disclosure）。**完整论证与量化抓手**见 link:../specs/core/execution.adoc[]「范围控制」的业界依据。
* **判定标准**：①读前能说出"本次任务的最小必要信息集"，且实际读取未超出（超出须有可说明的理由）；②已定位文件的任务使用了精确定位读取、未启动全库扫描；③任务切换时不沿用旧任务的探索路径，简单任务不在长会话中"沿用旧路径再读一遍"；④读完后读到的内容全部与任务相关。
* **重构防误改**：受不可降级保护，护法与 P1-P3 一致——维护规范集合的项目须机械钉住其存在性、必加载层引用落点与『不可降级』声明；本条**不因去重而删除**，多处出现时保留一处完整定义（link:../specs/core/execution.adoc[]「范围控制」）、其余用一行引用。

=== P5. 不可逆操作先确认，不得编造事实与来源

* **要求（L1，最高）**：①**删除/清空/覆盖等不可逆操作**执行前须确认目标、可回滚、范围可界定，三项任一不确定即停下提问；②**不得编造事实与来源**——命令/API、依赖坐标、标准编号与名称、链接与路径、数据与结论，不知道就明说并去查证。完整规则见 link:../specs/core/execution.adoc[]「破坏性操作」与 link:../specs/general/source.adoc[]。
* **依据**：两类失效**危害不可逆或会扩散**——误删/强推覆盖的数据与历史无法恢复（配置管理与变更控制：ISO 10007）；虚构来源会污染整条下游引用链且事后极难发现，故来源必须真实可溯源（link:../specs/general/source.adoc[]；ISO/IEC IEEE 标准引用现行有效文件的要求）。**犯错成本不对称**：做对比做快重要得多，"不确定"时默认停下而非输出。
* **判定标准**：①不可逆操作前能说出"删的是什么、能否恢复、范围边界"，且实际按此执行；②本次给出的命令/路径/编号/数据，都能指出**来源或实测依据**（凭空无法指认即违规）；③无把握时输出的是"未确证"而非貌似合理的编造内容。
* **重构防误改**：本条**不因去重而删除**；完整定义分别落在 link:../specs/core/execution.adoc[]「破坏性操作」与 link:../specs/general/source.adoc[]，其余位置用一行引用；存在性与关键要点**须由机械防线钉住**。

=== 最高关注项与去重的冲突处理（重点）

最高关注项与其引用**允许、且应当**在多处出现，但**一处是完整定义、其余是引用**：这样既保证"强调"（多处都指向它、不可能读不到），又不产生多份漂移（内容只有一份）。**判重时必须先判定"是不是最高关注项的引用"**：是引用 → 不判为注水、不合并；是**逐字复制的完整定义** → 收敛为一处定义 + 引用。

== 强调的正确做法（避免"写两次"的误解）

**"写两遍同样的完整内容"不等于强调**，反而是反模式：它会让 AI 把它判成"重复内容"而合并/删除（维护规范集合时已多次遇到），且两份会各自漂移。业界标准做法是**分级 + 单一定义 + 显式引用**：

* **分级**：把条目**升到 L1 / 列为最高关注项**（本文件），优先级由分级表达，不靠重复次数表达。
* **单一定义**：完整定义只写在一个**权威位置**（如在 link:../specs/general/git.adoc[]，或在 link:../specs/core/execution.adoc[] 的重申），其余位置**只写一行引用**（如"见 git 规范「文件移动与重命名」"）。
* **显式标题**：权威定义所在小节用**显著标题**（如 git 规范的「文件移动与重命名」）承载强调；重要条目在 `AGENTS_COMMON.adoc`「最高优先级铁律」**登记一次**，作为"进门必读"。
* **机械钉住**：对"任何时候都不得消失"的条目，用校验脚本钉住其**存在性**（维护规范集合的项目须落到具名检查），这比人工重复书写更可靠。

结论：**同一约束只写一次完整定义、其余用引用**；需要更强强调时，用"升级别 + 加显著标题 + 机械钉住"，而不是复制正文。

== 本文件的适用范围（维护方自查）

本文件属**维护方自查**，登记在上层目录的 `AGENTS.adoc`（维护方的项目规范入口），**只在维护这套规范集合（或同类共享资产）的项目中加载**，不随公共内容分发给普通引用方（引用方看不到、也无义务）。它给维护方两样东西：①最高关注项的**不可降级清单**（重构/去重时首保什么）；②维护方**必须把哪些东西转成机械防线**（否则会"只在文本上成立、执行时不会发生"）。
