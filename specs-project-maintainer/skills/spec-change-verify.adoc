= 技能：改完规范后的收尾复核

**技能文档**（定义与取值见 `specs/general/collab.adoc`「专家与技能」）：本文件把收尾这一步连成可整份照做的清单。**判据本体不在这里**——各步的"必须/不得"、判定标准与依据在 `specs/general/verify.adoc`「改完规范必做的五件事（机械手段必跑，干净子 agent 复核不可漏）」与其同文件的上文各节；本文件**只给次序与不可省略项**。

**加载触发特征**：改完公共内容（规范条目、任务提示词、随规范分发的工具）之后**要收尾**时加载；没有这个目的时不加载——它是技能，**要么不读、要么整份读完**（只读半份等于只拿到半套次序）。

== 步骤（按序做、一件都不能省）

. **跑机械手段**（判据见 `specs/general/verify.adoc`「改完规范必做的五件事」①）：先跑项目声明的**全部**既定校验脚本与其配套测试，**全量扫描**；报红**就地修复**、不留红。
. **起干净子 agent 做语义复核**（同上②）：换一次**干净上下文**，只带本次钉定的对象与其判据；通道**先实测、后派发**，取不到即按不成立处理（通道判据见 `specs/general/review.adoc`「review 时的干净子 agent 复核（强制）」）。
. **三视角一并回答、一次读取分栏列**（同上③，判据见 `specs/general/verify.adoc`「验证总纲」「规范验证」）：①完整性 + ②有效性与认知质量 + ③接纳面，**不拆成三次读**。
. **结论落成三态台账**（同上④，判据见 `specs/general/verify.adoc`「验证的效力等级」）：逐项成行、每条带**通过／未发现问题／悬置**之一，**三态各占一栏、不得合并**；台账随交付一并发布。
. **子 agent 不可用时走降级路径**（同上⑤）：由执行者在本次执行内按同一判据串行核对，**如实标注独立性边界**；仍不可行时标悬置 + 写明剩余风险。**降级后交付照常**。

== 本项目的取值与适用范围

* **"全部既定校验手段"具体是哪几套**、**干净子 agent 的通道是什么、怎么实测**、**哪一步由发布前的完成前自检承担**——本仓库落点在 `specs-project-maintainer/verify.adoc`「改完规范必做的五件事（维护方落点）」及其相邻两条，本文件不复述。
* **只对规范类改动（公共内容）成立**：代码类改动不做三视角、不设复盘节点（判据见 `specs/general/verify.adoc`「验证的适用边界」）。
