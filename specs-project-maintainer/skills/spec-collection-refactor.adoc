= 技能：规范集合的自身重构

**技能文档**（定义与取值见 `specs/general/collab.adoc`「专家与技能」）：本文件把瘦身与归位这一步连成可整份照做的清单。**判据本体不在这里**——各步的判据（归属判据、层级判据、三条拆分硬条件、"同一事项只有一个真源"、删/移/留的速查）在 `specs-project-maintainer/spec-lifecycle.adoc`「规范集合的自身重构（瘦身与归位）」及其同文件各节；本文件**只给固定次序与核对面**。

**加载触发特征**：要把规范集合整体优化一遍（用户显式声明的一次全库收敛），或做**发现即改的随动迁移**时加载；没有这个目的时不加载——它是技能，**要么不读、要么整份读完**（次序读一半即会颠倒、把"放错位置的内容"直接删掉）。

== 步骤（顺序不可颠倒）

. **先判归属**（公共 / 项目自身）：按**替换主语测试**逐条过；公共内容里出现的项目私有动作、脚本名、仓库结构即属放错位置（判据见 link:../spec-lifecycle.adoc[]「归属判定：公共规范还是项目规范（先判定再动手）」）。
. **再判层级**（放对层）：把只对特定场景/特定维护动作成立的内容从常驻层移出；**放不进去的不是删，而是移动**（判据见 link:../spec-lifecycle.adoc[]「常驻层只放底线（常驻层的准入判据）」）。
. **再判重复**（去重）：同一约束只保留**一处完整定义**、其余改为一行引用（判据见 link:../spec-lifecycle.adoc[]「规范集合的自身重构（瘦身与归位）」）。
. **最后压缩表述**（不得削弱有效性）：只留"规则 + 判定标准 + 依据（标准名/编号）"，删论证过程与长篇铺陈——**不删规则本身**。

== 收尾核对（缺一即重构不合格）

* **逐项核有效性**（判据见 link:../spec-lifecycle.adoc[] 该节的「重构后须核对规范有效性」条）：**"必须/不得"仍在、判据仍在、依据仍在、级别未降**——"判据仍在"**须按条正文里的判据句核对**，不得只看轴名齐全。
* **逐项核完整性**（同节「判定速查」条）：删的只是重复表述本身、被删处**留下可达引用**；对无法确定是否重复的一律**保留**。
* **核验五项**（同节「重构后必须核验」句）：体量、层级、级别、有效性、引用（是否留下悬空引用）——前两项靠人/子 agent 复核，后三项由本仓库的机械校验兜底。
* **收尾**：本技能只到"重构与核对"为止；改完公共内容后的收尾复核**另按** `specs-project-maintainer/skills/spec-change-verify.adoc` 走（那是另一件事）。
