= 用户错别字的纠正依据

本文件是依据图书馆的主题之一：**"用户的打错字不得当真值、先纠正再执行"这条规则的依据**——**外部材料只给方向与下限**，本集合在此之上加了什么（更严的 L1 约定与自己的裁量面）。

== 本主题为何独立于外部标准主题

`library/sources.adoc` 的口径是：**外部标准的逐字原文**，每条回答"这条标准确实支持这条规则"。而本条里存在一条**不可合并的差异**：标准只给**方向与下限**（交互须符合预期、需求须单一可追溯、成文信息须可核验），**本集合自己**在此之上有更严的硬性约定（"错别字不得当真值"是 L1）与自己的裁量面（"怎么纠正"不设统一动作）。按**"依据对谁成立"**分篇（判据见 `library/README.adoc`「何时该给一类依据独立成篇」）：只对本站成立的部分落在本文件。

== 外部材料说了什么（只给方向与下限）

* **ISO 9241-110（人机交互的交互原则）**：规范里列有**符合预期**与**可控性**一类交互原则——系统对用户输入的回应应与用户的意图与预期一致，且用户对过程保持可控。本集合**借用其原则**类推到"人与规则/agent 的交互"，**未**声称该标准直接规定 agent 该怎么处理用户的错别字（同 `library/adoption.adoc`「被未知项目加载时的可控性依据」的同义性写法）。标准原文的取样状态见 `library/sources.adoc`「ISO 9241-110」。
* **ISO/IEC/IEEE 29148（需求工程）**：需求须**单一、无歧义、可追溯、可验证**。按打错的词落地，等于**把一句用户没说过的话当成需求**——追溯链从源头就指错了；据此推出的"不得当真值"与"纠正须可核对"属本集合的判据化动作。取样状态见 `library/sources.adoc`「ISO/IEC/IEEE 29148」。
* **ISO 9001（成文信息控制）**：成文信息须**可核验**——"改了哪一处"须落成可对照的事实，否则"纠正过了"与"没纠正"在产物里分辨不出来。

== 同义性差异与覆盖点（本集合自己承认的）

以下**不是**外部材料的要求，而是**本集合自己的取舍**。每条分列**标准侧**与**本站侧**两半，以免读者把本站口径当成标准原文。

* **"用户的打错字不得当真值"（L1）是本集合更严的硬性约定**：**外部材料只给方向与下限**（符合预期、需求单一可追溯、成文信息可核验），**未规定「执行者必须纠正用户的错别字」这一动作**，**也未**规定"照着打错的词做算违规"。本集合把它收紧成一条**可核对**的动作：**按能读出的正确词执行 + 把纠正落到输出里**，判定标准只有一条——"照错写的那一处"是否存在（用户原文与交付物一对照即可判）。
* **"怎么纠正"由执行者定（L3）是本集合的裁量面**：本集合**不要求**为每一次纠错发起确认（那会把一次任务拆成多轮往返，与执行吞吐取向相抵），也不规定用哪种形态纠正（就地改判 / 输出里告知 / 先问再改都允许）。**本集合据此划的界**：**用户显式声明过的词以声明为准**（自定义命名、内部代号、产品专名，不得替用户改名），且**工作区里已有的词不是错别字**（已经存在的标识符/路径/字典值就是"这个项目的用词"，不得按"看着像打错"去改），**边界只在"读不出要哪个词"时**——那时属需求歧义，按 `specs/core/execution.adoc`「指令执行」的「歧义先问、不自行假设」停下问，不得猜一个改掉。
* **"显式声明过的词以其声明为准"是本集合自己划的界**：自定义命名、内部代号、产品专名在"外人看像错字"与"作者就是要在那个词"之间，**没有外部材料替我们判**；本集合按"作者声明优先"划界（与 `specs/general/source.adoc`「不得编造」同向：宁可不动，也不替用户改名）。
* **规则本体落点**：`specs/core/execution.adoc`「指令执行」的「用户打错字不是他的真值：先纠正、按纠正后的意思做（L1）」；它与同节「逐字执行用户指令（L1）」的"明显打错字除外"是**同一件事的两半**——那一处只解掉"必须照做"，**不构成"看出来了也不用管"**，两处须并读（不复制对方正文）。

== 本项目实证（本项目发生的事，不冒充标准原文）

* **用户原文口径（口径来源）**：「调整规范：用户可能会打错单词，如果是定义的变量的单词打过来，AI可能不会去纠正，以为是用户故意输的，需要帮用户纠正单词错误」。
* **要治的失效形态**：用户把**标识符/路径/字典值**里的某个词打错（少一个字母、多一个字母、形近字），执行者**识别出了"这是个打错的词"却不纠正**——照错值写进代码（生成名字打错的标识符）、写进文档（把错字当成既有名称）、或抄进路径与配置值；**过程中既没有纠正、也没有告知**，直到后来按正确名字检索不到才发现。该形态的特别之处是：**"用户故意输的"与"用户打错了"在文本上分辨不出来**（见下"可用的机制边界"），故执行者默认按前者处理、静默照做。
* **本集合的处理取向**：把**判断权交回用户**——执行者按"最可能的正确词"返回，并在输出里指明"这里纠正过"；**用户能否认**（他显式声明过的词以他为准）。这比"每个疑似错字都停下来问"便宜，也比"静默照做"可控。

== 可用的机制边界（如实标注，不夸大）

* **"用户打错"与"用户故意这么输"在文本上不可判**：两者都表现为"这个词在项目既有名称里检索不到"——本集合**不声称**能靠机械手段判出一条错别字，故本条的抓手只到**文本要点是否仍在**（见 `script/specs-rules/corrections.toml` 与 `specs-project-maintainer/guards.adoc` 的对应防线）；"这次到底纠正了没有"属**运行时事实与语义判断**，交人 / 子 agent 复核。
* **未逐字取回**：本条所引三项标准，本项目**未逐字取回**其条文（ISO 9241-110 按"借用其原则"引用，ISO/IEC/IEEE 29148 与 ISO 9001 按标准名/编号引用）；需要逐字核对时按 `library/sources.adoc` 的同名主题段取用其取样状态与取回方式。
