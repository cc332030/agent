= 图书馆（本仓库的依据库）

本目录是本项目的**图书馆**：集中存放本项目里**需要找依据**的东西——规范条目与项目决策背后的**依据**：**为什么这样要求、来源是哪一条、逐字原文是什么、当初要解决的失效长什么样**。

== 为什么要有它

规范正文是"怎么走"的形态（规则 + 判定标准 + 依据名）——这是**刻意**的（见 `specs/core/execution.adoc`「分级与最高关注项」、link:../specs/general/verify.adoc[]「验证总纲」）：执行时多看"为什么"只会占注意力。

但**依据不能只存在名称**：一条规则被执行久了，就会退化成"只记得是这么做的"——提出时的原因不再有人知道（可能原文里写过，也可能只是散在讨论里），于是无法判断它**还成不成立**、无法在争议中据以取舍、无法据以**举一反三**（link:../specs/general/verify.adoc[]「验证总纲」之「防"慢慢脱离初衷"」要求的正是"当初要解决的失效现在还在不在"）。它和 link:../specs/general/source.adoc[] 是同一件事的两端：那份管**引用不许编**，本目录给**依据一个能被检索、被逐字核对的落点**。

== 放什么、不放什么

* **放**：本项目里**任何需要依据的东西**——能**逐字对照**的外部标准原文（引文）、业界权威实践与真实事故的公开陈述、当初的**决策记载**（为什么这样要求、为什么不做别的方案）、**反例**（失效长什么样、实证是什么）、以及技术选型与组织约定的依据。**不限于规范依据**：规范、提示词、脚本、CI 乃至日常决策的依据都可入库。
* **不放**：规则本体（规则在 `specs/` 各文件，图书馆只补依据、不复制规则）、没有出处的观点与推测、**只把讨论过程落盘的会议记录**（link:../specs/general/doc.adoc[]「注释与文档」：空话套话、复述既有结论、为对称凑数者一律不收）。
* **依据找不全时**：按 link:../specs/general/source.adoc[]「无法确证时的正确做法」**如实标"未确证"并写明已查证方式**，不得用虚构内容填补。

== 何时该写、写什么（入口）

本文件只回答**形态**问题（放什么、放哪、是否独立成篇）；**触发**问题——什么时候该把一条依据写进图书馆、入库必写哪几项、什么时候不写——由 link:usage.adoc[]「一、什么时候该把依据写进图书馆（触发特征）」给判据。**依据与规则的互相关联与反查算法**（从规范正文只取一份、不遍历）见 link:usage.adoc[]「二、依据与规则怎么关联（关联协议）」。两者合起来才是完整的写入协议。

== 为什么还要有"定位协议"（馆可以无限大）

上面回答了"依据该不该入馆、放哪、何时加载"，但**没有回答另一个问题**：馆**没有体量与范围的上限**（见「放什么、不放什么」：本项目里任何需要依据的东西都能入馆），将来可能**特别大**。于是引用方要在**不把整馆下载下来**的前提下，**准确找到"这条依据具体在哪个文件"**——这件事需要一条**可机械执行**的路径，不能靠"看着像不像"。

**本站失效（缺协议会长成什么样）**：①**全量下载**——把整馆拉进工作区再 grep，馆一大就是几十上百 MB、每次找一条依据都付这个代价，且下载来的副本会与仓库漂移；②**按主题名猜文件名**——主题文件的命名与位置会随重构变化（本仓库的图书馆就搬过落点，见 link:../CHANGELOG.adoc[]），靠命名约定定位等于把"文件路径"当成主键，改名即断档；③**把图书馆当全文检索引擎**——这正是 link:usage.adoc[]「反查解析算法（只取一份，不遍历）」要拦的形态，因为外部项目根本不该遍历本仓库；④**要求取用者先说出"版本号"**——本仓库**不发布版本号、也不维护"最新 commit 是哪个"的登记文件**，故任何"先拿版本号、再用版本号拼地址"的路径，作者自己能走、**读者走不通**（本协议的前身即栽在这条：先入为主把 commit 写进了取值路径）；⑤**把主张写在文件名上**——指望"看文件名就知道这条依据在讲什么"（名字写成一句话、带上限定语与来源），于是**被机器读到的每一条链接与每一次目录列举都在替文件名付上下文**：文件名越长，取用侧为了解"这份文件是什么"要多读的字越多，而**名字本身并不是可检索键**（检索靠入口登记表，见「主题登记」）——馆一大，没有人会靠文件结构或文件名去找依据，都是**从已有内容反查到馆**（link:usage.adoc[]「一、什么时候该把依据写进图书馆（触发特征）」：触发来自规范正文的依据行）。

**先把两端分清（本协议的前提）**：**作者侧**有本仓库的工作副本（可 `git`、可读工作区）；**取用侧**是**游客**——**只有 https、没有仓库、没有 git**，它**唯一可用的发现入口**是**常驻层里指向图书馆的那条链接**（`AGENTS_COMMON.adoc` / `AGENTS.adoc` 的公共规范被加载时即含此链接，见 link:usage.adoc[]「三、默认引用面与非引用面（外部项目怎么处理）」）。协议**只能建立在取用侧成立的条件上**：作者侧的命令可以写进协议，但**不能写成取用前置**。

**本协议的位置**：本文件给**形态与取值**（入口在哪、索引在哪、怎么取一份文件定位到段），不重复判据；**触发特征与终止条件**仍由 link:usage.adoc[]「一、什么时候该把依据写进图书馆（触发特征）」与「反查解析算法（只取一份，不遍历）」给。本协议**只对"需要依据全文"的场合成立**——日常执行按规范正文走、正文里的**依据名**已足够（link:usage.adoc[]「三、默认引用面与非引用面（外部项目怎么处理）」），**不加载本目录不会有任何功能缺失**。

== 依据的定位协议（入口 + 索引 + 单点取值）

**目标**：取用侧**只凭一条常驻链接与 https**，就能从**依据名**走到**具体文件与文件内的段**，且**不下载整馆、不需要 git、不需要任何版本号**。

**第一步：入口 = 常驻层里的固定地址（不要自己拼地址）**：取用侧**不必知道**仓库长什么样、也不该去猜地址形态——公共规范（`AGENTS_COMMON.adoc` / `AGENTS.adoc`）里指向本文件的那条链接**就是入口**，`https` 直接可达（实测：取回的是**纯文本**，可直接按依据名匹配）。这是全协议**唯一需要写入常驻层的落点**：常驻层写一份**固定地址**（不是"某分支路径拼出来的地址"、不是"某 commit 的地址"）。

**第二步：解索引表（依据名 → 文件）**：读**本文件**（图书馆入口）的「主题登记」表——表把**依据名/主题**映射到**主题文件**。**只读入口这一份**即得映射，**不遍历主题目录、不列目录清单**（link:usage.adoc[]「反查解析算法（只取一份，不遍历）」）。

**第三步：落到文件内的依据段（段）**：主题文件按"**一条依据一段**"组织（见 link:usage.adoc[]「二、依据与规则怎么关联（关联协议）」），**段首即依据名**——按依据名匹配即可定位，**不必先读整份**；拿到段落即达终止条件（link:usage.adoc[]「反查解析算法（只取一份，不遍历）」的终止条件）。

**文件名协议（短、无语义、不承担定位）**：文件名**不是主键、也不承担语义**——上一步的定位**只由入口登记表（依据名 → 主题文件）与文件内的段完成**，故名字**只需在一级目录内唯一、简短可写**，**不承载内容描述、不承载限定语与来源**（名字写成一句话时，它既不可检索、又让每条链接与每次列举都替它付上下文——馆一大，没人会靠文件结构或文件名去找依据）。判据（L1）：①**短**——主题文件名为**单个短词、小写 ASCII、不带分隔的说明语**（形如 `sources.adoc`、`usage.adoc`，都是单词级；**不得**出现"依据的来源与定位协议"这类短语式命名），**长度上限 = 32 字符**（含扩展名，与 link:../specs/general/doc-module.adoc[] 的模块文件名上限同口径）；②**无语义负担**——名字**不必**让读者"望名知义"，**不需**为改名而搬文件（改名只影响登记表一行，**定位不因此断档**：内容主键是终态，见上）；③**只在一级目录内唯一**——馆是**平铺**的，**不建多层子目录、不靠目录结构承载分类**（分类由入口登记表承担）。**与其把主张写进名字，不如把依据写进内容**：文件名省下的每个字符，都是每个读者每次都要付的上下文。

**取值形态（都只依赖 https，按可行性排序）**：

. **直取原始文件（默认，取用侧唯一必要路径）**：对入口返回的地址**原样取用**（先取入口、再按登记表取一份主题文件），站内 `.adoc` 链接指向**同一个纯文本地址**（站点上已实测：`.../library/README.adoc` 返回 `text/plain`）；**这是未经处理器装配的仓库字节**——站点对非 HTML 文件直出原文、页面内的渲染只发生在 `index.html` 自己的正文区（与提示词侧同一判据，见 link:../prompts/_common.txt[]「查看与复制方式」与 link:../PROMPTS.adoc[]「取值路径与装配状态」），故**只需 https，不需要 git**。
. **平台原始文件视图（地址形态的兜底）**：仓库的原始文件也可从平台侧按**分支名**取回（`<平台仓库地址>/-/git/raw/<分支>/<文件>`，`main` 已实测可取）；**分支名是发布面的一部分、不随提交滚动**，故"要版本号"这一前置不成立时它仍然可用——但它是**兜底**：主路径是上一条的直链，避免调用方必需了解平台地址形态。
. **Git 原生（可选、只给有 git 的调用方）**：`git clone --filter=blob:none --no-checkout <仓库>` 后用 `git cat-file -p <commit:path>` 按需取单份——**体积小、且按内容寻址**（见下"版本固化"），但**不是取用侧的必要路径**（取用侧是游客、没有 git）：只有调用方**自己**具备 git 时才有意义。

**版本固化（可选加固，不得写成前置）**：上面三步默认取**入口所在分支的当前内容**——**这已经足够定位到段**（定位要的是"哪儿有这条依据"，不是"某个历史快照"）。若某次核对**需要钉住某一版**（例如报告里要写明"哪一版核对的"），再用 `git ls-remote <仓库> HEAD` 取默认分支当前 commit，并按 `commit:path` 取值或 `curl` 该 commit 对应的原始地址；**这条属作者侧/有 git 的调用方的加固动作**：取用侧**没有**取 commit 的途径（本仓库不发版本号、不维护"当前 commit"登记），**不得**把"先拿到 commit"写成取用前置。

**为什么可以不靠 commit、也不靠路径**：**内容主键才是终态，路径与 commit 都只是到达它的写法**。Git 对**文件内容**按内容寻址——`git rev-parse <commit>:<path>` 给出的是**内容 blob 的 sha**；**同一份内容在任何路径下都是同一个 blob**，文件改名/搬迁后**旧 blob 仍可按 sha 取回**（实测：改名前的 blob sha 在改名后仍能 `git cat-file` 取到原文）。故"可靠性"来自**内容本身可校验**，不来自"取用者先说出 commit"：默认取到的就是当前内容，需要固化时由**能取到 commit 的一方**（作者侧、有 git 的调用方）补上。这条同时解释了为什么本站**不建编号索引**（见 link:adoption.adoc[] 中「图书馆不建编号索引、入口主题表即索引」一条）：入口的「主题登记」表就是索引，**再套一层编号只会多一个没人维护的真源**。

**分段取值（馆特别大时怎么只取一段）**：HTTP 有**标准化的分段取值**——客户端发 `Range` 请求头，服务端在可满足时回 `206 (Partial Content)` 并只传请求的那些字节（RFC 7233；原文与取样记录见 link:sources.adoc[]「依据的定位与取值」）。故"只取依据段、不取整份主题文件"在**支持 Range 的托管服务**上是标准动作。**须如实说明的边界**：本仓库站点与平台原始文件视图**均未实测**到 `Range` 生效（实测请求 `Range: bytes=0-99` 仍返回 `200` 与**整份**内容）——故现阶段取值以**整份文件 + 文件内定位段**为准（单份主题文件不大），**Range 是"托管服务支持时的优化"、不是当前可用路径**；引用方若要用到 Range，须**在其自己实测能拿到 `206` 后再依赖它**，不得假定。

**形态约束（L1）**：①**发现落点只许写固定地址**——常驻层（公共规范入口）里指向图书馆的落点必须是**不随提交滚动的地址形态**（"当前分支的当前内容"），**不得**写成具体 commit、不得要求调用方自取 commit 再拼地址（取用侧取不到）；②**不承载派生落点**——本文件只承载**入口、索引表与取值形态**，不承载"哪条依据具体在第几行/落在哪个 commit"这类**派生的落点表**：落点随文件与 commit 变化，写进入口只会立刻过时，也把"内容主键"降级成"行的位置"（本仓库同时**不提交任何存放这类落点的临时产物**：依 link:../specs/general/doc.adoc[]「注释与文档」，只把讨论/过程落盘者不收；依 link:../specs/core/execution.adoc[]「临时产物」，检查清单与扫描中间结果进 `tmp/`、不入馆）；③**不解析页面结构**——取值走**原始文件或原始文件视图**，"仓库页面/渲染页面上的某条链接"是产物、会改版，**不得当作入口**（本协议唯一承认的动态发现入口是**常驻层里那条固定地址链接**）；④**不靠命名定位**——文件名**不得**被当作检索键（检索键只有依据名，经入口登记表解析），故**不得**用长名/短语式命名承载内容描述，馆内也**不建多层子目录**（分类由登记表承担）；名字长了**既有上下文代价、又制造"改名即断档"的错觉**（见本文件「依据的定位协议（入口 + 索引 + 单点取值）」的『文件名协议』一段）。

== 放哪、怎么用、何时加载

* **位置**：本目录在**仓库根**、与规范入口 `AGENTS_COMMON.adoc` 平级（登记与维护说明见项目规范入口 link:../AGENTS.adoc[]）。**为什么不放 `specs/` 下**：**本仓库所有内容都会被发布出去、没有"只在本站内"的内容**（站点见 link:../README.adoc[]），区别只在**默认引用什么**——`AGENTS_COMMON.adoc` + `specs/` 是**默认引用的公共规范**（接入时按它加载，一个字节都会被引用方取到）；而图书馆**不在默认引用面内**（没有指向它的加载项、不被任何入口取到）。差别不是"发布与否"，而是**内容口径**：图书馆天然包含**只对本项目成立**的内容（当初的失效、取舍、实证、选型理由），默认引用项要么把它们改写成"对谁都不犯错"的空泛表述，要么把本站处置口径（可关闭、不新增要求、冲突次序）反复声明一遍——**项目自己的依据库就是项目自己的内容**，故落在根目录、按需加载、由项目规范入口登记。
* **怎么用**：规范正文里的"依据（标准名/编号）"是入口——按其标准名/编号检索本目录；找不到对应主题时**按需补一篇**（判据见 link:../specs/general/source.adoc[]「内部引用」「外部引用」）。也可以**先读本文件**（主题登记表）再取对应主题文件。**馆可能很大、不能整馆下载**：定位与取值按本文件「依据的定位协议（入口 + 索引 + 单点取值）」三步做——**入口是常驻层里的固定地址**（取用侧只需 https，**不需要 git、也不需要版本号**）、索引是入口的主题登记表、取值是"取一份文件 + 文件内按依据名定位段"，协议与本条的使用判据见 link:usage.adoc[]「四、引用方怎么准确定位依据（不全量下载）」。
* **何时加载（按需懒加载，非必加载）**：要**思考或决策**、出现**争议或取舍**、要**复盘**、要**核对某条依据今天是否仍成立**时才加载——具体触发特征登记在 link:../AGENTS.adoc[]。日常执行按规范正文走即可，**不加载本目录不会有任何功能缺失**。
* **每次取一份即可**：每个主题文件自足（只引用本项目内可加载到的落点），入口登记全部主题，不存在"必须整目录读"的情形。
* **可达性判别（两种读者，两种到达方式）**：**作者侧**（本仓库维护方与在馆内的执行者）工作区里就有本文件，直接读；**取用侧**（引用方项目里的 AI）工作区里**没有**本仓库的文件（也不由公共入口加载本目录）——区别是**它不在默认引用面内**，不是"未发布"（本仓库全部内容都会被发布，见 link:../README.adoc[]）。取用侧**按公共规范里的固定地址用 https 取**（link:usage.adoc[]「三、默认引用面与非引用面（外部项目怎么处理）」）；**只有 https 也够了**——**不要**为定位依据去克隆仓库或遍历工作区（按 link:usage.adoc[]「反查解析算法（只取一份，不遍历）」的终止条件停止）。

== 何时该给一类依据独立成篇（判据）

某类内在依据需要独立成篇时（**判据，非"已建清单"**），再按 link:../specs/general/source.adoc[] 新增主题文件并**同步登记到上表**（写文件与登记是同一个动作）。同时命中以下两条即应独立成篇（命中其一即**不该**）：

* **判据①与规则本体分离**：这类依据**不再与某一条规则同处一处**可承载——即它跨越**多份文件**（不是一个规范文件、一个目录的说明性段落），或**需要长期追溯**（实证与反例、选型与取舍、跨轮次的失效记录），或**存在多来源表述需要统一**语义与强度（如同一决策有多处说法、需指明哪一处为准）。
* **判据②按"依据对谁成立"归类**：同类内部依据里，**既有对外部也成立**的依据、又有**只对本项目成立**的依据——前者与外部标准正文合并成篇（如 link:sources.adoc[] 的"标准原文 + 标准确实支持该条"），后者**必须**独立于外部标准主题，否则一份主题文件会同时混有"对外部成立"与"只对本站成立"两类内容，读者与维护者都会误判其适用范围（`library/README.adoc`「放什么、不放什么」的落点要求）。
* **已按此判据独立成篇的主题**：link:adoption.adoc[]（规范准入判定与本集合自身取舍）——见其「同义性差异与覆盖点」一节（写明"标准**未**规定此类要求、本条属本站更严取舍或组织约定"）。

[quote]
**不预建空壳**：未独立成篇的内在依据仍在上述各处**就地承载**；独立成篇不是"依据必须离开规则所在地"的强制动作，只是"确实需要时"的落点。判据本身即"该不该建"的答案，**不得以"凑主题数"或"看起来完整"为由预建**（link:../specs/general/doc.adoc[]「注释与文档」）。
