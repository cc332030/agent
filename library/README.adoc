= 图书馆（本仓库的依据库）

本目录是本项目的**图书馆**：集中存放本项目里**需要找依据**的东西——规范条目与项目决策背后的**依据**：**为什么这样要求、来源是哪一条、逐字原文是什么、当初要解决的失效长什么样**。

== 为什么要有它

规范正文是"怎么走"的形态（规则 + 判定标准 + 依据名）——这是**刻意**的（见 `specs/core/execution.adoc`「分级与最高关注项」、link:../specs/general/verify.adoc[]「验证总纲」）：执行时多看"为什么"只会占注意力。

但**依据不能只存在名称**：一条规则被执行久了，就会退化成"只记得是这么做的"——提出时的原因不再有人知道（可能原文里写过，也可能只是散在讨论里），于是无法判断它**还成不成立**、无法在争议中据以取舍、无法据以**举一反三**（link:../specs/general/verify.adoc[]「验证总纲」之「防"慢慢脱离初衷"」要求的正是"当初要解决的失效现在还在不在"）。它和 link:../specs/general/source.adoc[] 是同一件事的两端：那份管**引用不许编**，本目录给**依据一个能被检索、被逐字核对的落点**。

== 放什么、不放什么

* **放**：本项目里**任何需要依据的东西**——能**逐字对照**的外部标准原文（引文）、业界权威实践与真实事故的公开陈述、当初的**决策记载**（为什么这样要求、为什么不做别的方案）、**反例**（失效长什么样、实证是什么）、以及技术选型与组织约定的依据。**不限于规范依据**：规范、提示词、脚本、CI 乃至日常决策的依据都可入库。
* **不放**：规则本体（规则在 `specs/` 各文件，图书馆只补依据、不复制规则）、没有出处的观点与推测、**只把讨论过程落盘的会议记录**（link:../specs/general/doc.adoc[]「注释与文档」：空话套话、复述既有结论、为对称凑数者一律不收）。
* **依据找不全时**：按 link:../specs/general/source.adoc[]「无法确证时的正确做法」**如实标"未确证"并写明已查证方式**，不得用虚构内容填补。

== 何时该写、写什么（入口）

本文件只回答**形态**问题（放什么、放哪、是否独立成篇）；**触发**问题——什么时候该把一条依据写进图书馆、入库必写哪几项、什么时候不写——由 link:usage.adoc[]「一、什么时候该把依据写进图书馆（触发特征）」给判据。**依据与规则的互相关联与反查算法**（从规范正文只取一份、不遍历）见 link:usage.adoc[]「二、依据与规则怎么关联（关联协议）」。两者合起来才是完整的写入协议。

== 放哪、怎么用、何时加载

* **位置**：本目录在**仓库根**、与规范入口 `AGENTS_COMMON.adoc` 平级（登记与维护说明见项目规范入口 link:../AGENTS.adoc[]）。**为什么不放 `specs/` 下**：**本仓库所有内容都会被发布出去、没有"只在本站内"的内容**（站点见 link:../README.adoc[]），区别只在**默认引用什么**——`AGENTS_COMMON.adoc` + `specs/` 是**默认引用的公共规范**（接入时按它加载，一个字节都会被引用方取到）；而图书馆**不在默认引用面内**（没有指向它的加载项、不被任何入口取到）。差别不是"发布与否"，而是**内容口径**：图书馆天然包含**只对本项目成立**的内容（当初的失效、取舍、实证、选型理由），默认引用项要么把它们改写成"对谁都不犯错"的空泛表述，要么把本站处置口径（可关闭、不新增要求、冲突次序）反复声明一遍——**项目自己的依据库就是项目自己的内容**，故落在根目录、按需加载、由项目规范入口登记。
* **怎么用**：规范正文里的"依据（标准名/编号）"是入口——按其标准名/编号检索本目录；找不到对应主题时**按需补一篇**（判据见 link:../specs/general/source.adoc[]「内部引用」「外部引用」）。也可以**先读本文件**（主题登记表）再取对应主题文件。
* **何时加载（按需懒加载，非必加载）**：要**思考或决策**、出现**争议或取舍**、要**复盘**、要**核对某条依据今天是否仍成立**时才加载——具体触发特征登记在 link:../AGENTS.adoc[]。日常执行按规范正文走即可，**不加载本目录不会有任何功能缺失**。
* **每次取一份即可**：每个主题文件自足（只引用本项目内可加载到的落点），入口登记全部主题，不存在"必须整目录读"的情形。
* **可达性判别（引用方项目不具备的条件）**：本目录落在本仓库内，**引用方项目里没有它**（其工作区里没有本仓库的文件、也不由公共入口加载它）——区别是**它不在默认引用面内**，不是"未发布"（本仓库全部内容都会被发布，见 link:../README.adoc[]）。故反查依据时先确认工作区里能读到本文件，否则按 link:usage.adoc[]「反查解析算法（只取一份，不遍历）」的终止条件停止（不克隆、不遍历）。

== 何时该给一类依据独立成篇（判据）

某类内在依据需要独立成篇时（**判据，非"已建清单"**），再按 link:../specs/general/source.adoc[] 新增主题文件并**同步登记到上表**（写文件与登记是同一个动作）。同时命中以下两条即应独立成篇（命中其一即**不该**）：

* **判据①与规则本体分离**：这类依据**不再与某一条规则同处一处**可承载——即它跨越**多份文件**（不是一个规范文件、一个目录的说明性段落），或**需要长期追溯**（实证与反例、选型与取舍、跨轮次的失效记录），或**存在多来源表述需要统一**语义与强度（如同一决策有多处说法、需指明哪一处为准）。
* **判据②按"依据对谁成立"归类**：同类内部依据里，**既有对外部也成立**的依据、又有**只对本项目成立**的依据——前者与外部标准正文合并成篇（如 link:sources.adoc[] 的"标准原文 + 标准确实支持该条"），后者**必须**独立于外部标准主题，否则一份主题文件会同时混有"对外部成立"与"只对本站成立"两类内容，读者与维护者都会误判其适用范围（`library/README.adoc`「放什么、不放什么」的落点要求）。
* **已按此判据独立成篇的主题**：link:adoption.adoc[]（规范准入判定与本集合自身取舍）——见其「同义性差异与覆盖点」一节（写明"标准**未**规定此类要求、本条属本站更严取舍或组织约定"）。

> **不预建空壳**：未独立成篇的内在依据仍在上述各处**就地承载**；独立成篇不是"依据必须离开规则所在地"的强制动作，只是"确实需要时"的落点。判据本身即"该不该建"的答案，**不得以"凑主题数"或"看起来完整"为由预建**（link:../specs/general/doc.adoc[]「注释与文档」）。
