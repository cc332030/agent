= 公共内容入口索引（维护方）

本仓库对外分发的**公共内容**有多个公开入口，本文件是它们的**索引**：维护方据此知道"引用方会看到哪些文件、这些文件之间必须互相自足"，检查器据此界定**完整性检查的覆盖面**（link:specs-project-maintainer/verify.adoc[]）。

本文件属**维护方内容**（本仓库私有、不分发）：引用方不需要它，读到它也没有意义。

== 公共内容入口清单

公共内容 = 会被**引用方项目**取到的文本。引用方有两个入口（link:README.adoc[]「引用方式」）：①接入时读的 **安装文档**、②接入后每次会话读的 **通用规范入口**。两者取到的文件合集即"公共内容"，**其中任何一个都会被未知项目加载**，故**公共内容自足**与**接纳面**（影响面/成本/可控性）的核对对象都是这本清单：

[cols="1,2,3", options="header"]
|===
| 入口 | 文件 | 说明

| 安装入口 | `INSTALL.adoc`（link:INSTALL.adoc[]） | 引用方**接入时**读的安装文档：指导 agent 在目标项目根目录创建规范入口（默认 `AGENTS.adoc`、已存在 `AGENTS.md` 时就地融合）并指向远程通用规范入口
| 通用规范入口 | `AGENTS_COMMON.adoc` | 引用方**每次会话**读的规范入口与加载调度器；其 `specs/...` 引用按本文件所在目录解析
| 通用规范入口 | `specs/`（整目录） | 规范正文：必加载层 / 通用层 / 技术栈层 / 项目类型层 / 平台层（分层见 `AGENTS_COMMON.adoc`「分类与懒加载」）
| 通用规范入口 | `prompts/_common.txt` | 公共任务提示词的**公共片段**：会被提示词用 `include::_common.txt[tag=…]` 引用，AI 以纯文本读取、片段未展开时**按提示词正文的指引单独取用**（故它同样会被引用方取到）
| 通用规范入口 | `script/clean_tmp.py` | 随规范分发的通用清理工具（可远程加载执行，见 `specs/core/execution.adoc`「临时产物」）
|===

== 组织与其边界

* **为什么需要本索引**：公共内容此前只口头定义为"`AGENTS_COMMON.adoc` + `specs/`"，而 `INSTALL.adoc`、`prompts/`、`script/clean_tmp.py` **同样会被引用方读到**——覆盖面界定不清时，机械检查会漏掉一半公共内容，而"自足"要求又会被误用于只对维护方成立的文件（造成误报）。本索引把"哪些文件必须自足"变成可机械核对的清单。
* **不属公共内容入口清单**（不被引用方按入口取到，故可引用本仓库私有落点；注意"不进清单"≠"可带私有落点"，判据见下条）：link:README.adoc[]（站点首页，虽然公开渲染，但读者是"来接入的人"而非"已接入的项目"）、`AGENTS.adoc`（本仓库项目规范入口）、`specs-project-maintainer/`（维护方自查层，公开面文档对其只作文字描述、不给可点路径）、`library/`（本仓库图书馆）、`prompts/` 下的**提示词正文**（由用户手动复制、不由入口加载，归属边界见下）、`CHANGELOG.adoc`、`PUBLIC.adoc` 本文件、`script/` 下的维护方工具。
* **提示词正文（`prompts/review.adoc`、`prompts/refactor.adoc`）的归属（显式边界，不是遗漏）**：它们是**对外分发的产物**（用户复制给 AI、在未知项目里执行），但**不由任何入口自动加载**——引用方不会"读着读着"读到它们，故：
  ** **受"自足"约束**（`prompts/` 下不得出现引用方看不到的私有落点）——机械检查按"公共内容"口径覆盖它们；
  ** **不列入上表**：本表界定的是"**哪些文件会被引用方按入口取到**"（决定整合与体积口径），提示词正文不在此列，其质量与接纳面按验证三视角另行核对（见 link:specs-project-maintainer/verify.adoc[]）。
  两件事的分界须写清，否则"算不算公共内容"会各说各话：**自足性看"会不会被未知项目执行"，清单看"会不会被入口取到"**。两类的**并集**才是"自足受限集合"，分类只为解释"为什么同一份约束有两种对象"、不进体积与整合口径（同一文件可同时命中两类，如 `INSTALL.adoc`：既被入口取到、又被复制执行——归类不唯一属设计，不属歧义）。
* **"私有落点"的枚举（自足检查的可核对判据）**：不靠"看着像不像"，按四类逐类核——①本仓库私有目录名：`specs-project-maintainer/`、`library/`；②本仓库私有脚本名：`script/` 下的维护方工具（`script/check_specs.py`、`script/check_effective.py` 及 `check_*` 抓手名）；③本仓库私有文件：`AGENTS.adoc`、`PUBLIC.adoc`、`CHANGELOG.adoc`、根 `README.adoc`（作为**跨目录引用目标**时；同项目内的自我说明不算）；④隐含本仓库结构的相对路径假设（如"本目录上一级必有 `specs/`"）。机械检查覆盖①②③（`check_*` 裸名、`specs-project-maintainer/`、`library/` 等字样），④属语义判断交复核——**"单条 grep 无命中"只否定命中的那一类，不等于全类自足**。
* **清单与实际一致性由机械防线核对**：上表里以反引号点名的路径须**真实存在**；`specs/` 整目录与 `prompts/` 目录的存在性、以及本文件被 link:AGENTS.adoc[] 登记，同样机械核对（改名或漏登记会被拦下）。
* **自足要求的适用范围**（两类合起来才是完整的约束对象）：①**会被入口取到的**——`AGENTS_COMMON.adoc`、`specs/`、`INSTALL.adoc`、`prompts/_common.txt`、`script/clean_tmp.py`；②**会被复制到未知项目执行的**——`prompts/review.adoc`、`prompts/refactor.adoc`。两类都不得引用引用方看不到的私有落点（`specs-project-maintainer/`、`library/`、本仓库脚本名等）。`README.adoc` 与 `PROMPTS.adoc` 是**面向引用方的说明文档**，同样受该约束（见 link:AGENTS.adoc[]「Agent 项目自身工具声明」）。
