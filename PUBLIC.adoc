= 公共内容入口索引（维护方）

本仓库对外分发的**公共内容**有多个公开入口，本文件是它们的**索引**：维护方据此知道"引用方会看到哪些文件、这些文件之间必须互相自足"，检查器据此界定**完整性检查的覆盖面**。

本文件属**维护方内容**（**不在默认引用面内**）：引用方不会按入口取到它、也不需要它。**注意表述口径**：本仓库内容**全部会被发布**（站点会渲染本仓库文档），故"维护方内容"指**引用方不按它加载**，**不是"不对外发布"**。

== 公共内容入口清单

公共内容 = 会被**引用方项目**取到的文本。引用方有两个入口：① 接入时读的 **安装文档**、② 接入后每次会话读的 **通用规范入口**。两者取到的文件合集即"公共内容"，**其中任何一个都会被未知项目加载**，故**公共内容自足**与**接纳面**的核对对象都是这本清单：

[cols="1,2,3", options="header"]
|===
| 入口 | 文件 | 说明

| 安装入口 | `INSTALL.adoc` | 引用方**接入时**读的安装文档：指导 agent 在目标项目根目录创建规范入口并指向远程通用规范入口；**入口文档是安装流程唯一持久化到目标项目的产物**（只放『这是什么、在哪』：规范路径、**安装文档路径**、**取规范脚本路径**、规范副本落点、取回与更新方式、本项目要跨会话保留的约定，判据见 `specs/general/entry-doc.adoc`）
| 通用规范入口 | `AGENTS_COMMON.adoc` | 引用方**每次会话**读的规范入口与加载调度器；其 `specs/...` 引用按本文件所在目录解析
| 通用规范入口 | `specs/`（整目录） | 规范正文：必加载层 / 通用层 / 技术栈层 / 项目类型层 / 平台层
| 通用规范入口 | `prompts/_common.txt` | 公共任务提示词的**公共片段**：会被提示词用 `include::_common.txt[tag=…]` 引用，AI 以纯文本读取、片段未展开时**按提示词正文的指引单独取用**（故它同样会被引用方取到）
| 通用规范入口 | `script/clean_tmp.py` | 随规范分发的通用清理工具（可远程加载执行，见 `specs/core/execution.adoc`「临时产物」）
| 通用规范入口 | `script/fetch-specs.py`（+ 同名入口 `fetch-specs.sh` / `fetch-specs.bat`） | 随规范分发的抓取工具：按入口的加载调度器登记自动解析清单、一次取全，两个平台入口均**按次序探测解释器**（不假定机器上有 python3、都没有时报错退出）；**默认以远程为准**、重复执行即是更新（要「不动本地那份」加 `--keep`）；**默认取到本机用户级缓存**（所有项目共用一份）、缓存不可用时退回项目内临时目录 `tmp/agent-specs/`（要项目内副本加 `--local`）
|===

== 组织与其边界

* **为什么需要本索引**：公共内容此前只口头定义为"`AGENTS_COMMON.adoc` + `specs/`"，而 `INSTALL.adoc`、`prompts/`、`script/clean_tmp.py` **同样会被引用方读到**——覆盖面界定不清时，机械检查会漏掉一半公共内容，而"自足"要求又会被误用于只对维护方成立的文件。本索引把"哪些文件必须自足"变成可机械核对的清单。
* **不属公共内容入口清单**（不被引用方按入口取到；注意"不进清单"**不等于**"不发布"，也**不等于**"可带私有落点"）：`README.adoc`（站点首页，虽然公开渲染，但读者是"来接入的人"而非"已接入的项目"）、`AGENTS.adoc`（本仓库项目规范入口）、`specs-project-maintainer/`（维护方自查层，公开面文档对其只作文字描述、不给可点路径）、`library/`（本仓库图书馆）、`prompts/` 下的**提示词正文**（由用户手动复制、不由入口加载）、`CHANGELOG.adoc`、`PUBLIC.adoc` 本文件、`script/` 下的维护方工具。
* **提示词正文的归属（显式边界，不是遗漏）**：它们是**对外分发的产物**（用户复制给 AI、在未知项目里执行），但**不由任何入口自动加载**——故 ① **受"自足"约束**（`prompts/` 下不得出现引用方看不到的私有落点）；② **不列入上表**（本表界定的是"哪些文件会被引用方按入口取到"）。**自足性看"会不会被未知项目执行"，清单看"会不会被入口取到"**——两类的**并集**才是"自足受限集合"。
* **"私有落点"的枚举（自足检查的可核对判据）**：不靠"看着像不像"，按四类逐类核——①本仓库私有目录名：`specs-project-maintainer/`、`library/`；②本仓库私有脚本名：`script/` 下的维护方工具（`script/check_specs.py`、`script/check_effective.py` 及其配套测试与 `check_*` 一类抓手名）；③本仓库私有文件：`AGENTS.adoc`、`PUBLIC.adoc`、`CHANGELOG.adoc`、根 `README.adoc`（作为**跨目录引用目标**时）；④隐含本仓库结构的相对路径假设（如"本目录上一级必有 `specs/`"）。机械检查覆盖①②③④中的可机械判定部分，④属语义判断交复核——**"单条 grep 无命中"只否定命中的那一类，不等于全类自足**。
* **清单与实际一致性由机械防线核对**：上表里以反引号点名的路径须**真实存在**；`specs/` 整目录与 `prompts/` 目录的存在性、以及本文件被 `AGENTS.adoc` 登记，同样机械核对。
* **自足要求的适用范围**（两类合起来才是完整的约束对象）：①**会被入口取到的**——`AGENTS_COMMON.adoc`、`specs/`、`INSTALL.adoc`、`prompts/_common.txt`、`script/clean_tmp.py`、`script/fetch-specs.py`（及其同名入口）；②**会被复制到未知项目执行的**——`prompts/review.adoc`、`prompts/refactor.adoc`。两类都不得引用引用方看不到的私有落点。`README.adoc` 与 `PROMPTS.adoc` 是**面向引用方的说明文档**，同样受该约束。
