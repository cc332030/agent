= AGENT 执行规范

本规范约束 agent 的编码与协作行为，适用于**任何语言、任何项目**。

== 访问与解析（引用方须知）

* **引用方式**：引用方以 https 公网地址或本地路径引入本文件，不限方式。**引用方只需本文件**——规范正文在其所在目录的 `specs/` 下，随本文件一并生效，`specs/...` 一律相对本文件所在目录解析。本文件与其 `specs/` 即**全部公共内容**。
* **公共内容须自足**：公共内容只引用本文件与 `specs/` 下的文件，**不得引用引用方看不到的私有落点**（他人仓库的目录、项目入口文件、脚本名等）——引用了就是死链。
* **严格使用本规范、冲突时的优先级（L1）**：以本文件**当前内容**为准；与本规范冲突时以本规范定义为准。**引用方项目自身规范优先**——引用方自己的项目规范（通常为根目录 `AGENTS.adoc`）与公共内容冲突时，以**该项目自身规范**为准（两者不得混淆）。
* **入口可达性自检（L1，动手前先做）**：先确认本文件**实际可取到**；取不到（网络不通、地址失效、无副本）须**先告知用户规范不可达并请其给出可访问地址或副本**，**不得假装已加载**（未读规范即评"符合规范"、或凭记忆代替规范均属违规）。
* **从属者（子 agent / 被引用方）的加载由入口驱动、不靠自报（L1）**：派发者须把"读取并遵守本入口"作为派发内容的一部分；执行者（含子 agent、被派发的分步任务）**读到即须自行按本文件的调度器加载**，不得以"没被派发这份规范""上级已读过"为由跳过加载或降低约束——**约束随入口传递、不随上下文传递**。
* **网络不佳时取本地副本**：本规范常部署于外网。**强烈建议**先把本文件与其 `specs/` 取到本地副本再读（相对解析基准不变）。**取文件的抓手随本规范分发**：本目录 `script/` 下的 `fetch-specs.py`（配同名入口 `.sh`/`.bat`）在目标项目根目录直接执行脚本名即可，一次取全、不必自己拼逐条下载命令；**取不到时直接读远程入口地址即可**（取文件不是读规范的前置条件）。**副本落点、取回方式与解释器兜底以本文件「取规范到本地副本」为唯一真源**（本文件不复述那几条路径与命令：副本落点只写一处，读的与写的对不上即无从核对）；**副本落点与"再取一次"的方式须写进项目入口文档**（新开实例从这里读到，判据见 `specs/general/entry-doc.adoc`）。

== 安装与更新（引用方接入与取回口径）

* **入口文档（安装流程）**：在目标项目根目录创建入口文档，文件名取 `AGENTS.adoc`；已存在 `AGENTS.md` 时就地融合（**不重命名、不迁移、不另建**）。入口文档是**唯一持久化到目标项目的产物**（一次会话结束后，下一个会话只能看到落到项目里的文件）。**写入判据**见 `specs/general/entry-doc.adoc`——那是唯一真源，本文件不重复其条文。入口文档须逐字原样复制下面代码块里的内容（含全部换行与空行）：

[source,asciidoc]
----
本项目的 agent 执行规范入口为：

https://agent.c332030.com/AGENTS_COMMON.adoc
（重装、更新、要完整的取法与退路，也读它——安装与取回口径在本文件内）

取规范脚本（要再取一次规范、或本机没有副本时用它）：

https://agent.c332030.com/script/fetch-specs.py

优先取到本地副本（避免网络原因无法访问）：**下载的文件一律只落 `~/.cache/agent-specs`**——规范文件与安装脚本（取规范脚本、清理脚本）都在这一处，不在项目里另留副本；在项目根目录运行一次取文件抓手即可（它把安装脚本也一并落到该处）；取不到时就直接读上面的远程入口；**需要最新规范时再运行一次取规范脚本即是更新**。

该文件夹是**只读的**：取完即收紧为只读，**严禁任何项目改动它**（不得就地编辑、新增、删除或改名其中的任何文件；要留自己的东西写进项目自己）。

规范属强制约束：**开工前必须先读取规范再执行**，不得因未读取/记不全而跳过或放宽任何条款。

读取该入口及其引用的 specs/ 规范，并持续遵守其全部要求。
----

* **本流程可重复执行、且以远程为准**：安装脚本（本文件与随规范分发的取文件抓手）会持续更新，任何时候再执行一次都应拿到**当前最新**的一份：
** **入口文档（幂等）**：已含上面的入口占位、且与它逐字一致：不动；已含但**不一致**：**就地更新为最新模板的那几行**，保留其后的项目自身内容；**没有**入口占位：在开头融合（与项目自身规范合写在同一文件里时不新增文件）。**用户改过的行以用户改过的为准**：**用户手工编辑过的模板内容一律照原文保留**——不符合本模板时**不自动改回**，只在汇报里指出不一致、**等用户定**。
** **规范副本（以远程为准）**：跑一次取规范脚本即是更新；其落点、取回方式与解释器兜底**以「取规范到本地副本」为唯一真源**（那一节不复述脚本头部注释里的参数细节）。

== 取规范到本地副本

* **取回口径的工序侧真源是 `script/fetch-specs.py` 的头部注释**（脚本的文档头先行与承载位置见 `specs/general/script.adoc`）：脚本的用法与开关（`--base` 换来源、`--keep` 不动本地那份、`--list` 只列清单）、**默认以远程为准**（取回的字节与本地不同才落盘、重复执行即是更新、失败保留本地已有那一份）、退出码语义（0 成功、1 有文件没取到、2 参数或前置条件错误——非 0 就别把副本当已就绪）与**解释器兜底次序**（Linux/macOS 先 `python3` 再 `python`；Windows 先 `py -3`、再 `python3`、最后 `python`；一个都没有时报错退出非 0、**不静默继续**）都写在那里，本节不复述、也不在别处再抄一份。
* **落点只有一处**：**用户家目录**下的 `.cache/agent-specs`——不分系统、不分环境都是这一个路径，其下按来源地址分槽（同一台机器上的所有项目共用这一份）。**下载的东西一律只落这一处**：规范副本、取规范脚本（及其平台入口）、清理脚本 `clean_tmp.py` 都落在这一个路径下；既不在项目里另留副本，也不手工挪去别处。
* **落点取完即只读、严禁项目改动它（L1）**：取完即把该文件夹收紧为**只读**（目录去掉写位、文件只留读位；取值与例外见 `script/fetch-specs.py` 头部注释），**任何项目都不得改动落点里的内容**——不得就地编辑规范副本、不得往落点里新增文件、也不得删除或改名其中的任何东西。**这不止是规范里定义的一条**：只读由**本机文件系统**保证（非特权调用方改不动），要改必须先显式放开权限——那一步刻意、可见、须自担后果。**平台边界（别把上面这句当成全平台强制）**：**Windows 上只有“文件只读”这一半由文件系统保证**——目录的增删改名拦不住（Windows 的 READONLY 属性对目录不阻止增删改名，删除权来自父目录）；故那一半靠**本条规范**约束，判据与实测见 `script/fetch-specs.py` 头部注释「已知限制」。**项目要留自己的东西，写进项目自己**（临时产物按 `specs/core/execution.adoc`「临时产物」走 `tmp/`）。理由：落点是**规范正文本身**的位置，就地改它等于把规范改成项目私有的那一份——规范是只读的参考物、公共内容须自足（见 `specs/general/source.adoc`）。
* **取回口径与判据分家**：「入口文档里具体写哪几条路径、落点长什么样」的判据真源是 `specs/general/entry-doc.adoc`，本文件不重复其条文；**"没有解释器时怎么办"的处置**（先按本平台既有的软件分发方式装一个 python 3——这是**人**的一步，入口**不得**代为安装运行时；只装 python2 的发行版（CentOS/RHEL 8 及更早、老 macOS）不算"一个都没有"）见 `script/fetch-specs.py` 头部注释；**取不到时直接读远程入口地址即可**——本规范在网络上就是这套文件，**不建议**改用 `curl … | python3 -`（**它同样要 python**）。

=== 技术栈层（检测到即加载，不得遗漏）

* **Java 项目**（存在 `.java`、`pom.xml`/`build.gradle`、lombok 配置）→ `specs/stack/java.adoc` + `specs/stack/java-syntax.adoc` + `specs/stack/java-testing.adoc`。识别特征（**本处只给"什么时候要加载、凭什么认出来"**，取值与判法写在被引文件里——与本节「任何代码活动」条同一形态、同一口径，不另立一份）：**类型指代**（写 javadoc 时要提到一个类）、**对象转换**（写多层嵌套对象之间的搬运代码）、**新建数据对象**（要新建数据对象类，或要给既有对象补这套注解——补注解须**主动声明**，review 时不查、全局口径见 `specs/general/review.adoc`）、**持久化访问**（要查/改库：出现统一服务入口一类的继承特征、查询构造 API、或 Wrapper 一类构造器 `new`、Wrapper 静态工厂（`Wrappers` 一族）的字样时）、**Feign 接口命名**（要写声明式 HTTP 调用接口的名字，**只此一类**接口适用）、**构造方法不手写**（`@NoArgsConstructor`/`@RequiredArgsConstructor`/`@AllArgsConstructor` 一类字样出现时）、**字段接口只加 get 不加 set**（要写承载字段读写契约的 `interface`、或给这类接口加访问器注解时）、**接口实现的访问器桥接**（类实现接口、两侧名字对不上时）、**成员与方法次序**（要新增字段/方法：决定它加在已有成员的前面、中间还是末尾，或要写方法重载、写数据转换方法时）、**链式赋值顺序**（要写链式 setter / builder 链的赋值环节时）、**局部变量类型推断**（要声明局部变量：`val`/`var` 字样出现时）、**序列化**（要让某类型实现 `Serializable`、或出现 `serialVersionUID` 时）、**测试类命名与拆分**（要新建或改动 Java 测试类：类名带 `Tests`/`BootTests`/`PerfTests`/`IT` 一类后缀时）、**跨语言执行脚本**（要把 SQL/Lua 等放进资源目录）、**SQL 写法**（要写建表/改表或数据变更语句）、**分页查询**（要写分页的返回类型或元素转换：出现分页容器或元素转换字样时）、**逻辑删除**（要给按实体/表查询的方法定名：出现删除标志字段、`@TableLogic` 一类逻辑删除声明、或在判定"这两个查询方法该怎么起名"时）、**枚举查找的失败处理**（要写按值查枚举/按任意取值取默认枚举：出现 `Enum.valueOf` 一类查找式调用、或自己在写这类枚举工具时）
* **Java 数据对象模板**（识别特征：要新建数据对象、或出现 `@Singular`/`@Accessors(chain = true)` 一类字样时）→ `specs/stack/java-object.adoc`。**模板文件、不是规范文件**：判据本体在 `specs/stack/java.adoc`「编码」，该文件只把它们连成一份可直接复制的清单；不加载它不会有规则缺失
* **Spring 项目**（存在 Spring 依赖/注解）→ `specs/stack/spring.adoc`（识别特征：要写/改 Spring 注解与分层代码、要写/改 `@RequestMapping`/`@GetMapping` 一类的**路由路径**、要写/改**配置项绑定注解**（`@Value`/`@ConfigurationProperties`）、要写/改**参数校验注解**、**HTTP 方法映射**与**声明式客户端契约**（含契约路径前缀））
* **Maven 构建**（存在 `pom.xml`/`mvnw`）→ `specs/stack/maven.adoc`。识别特征：**要跑 Maven 构建/测试时**（裸 `mvn`、命令行构建）、要配置或排障**包源与镜像**、要判定**构建并行度**
* **Bash/Shell 脚本**（存在 `.sh`，或 shebang 为 bash/sh）→ `specs/stack/bash.adoc`
* **Python 脚本**（以 `python3`/`python` 为 shebang 的 `.py`）→ `specs/stack/python.adoc`
* **Windows 批处理**（存在 `.bat`/`.cmd`）→ `specs/stack/batch.adoc`
* **PowerShell 脚本**（存在 `.ps1`）→ `specs/stack/powershell.adoc`
* **其他技术栈**按其栈文件加载（未登记的栈按通用层与本入口执行，不臆造其专属规则）；新增栈文件时须在本层登记并写明检测特征（见下「技术栈扩展约定」）。

=== 项目类型层（项目在其自身规范中主动声明才加载）

* **通用工具/库类项目**（识别特征：项目以可复用的组件/库/工具为主、要求各类绝对正确与可维护）→ `specs/general/doc-tool.adoc`。**触发方式**：项目在**自身规范**中主动声明，声明模板：`本项目为通用工具/库类项目，各类须保证绝对正确与可维护性。`；未声明即按普通项目处理。

=== 平台层（按使用平台加载）

* **CNB 平台**（要在该平台上开发协作、与平台 NPC 协作、**在 Issue/PR 里发评论 @ 某个 NPC 发起一次执行**；识别特征：要建分支/建 PR、要判"改动能不能落到别的仓库"、要派发或复核、要发评论或处置评论、要解决冲突/压缩提交（含"只被要求压缩提交"的情形）、要把平台上的任务单/评论作为操作对象）→ `specs/platform/cnb.adoc`（该文件承载本平台上的全部专属口径与判据，本入口不列其条目）

=== 维护方层（只对维护"被其他项目引用的共享内容集合"的项目生效）

* 该层不在公共入口的加载项内，由**维护方项目自己的项目规范**登记——公共内容不引用其私有文件，引用方按公共输入执行时取不到它。维护方需**自行设机械防线**并自备元规范：条目准入与定级、规范集合自身的重构与拆分、最高关注项的不可降级清单、维护方的验证义务。

== 技术栈扩展约定

新增技术栈规范时：在 `specs/stack/` 下新增栈文件，只收录该栈专属规则（跨语言通用规则一律写入 `specs/general/`，避免重复）；**新增前先过准入判定**（对任意项目成立才进公共内容，只对某个项目成立则写进该项目自己的项目规范）；同步在本入口的"技术栈层"登记并写明检测特征，保证按项目类型加载且不漏。
