= AGENT 执行规范

本规范约束 agent 的编码与协作行为，适用于**任何语言、任何项目**。

== 访问与解析（引用方须知）

* **引用方式**：引用方以 https 公网地址或本地路径引入本文件，不限方式。**引用方只需本文件**——规范正文在其所在目录的 `specs/` 下，随本文件一并生效，`specs/...` 一律相对本文件所在目录解析。本文件与其 `specs/` 即**全部公共内容**。
* **公共内容须自足**：公共内容只引用本文件与 `specs/` 下的文件，**不得引用引用方看不到的私有落点**（他人仓库的目录、项目入口文件、脚本名等）——引用了就是死链。
* **严格使用本规范、冲突时的优先级（L1）**：以本文件**当前内容**为准；与本规范冲突时以本规范定义为准。**引用方项目自身规范优先**——引用方自己的项目规范（通常为根目录 `AGENTS.adoc`）与公共内容冲突时，以**该项目自身规范**为准（两者不得混淆）。
* **入口可达性自检（L1，动手前先做）**：先确认本文件**实际可取到**；取不到（网络不通、地址失效、无副本）须**先告知用户规范不可达并请其给出可访问地址或副本**，**不得假装已加载**（未读规范即评"符合规范"、或凭记忆代替规范均属违规）。
* **从属者（子 agent / 被引用方）的加载由入口驱动、不靠自报（L1）**：派发者须把"读取并遵守本入口"作为派发内容的一部分；执行者（含子 agent、被派发的分步任务）**读到即须自行按本文件的调度器加载**，不得以"没被派发这份规范""上级已读过"为由跳过加载或降低约束——**约束随入口传递、不随上下文传递**。
* **网络不佳时取本地副本**：本规范常部署于外网。**强烈建议**先把本文件与其 `specs/` 取到本地副本再读（相对解析基准不变）。**取文件的抓手随本规范分发**：本目录 `script/` 下的 `fetch-specs.py`（配同名入口 `.sh`/`.bat`）在目标项目根目录直接执行脚本名即可，一次取全、不必自己拼逐条下载命令；**取不到时直接读远程入口地址即可**（取文件不是读规范的前置条件）。**副本落点、取回方式与解释器兜底以安装文档 `INSTALL.adoc` 为唯一真源**（本文件不复述那几条路径与命令：副本落点只写一处，读的与写的对不上即无从核对）；**副本落点与"再取一次"的方式须写进项目入口文档**（新开实例从这里读到，判据见该文件）。

== 最高优先级铁律（先读）

以下五条为 **L1、最高优先级**，任何理由（含"重构/精简/上下文不够"）都不得规避；**重构/去重时不得删除或降级本条及其引用**。分级定义见 `specs/core/execution.adoc`「分级与最高关注项」。

* **文件移动/重命名必须用 `git mv`**，禁止 delete+create（用「新增新文件 + 删除旧文件」代替移动/重命名会让 git 历史断裂）。完整定义见 `specs/general/git.adoc`「文件移动与重命名」。
* **同一文件的重命名与内容修改必须分两个提交（最高关注项 P7）**：先 `git mv` 并只提交改名（内容逐字节不变、本次涉及改名的文件全在这一个提交里），再改内容。**"压缩提交"的请求未点名本条时，只压临时中间提交、本条的两个提交原样保留**。完整定义见 `specs/general/git.adoc`「重命名与内容修改须分两个提交（默认固定动作）」。
* **不得执行任何会不可逆丢失内容的操作**（删除文件/目录、清空数据、`rm -rf`、`git reset --hard`、强推覆盖远端、删除平台任务单下的评论）：先确认目标、先备份可取回、范围可界定，三项任一不确定即**停下提问**。
* **不得编造事实与来源**（命令/API 签名、依赖坐标、标准编号与名称、链接与路径、数据与结论）：不知道就明说并去查证，宁可不给也不得编。
* **优先站在前人的肩膀上看世界**：规范条目的依据优先引用广泛、高知名度、高可靠性的业界标准与文献（ISO/IEC/IEEE、RFC、W3C、OWASP 等），出处**只写标准名/编号、不附链接**；对标准有明确自身取舍时须显式覆盖并说明理由。完整规则见 `specs/general/source.adoc`「外部引用」。

== 分类与懒加载（加载调度器）

=== 规范文件登记完整性

本入口是规范文件的**唯一登记处**：凡被 `specs/...` 引用的文件都须在此登记（未登记即永远不会被加载、规则实际失效），登记也不得指向不存在或未被引用的文件——**"写文件"与"登记调度器"是同一个动作**。该一致性由机械校验核对。

**加载规则**：**涉及即加载、不得跳过**。凡工作涉及对应主题、或项目具备对应技术特征（见各条**识别特征**），须实际加载对应文件；不得因"文件不在常驻上下文"而凭记忆或仅凭本入口猜测执行。**必加载层每次工作都加载**。

=== 必加载层（每次工作都加载）

* `specs/core/execution.adoc` — 执行原则：分级与最高关注项、指令执行、先规划后执行、文件操作强制检查、破坏性操作、临时产物、任务生命周期与节点自查、规范变更的存量处理。

=== 通用层（涉及对应活动时加载）

* **写任何新代码、改任何既有代码（含代码评审）** → `specs/general/coding.adoc`（含「抽象与接入成本」「代码复用」；「持久化访问（数据库/缓存等）」——含**统一入口**、**请求响应类优先移动复用**、**本项目自身的依赖不算三方依赖**；「对象转换」——含**多层嵌套对象**；「跨语言执行脚本的落点」——含 **`src/main/resources/`**；「HTTP 接口语义」；「代码质量（新产出即高质）」——含**代码评审**时逐条核对）
* **写/改脚本（bash、Python、Node、PowerShell、Windows 批处理；识别特征：`.bat`/`.cmd` 与 `.sh` 成对、安排取舍（要不要多读一份资料 / 要不要再跑一遍）、要把逻辑在两个平台各写一份、要为脚本另建独立文档）** → `specs/general/script.adoc`（含「脚本文档随脚本落盘」——**脚本单打独斗**、承载按**多行块注释**取值；「脚本头部注释」——**文档头先行**、取值写**常量名**；「参数处理」「退出码」「安全」「跨环境脚本」——纯**逻辑只写一份**、入口只做薄壳）
* **写注释/文档、判定内容写在哪一层（识别特征：文中出现包名 + 类名形态的指代）** → `specs/general/doc.adoc`（含「注释与文档」「必记录项」「文档质量」「文档组织与导航」「索引页的触发判据」「引用路径」「类型指代：优先写类名 + import、**不写类全名**」）
* **新增/调整任何内容时判定名称的落点、或要引入/引用一个已定义的名称（识别特征：要为一个概念定名、要给名称下定义、出现"这个代号指什么"、要把名称的定义归档到某处）** → `specs/general/terminology.adoc`（含「数据字典」——**只引名称不引定义**、**作用域决定落点且每档只一处**（本文件的字典写在该文档开头）、条目形态照 ISO 1087、**新增与调整内容时都须判定**、图书馆等不在默认引用面内的落点）
* **写/更新设计文档、测试设计文档、判定信息归属** → `specs/general/doc-design.adoc`（含「依赖关系文档（模块间依赖的唯一视图）」）
* **业务系统全生命周期文档（`doc/` 下有阶段目录、项目走立项→上线完整流程）** → `specs/general/doc-lifecycle.adoc`
* **多模块项目的模块文档组织** → `specs/general/doc-module.adoc`
* **git 操作（文件移动/重命名、行尾与检出归一、暂存与提交、提交信息）** → `specs/general/git.adoc`
* **写/更新变更日志（存在 `CHANGELOG.*`、要新增或改写条目）** → `specs/general/changelog.adoc`
* **code review（含每次改完东西后对本轮改动的复核）** → `specs/general/review.adoc`
* **多 agent 协作（拆分、派发、调用量控制、硬超时与降级；含「派发入口（评论唤起新实例：一次评论 = 一次派发；执行者不得自行发评论唤起自己）」）** → `specs/general/collab.adoc`
* **文件编码与换行符（新增/编辑文件、跨 Linux 与 Windows 协作、写 `.bat`/`.cmd`/`.ps1`、配置 `.gitattributes`/`.editorconfig`）** → `specs/general/encoding.adoc`

=== 技术栈层（检测到即加载，不得遗漏）

* **Java 项目**（存在 `.java`、`pom.xml`/`build.gradle`、lombok 配置）→ `specs/stack/java.adoc` + `specs/stack/java-syntax.adoc` + `specs/stack/java-testing.adoc`。涉及：**类型指代**（写 javadoc 时用**全限定类名**还是类名 + `import`，含 `classpath` 判定）、**对象转换（MapStruct）**、**MyBatis-Plus 持久化访问**（识别特征：`lambdaQuery`/`lambdaUpdate`/`ktQuery`/`ktUpdate` 与**禁止 `new QueryWrapper`**）、**Feign 接口命名**（**只此一类**接口适用）、**构造方法不手写**（`@NoArgsConstructor`/`@RequiredArgsConstructor`/`@AllArgsConstructor`）、**测试类命名与拆分**（`Tests`/`BootTests`/`PerfTests`/`IT` 四类后缀；一个被测类可按需求/分类拆多个测试类、同分类同属性须归一类、不得滥拆）、**跨语言脚本**（SQL/Lua 放 `src/main/resources/`）。
* **Spring 项目（存在 Spring 依赖/注解）** → `specs/stack/spring.adoc`（注入、Bean 定义、配置、事务、分层与职责）。识别特征：写/改 `@RequestMapping`/`@GetMapping` 一类的路由路径时，按「**HTTP 接口路径优先用中划线（kebab-case）**」判（存量随动迁移）。
* **Maven 构建**（存在 `pom.xml`/`mvnw`）→ `specs/stack/maven.adoc`（仓库与镜像、依赖、构建与验证）。
* **Bash/Shell 脚本**（存在 `.sh`，或 shebang 为 bash/sh）→ `specs/stack/bash.adoc`（行尾 LF）。
* **Python 脚本**（以 `python3`/`python` 为 shebang 的 `.py`）→ `specs/stack/python.adoc`（行尾 LF、docstring 文档头）。
* **Windows 批处理**（存在 `.bat`/`.cmd`）→ `specs/stack/batch.adoc`（行尾 CRLF、纯 ASCII、专属坑位）。
* **PowerShell 脚本**（存在 `.ps1`）→ `specs/stack/powershell.adoc`（行尾 CRLF、同名 `.bat` 启动脚本）。
* **其他技术栈**按其栈文件加载（未登记的栈按通用层与本入口执行，不臆造其专属规则）。

=== 项目类型层（项目在其自身规范中主动声明才加载）

* **通用工具/库类项目**（以可复用组件/库/工具为主、要求每个类设计时保证绝对正确与可维护）→ `specs/general/doc-tool.adoc`。**触发方式**：项目在**自身规范**中主动声明，声明模板：`本项目为通用工具/库类项目，各类须保证绝对正确与可维护性。`；未声明即按普通项目处理。

=== 平台层（按使用平台加载）

* **CNB 平台**（在其上进行任务开发与合并请求管理、与平台 NPC 协作、**在 Issue/PR 里发评论 @ 某个 NPC 发起一次执行**）→ `specs/platform/cnb.adoc`。涉及：分支与合并请求统一、变更范围只限当前项目、冲突处理、NPC 禁合并、**评论唤起新实例**（**执行者不得自行发评论唤起自己**）、**评论不得删除**、**压缩提交（**提交历史整理**）**、对象钉定与可追溯、平台侧执行吞吐。

=== 维护方层（只对维护"被其他项目引用的共享内容集合"的项目生效）

* 该层不在公共入口的加载项内，由**维护方项目自己的项目规范**登记——公共内容不引用其私有文件，引用方按公共输入执行时取不到它。维护方需**自行设机械防线**并自备元规范：条目准入与定级、规范集合自身的重构与拆分、最高关注项的不可降级清单、维护方的验证义务。

== 技术栈扩展约定

新增技术栈规范时：在 `specs/stack/` 下新增栈文件，只收录该栈专属规则（跨语言通用规则一律写入 `specs/general/`，避免重复）；**新增前先过准入判定**（对任意项目成立才进公共内容，只对某个项目成立则写进该项目自己的项目规范）；同步在本入口的"技术栈层"登记并写明检测特征，保证按项目类型加载且不漏。
