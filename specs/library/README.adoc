= 依据图书馆（懒加载层）

本目录是**所有项目**可用的**依据图书馆**：集中存放规范条目与项目决策**背后的依据**——**为什么这样要求、来源是哪一条、逐字原文是什么、当初要解决的失效长什么样**。

== 为什么要有它

规范正文是"怎么走"的形态（规则 + 判定标准 + 依据名）——这是**刻意**的（见 `specs/core/execution.adoc`「分级与最高关注项」与 `specs/general/verify.adoc`「验证总纲」）：执行时多看"为什么"只会占注意力。

但**依据不能只存在名称**：一条规则被执行久了，就会退化成"只记得是这么做的"——提出时的原因不再有人知道（可能原文里写过，也可能只是散在讨论里），于是无法判断它**还成不成立**、无法在争议中据以取舍、无法据以**举一反三**（`specs/general/verify.adoc`「验证总纲」之「防"慢慢脱离初衷"」要求的正是"当初要解决的失效现在还在不在"）。本条与 `specs/general/source.adoc` 是同一件事的两端：那条管**引用不许编**，本条给**依据一个能被检索、被逐字核对的落点**。

== 放什么、不放什么

* **放**：能**逐字对照**的依据——外部标准的原文（引文）、业界权威实践与真实事故的公开陈述、本集合**内部**规范中支撑某条的那段原话、以及**反例**（失效长什么样、实证是什么）。适用范围**不限于规范依据**：项目后续**任何需要找依据**的东西都可入库（技术选型、组织约定、设计取舍），不限于规范条目。
* **不放**：规范条目本体（规则正文在 `specs/` 各文件，图书馆只补依据，不复制规则）、没有出处的观点与推测、**只把讨论过程落盘的会议记录**（`specs/general/doc.adoc`「文档不得注水」：空话套话、复述既有结论、为对称凑数者一律不收）。
* **依据找不全时**：按 `specs/general/source.adoc`「无法确证时的正确做法」**如实标"未确证"并写明已查证方式**，不得用虚构内容填补。

== 怎么用、何时加载

* **按需加载，不常驻**：本层**不属必加载层**（见 `AGENTS_COMMON.adoc`「分类与懒加载」）——执行时按规范正文走即可；**要思考、要决策、遇争议或取舍、要复盘、要核对某条还成不成立**时才加载对应主题文件。
* **反查路径**：规范正文里的"依据（标准名/编号）"是入口——按其标准名/编号检索本层；找不到对应主题时**按需补一篇**（判据见 `specs/general/source.adoc`「内部引用」、「外部引用」）。
* **只读入口即可起步**：入口登记全部主题；每个主题文件**自足**（只引用 `AGENTS_COMMON.adoc` 与 `specs/` 内可加载到的落点，不引用引用方看不到的私有落点）。
* **代价说明（可预判）**：本层**只在不加载它也能正常干活时被打开**——触发条件为"要思考/要决策/要复盘/要核对依据"（不是每次会话）；单文件在其入口声明所属主题，**按主题取一份即可**（不会要求整目录加载）；体积量级与常驻层无关（常驻层体积上限另有机械边界，本层不参与）。因而不加载它不会有任何功能缺失，加载它也不改变任何行为——它**只提供依据，不新增要求**。

== 与引用方项目的关系（不覆盖、不改动）

* **只是依据，可关闭**：本层内容**不构成对引用方项目的额外要求**——规则本体在 `specs/` 各文件（该加载哪个、按调度器执行）；图书馆只让读者**查得到依据**，**关闭它（不加载）不影响任何规则生效**。
* **与项目自身约定的冲突次序**：引用方项目可以在**自己的项目规范**里对本集合的依据/规则**加严或另取依据**——冲突时以**引用方项目自身规范为准**（`AGENTS_COMMON.adoc`「访问与解析」），图书馆不会据此静默推翻引用方既有约定。
* **不默认改动任何工作区**：图书馆是**纯文本依据**，不引入依赖、不要求工具链、不默认改动/格式化引用方文件、不代为提交、不清理其临时产物；**离线也能用**（全部内容随规范一并取到，无需联网取回原文）。
* **不夹带私有约定**：馆内不得出现只对某个项目/某个平台成立的私有路径、脚本名与目录结构（私人落点引用方看不到，读到即死链）。
