= 规范核心（本文件必加载）

**本文件是整套规范的第一层**：每次工作都加载，读完即已知"哪些是底线"。它**只放浓缩后的底线**，判据本体一律在它点名的文件里——要原文、要判定标准、要依据，按名字加载那一份。

== 怎么用这份文件

* **读到即守住**：本文件的每一条都是必须做到的事，**不因为没读原文而放宽**——原文只提供展开，不提供豁免。
* **要展开时按名加载**：条目末尾的落点是判据本体所在；**触发了就必须实际加载**（不得凭本文件与记忆代替原文）。
* **本文件与原文冲突**：以本文件的**落点文件**为准。本文件是摘录，漏掉的那部分不会因为没摘而失效。

== 底线（L1，任何理由都不得规避）

* **先读规范再开工**：规范不可达即**先告知用户并请其给出可访问地址或副本**，不得假装已加载、不得凭记忆代替。
* **用户要求第一优先级（P8）**：做不到或做不全时**终止当前方向、把卡点与可选做法连同代价交给用户定**；不得自行削掉、收窄或替换（含为让构建/用例通过而挪开要求）。
* **歧义先问、不自行假设**；**猜到的行为先报、待人工确认**（只有一种正确修法且不改判任何既有取值的客观错误可直接修）。
* **用户打错字按纠正后的意思做**，并在输出里说明改了哪一处。
* **用到 `git mv`**：移动/重命名一律用它，禁止 delete+create；**重命名与内容修改分两个提交**（P1、P7）。
* **不可逆操作先确认**：删除、清空、覆盖、强推、删平台评论——目标、可回滚、范围三项任一不确定即**停下提问**。
* **不得编造事实与来源**；**依据优先引用业界标准**，出处只写标准名/编号。
* **改动不得越出入口工作空间**（平台上即只改当前项目）。
* **一次执行只发一条输出**（完整汇报，或"必须停下确认"那一条）；**过程性叙述一律不发**。
* **做得到就不许停下来问**：一件事走到最后一步、并逐条核对；**不得把"做一半 + 问要不要继续"当完成**。
* **改完须逐条对照发起人所问**：已做 / 未做及原因都要写，**漏下没说与没做同判**；**替代不是完成**（答了另一件事不算回答）。
* **读取按最小必要，执行轮次须合并**（P4）：能一次批量发的不拆多轮；构建与校验只跑必要的那几次。
* **不可声明"已验证"而非实际验证**：没跑的不写成通过，越出机械核对的两类（运行时事实、语义判断）如实标**悬置**。

== 每次改完（先判改动性质，再决定验到什么程度）

* **先判性质**：改动会被未知项目加载、或会改变别人行为（规范、提示词、随规范分发的工具）→ 深度验证；明确的代码类改动 → 机械判据判过不过；确未改变内容的操作 → 用该操作自身的判据核对，不重跑全量。
* **不得互串**：代码类改动不得升级成三视角全局核对；规范类改动**不得只跑机械校验就收尾**。
* **规范类改动**：动手前须有基线；改完须跑机械校验 + 由**同一 Agent 的干净上下文**做三视角复核（完整性、有效性与认知质量、接纳面），结论按**三态台账**留证，概念项只到"未发现问题"、查不出标悬置。
* **代码类改动**：暴露问题的既有用例**不得为迁就改动而改判**；新老用例须同时成立。

* 评审与干净复核 → `specs/general/review.adoc`
