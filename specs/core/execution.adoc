= 执行原则（必加载层）

以下规范适用于所有任务执行，为必加载层，每次工作都须遵循。涉及具体主题时再按 AGENTS.adoc 的加载调度规则加载对应分类规范。

== 指令执行

* 指令执行：严格执行用户指令——需求有歧义时先提问澄清，不自行假设后动手；用户说的每一句话、每一个字都是有效指令，不允许忽略、跳过或选择性执行任何一个字（仅明显打错字除外），执行时逐字对照用户输入，确认全部落实后方可结束；每次操作后必须验证是否达到预期（如用 diff/status 比对、运行检查等确认结果）

== 先规划后执行

* 先规划后执行：任何任务动手前必须先规划——明确目标与范围、拆解执行步骤、设计实现方案（复杂/有取舍的任务含备选方案与取舍评估），规划完成后再执行；规划文档须落到磁盘（如设计文档或临时规划文件），不得仅存于上下文（避免超出上下文限制）；规划文档是否需持久化按任务类型判断——项目代码开发等需提交的任务，规划按设计文档持久化（见文档规范「设计文档」条目），后续随代码一并提交；一般任务规划写入 `tmp/` 文件夹临时文档（见下条「临时产物」），方案在代码注释或执行说明中体现；执行中偏离规划时先调整规划再继续，不得边做边定方案

== 命令执行

* 命令执行：能用项目自身提供的构建/运行脚本（如 `mvnw.cmd`、`mvnw`、`npm`、`pnpm`、`gradlew` 等）直接运行的命令优先用其直接执行，不套用更重的 shell——避免不必要的环境差异与转义问题（如 powershell 会对参数做额外解析）；确需目标 shell 特性（如复杂对象处理、过滤管道等）时才使用对应 shell

== 文档先行、文档与代码对应

* 文档先行、文档与代码对应：修改源码前必须先阅读相关文档（设计文档、测试文档、规范文档等），了解现状与既有约定，避免盲目改码；若该功能/改动尚无对应文档，则先补充添加文档再改代码；全局要求先改文档再改代码（文档驱动），代码与文档必须能互相对应、可互相定位关联（如功能对应设计文档、测试用例对应测试文档与编号），改代码时同步改文档、改文档时同步改代码，不得只改一处、留一处不同步

== 范围控制

* 范围控制：原则上不得范围蔓延，执行范围以规划的目标与范围为界——不擅自扩大改动范围（要求 A 时不额外改 B；关联改动先说明并征得同意；回退自作主张的改动时只回退、不加新内容）；执行过程中发现前期规划有问题或需补充的新内容：先记录下来（如临时文档、问题清单），不中断当前任务，待当前任务完成后再考虑修复或补充，完成后须提醒用户；默认不中断任务，除非过程中发现严重偏移目标（需大幅变更方案、明显超出原任务边界）——严重偏移目标时：当前任务完成后直接停止，无需先向用户确认，由用户人工确认后再决定是否继续或调整

== 任务编排与上下文管理

* 任务编排与上下文管理：互不影响的任务拆分并发执行，互相影响或需共享状态的必须串行，多任务先易后难；大范围检查及多步骤任务（调研、设计、编码、写用例、用例验证、文档等）的子 agent 拆分协作细节见 agent 协作规范（specs/general/collab.adoc）；大规模检查可能上下文不足时，进度与结果写入 `tmp/` 文件夹临时文档（见下条「临时产物」）：不保留、只做问题记录、不写备注（备注一律写入代码注释等持久文档），问题解决后可在其中更新解决状态；整个项目级别内容按子模块拆分、分步分批处理；后续任务不依赖当前上下文即可释放（清除历史上下文或开新会话）

== 任务放弃与中断

* 任务放弃与中断：任务在执行中被中断、且用户后续未明确提及继续该任务时，该任务视为放弃——用户改变主意或另起新任务时同理；放弃的判断以用户最新指令为准，不自行推断延续；放弃后不再做任何事（含还原/撤销已实施改动），由用户人工处理；已放弃/中断的任务不再考虑，不得再次追问确认是否继续、不得重新提起或自行延续（用户主动再次发起该任务时除外）

== 按操作加载规范（懒加载）

* 按操作加载规范：规范按分类拆分到 `specs/` 下（按需懒加载，避免常驻加载不需要的规范、节省上下文）；执行涉及某主题的操作前，须先按 AGENTS.adoc 加载调度规则加载该主题对应的规范文件确认规则，不得凭记忆或仅凭常驻的 AGENTS.adoc 猜测执行——如文件移动/重命名前先加载 git 规范（含"文件移动必须 git mv"规则）、写 Java 前先加载 java 规范、跑测试/补测试前先加载测试规范、构建/依赖调整前先加载对应构建工具规范；加载的规范以其当前内容为准，不得因「规范文件不在常驻上下文」而跳过其要求

== 临时产物

* 临时产物（权威定义）：进度记录、日志文件、扫描中间结果、临时规划文件、结果报告等临时产物，统一写入项目根目录 `tmp/` 文件夹（不存在则新建），按任务/文件类型等维度在 `tmp/` 下分类建子文件夹存放，不混在一起；临时产物不保留、不提交；**持久文档（代码注释、设计文档、测试文档、README 等）不得引用临时产物及其中的内容**（如问题编号、问题描述等——临时产物会删除，其内容无出处可追溯）；清理 `tmp/` 下临时产物属规范要求的常规收尾动作，通过 `script/clean-tmp.py` 执行（本仓库提供的清理脚本，以当前工作目录为项目根，内置路径穿越防护仅限 `tmp/` 下，其他删除仍按常规确认）；该脚本**无需下载到目标项目**，在目标项目根目录以本地文件或远程加载方式执行——Linux/macOS 用 `curl -s <script-url> | python3 -`（stdin 执行），Windows 用 `Invoke-WebRequest` 下载到本地再执行（详见 script/clean-tmp.py 头部用法）；任务报告等大范围任务结果须生成文件（如 `tmp/check-result-*.md`），内容含检查范围、问题清单（分级编号）与处理状态，按临时产物处理（不保留、不提交）
