= 规范管理（必加载层）

以下规范适用于本规范集合本身的维护。为必加载层，每次工作都须遵循。

== 规范分层

* 规范分层：规范只收录通用规则；局部决策/已知取舍写在对应代码注释，不写入全局规范
* 分层组织：规范按"必加载层 / 通用层 / 技术栈层 / 平台层"分层存储于 `specs/` 下（分层定义与加载调度见 AGENTS.adoc「分类与懒加载」）；跨语言通用规则写入 link:../general/coding.adoc[]，某语言/技术栈专属规则写入 `specs/stack/` 对应文件——通用规则不重复收录进各栈，各栈只收录该栈专属规则

== 规范组织

* 规范组织：规范须归纳总结、分组分类组织（按主题分组，如执行原则/文档/代码质量/code review/规范管理/任务与 git），不得遇到情况就零散追加、平铺堆砌——新增或调整规范时先检查是否与现有条目重复、可归纳合并，冗余内容须合并去重；条目按主题归类到对应分组，不重复表述
* 规范引用文件必须真实存在：规范文件中引用的 `specs/...` 文件地址必须是**当前真实存在、可追溯**的文件；**不得引用已删除/不存在的旧文件**，也不得添加指向旧文件的历史来源注记（旧文件可能已无法追溯，且会让引用悬空）。引用一律直接指向当前有效的文件地址（迁移/拆分后直接引用新地址），不保留无用的历史来源声明

== 规范调整

* 规范调整：除非明确要求删除某条规范，否则调整规范时必须保证规范完整性（不因调整丢失规则）。「完整性校验」与「定义未执行核验」相互独立、触发条件不同：
  ** 完整性校验（**每次改完规范后必做**）：核对本次调整未丢失规则、无误删/误改/遗漏。①自动运行 `script/check-specs.py`（及测试 `script/check_specs_test.py`）做机械校验（引用存在、文档链接格式、技术栈一致、私有约定、规范要点防线）——机械校验**每次全量扫描所有规范文件**：它纯本地、毫秒级、不消耗外部成本，且天然交叉敏感（删除/改动某文件可能让其余未变更文件的 link 悬空或技术栈登记失配，须全量才能发现），故**不得**改为"只查有变更的文件"；②对内容实质性调整，在隔离上下文开启干净子 agent 核对本次调整要点是否全保留、有无误删/误改/遗漏——语义核验**范围限定为本次变更文件及其引用/被引用的受影响文件**，其成本只随本次变更范围增长、不随规范文件总量增长。完整性校验不依赖用户提示、不得以"用户未要求/改动很小/项目简单"为由跳过（仅用户明确豁免时除外）
  ** 定义未执行核验（**单独手动执行**）：评估"规范里定义的每条规则是否真正有效、是否被实际遵守、有无可执行抓手"，而非仅存在于文档——规范里写了某条"必须/不得"不代表它必然被遵守，这类"定义未执行"的风险不会随每次调整暴露，故不随每次调整自动运行；由用户决定何时整体执行（如运行 `script/check-effective.py`），并可指定核验范围
