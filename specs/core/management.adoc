= 规范管理（必加载层）

以下规范适用于本规范集合本身的维护。为必加载层，每次工作都须遵循。

== 规范分层

* 规范分层：规范只收录通用规则；局部决策/已知取舍写在对应代码注释，不写入全局规范
* 分层组织：规范按"必加载层 / 通用层 / 技术栈层 / 平台层"分层存储于 `specs/` 下，跨语言通用规则写入 `specs/general/coding.adoc`，某语言/技术栈专属规则写入 `specs/stack/` 对应文件——通用规则不重复收录进各栈，各栈只收录该栈专属规则

== 规范组织

* 规范组织：规范须归纳总结、分组分类组织（按主题分组，如执行原则/文档/代码质量/code review/规范管理/任务与 git），不得遇到情况就零散追加、平铺堆砌——新增或调整规范时先检查是否与现有条目重复、可归纳合并，冗余内容须合并去重；条目按主题归类到对应分组，不重复表述

== 规范调整

* 规范调整：除非明确要求删除某条规范，否则调整规范时必须保证规范完整性（不因调整丢失规则）；调整完成后须验证（如核对要点是否全保留），验证需在隔离的上下文（如干净的子 agent）中进行，避免本次调整的上下文影响验证结果
