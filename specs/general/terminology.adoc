= 数据字典规范（通用层）

适用于**任何语言、任何项目、任何落点**：把"名称这个代号到底指什么"从分散的上下文里收进**定义**，并让定义**按作用域归档**——按需取用、不随每次加载一起膨胀。术语的统一叫法见 `specs/general/encoding.adoc`「术语统一」；同一信息只写一处的归属判据见 `specs/general/doc-design.adoc`「信息归属」；引用与出处的真实性见 `specs/general/source.adoc`。

依据：ISO 1087（术语工作与术语科学——词汇，其条目元素次序为 entry number / preferred term(s) / admitted term(s) / abbreviated form(s) / definition / example(s) / note(s)）、ISO 704（术语工作的原则与方法）、ISO 10241-1（标准中的术语条目——表述要求）；W3C SKOS Reference（`skos:definition` 与 `skos:scopeNote` 是**两个**属性、`ConceptScheme` 承载"一套术语"）；行业全局词汇表的先例为 ISO/IEC/IEEE 24765。

== 本文件的字典（本文件使用的名称，定义写在本文开头）

本文件自己就用这套形态：用到的名称，解码表就在**本文件开头**——读者一进文件即拿到，不必翻到末尾、也不必另开一处（这是「当前文档」档的示范落点）。

[[term-data-dictionary]]
**数据字典**：一份"名称 → 定义"的对应表；同义词为"术语表/词汇表"。

[[term-scope]]
**作用域**：一条定义**成立的范围**（对任意项目成立 / 只对本项目成立 / 只对本模块成立 / 只对本文档成立…）；它决定该定义**归档到哪一处**。

[[term-definition]]
**定义**：这个名称**是什么**（概念本身的表述），**不含**"什么时候用"。

[[term-scope-note]]
**使用说明**：这个名称**什么时候适用、什么时候不适用、易误用点**（属"怎么用"，与定义**分列**）。

[[term-home]]
**落点**：承载某条定义的**唯一位置**。

[[term-citation]]
**引用**：别处提到该名称时**只写名称**、必要时给一行指向落点的说明。

== 数据字典

* **只引名称、不引定义（L1）**：内容里提到一个已入字典的名称时，**只写名称**（必要时给指向定义的**一行引用**，如"（定义见 X）"），**不得**在该处再复述一遍定义。**理由**：名称是**检索键**，定义只有**一处**——同一名称在 N 处各带一份定义，就是 N 份会各自漂移的第二真源（与 `specs/general/doc-design.adoc`「信息归属」、`specs/general/review.adoc`「精炼性」同向）。**判定标准（任一命中即违规）**：① 同一名称的定义在正文里重复出现两处及以上；② 引用处写明"定义见某处"之后又跟了一段解释性复述；③ 同一概念在不同文件里用了不同名称（名称本身就不唯一）。
* **作用域决定落点、每档只一处（L1）**：一个名称的定义**按它的作用域**写进**唯一落点**；定义只写在这一处，别处只引名称。**每档只一处**：同一作用域不得出现第二个落点。**本文件的字典写在本文开头**——文档自身使用的名称，字典就放在该文档开头（读者一进文件即拿到解码表，不必翻到末尾或另开一处）。落点分档（**按实际成立范围判定，不按文件类型**；判据即表末一列，**抽取**掉本项目的专有名词后拿去核对）：

| 作用域（定义在什么范围内成立） | 唯一落点 | 判据（拿它去核对） |
| --- | --- | --- |
| 全局（对任意项目/语言成立） | 规则所在的 `specs/**` 文件正文 | 抽掉本项目的专有名词后该定义仍成立 |
| 项目全局（本项目内成立） | 项目自身规范入口（通常为根 `AGENTS.adoc`） | 只在本项目内成立，换个项目即不成立 |
| 模块/功能（跨类的同一件事） | 该模块的设计文档 | 只被某模块/功能内的多个类或组件共用 |
| 类/接口（单类内部） | 该类/接口的代码文档注释 | 只有该类的使用者需要解码（见 `specs/general/doc.adoc`「注释与文档」） |
| **当前文档** | **该文档自己的开头** | 只有读这份文档的人需要解码 |
| 图书馆（依据/证据，规则背后的出处） | 依据图书馆入口的主题登记表 + 短名主题文件 | 是"为什么这样定"的逐字依据，不是名称本身（见下条） |
| 提示词/模板产物 | 该产物**所在文件**（片段即片段文件） | 会被复制到未知项目执行，落点须随产物一起走 |

* **一行一个名称（L1）**：本文件的字典与任何字典条目**一行只写一个名称**——名称起行、**每个名称独占一段**，**不得**把多个名称挤在同一行、同一段里。**判定标准（任一命中即违规）**：① 同一行/同一段里出现两个及以上名称的**定义正文**；② 想增删或引用其中一个名称的定义时**必须碰到同一行/同一段里的其他名称**（改一条要动一整段，即这条没独立成行）；③ 一行里出现"定义与使用说明"之外的**第二个名称的正文**（两个名称**互相引用**不违规，违规的是把两份定义挤在一行）。**理由**：一份"名称 → 定义"的表里，**一行就是一个可寻址的行**——挤在一起时增删与引用都得动整行、diff 里一改一串，读者也无法按名称逐行核对；这与「只引名称」同向——名称是**检索键**，键得能**单独**被看到。**示范**：本节上面「本文件的字典」即一行一个名称。
* **条目形态照标准（L2）**：每条按 ISO 1087 的元素次序写——① 名称（首选名称；有别名/缩写时紧随其后并标明哪个是**首选**）；② **定义**（这是什么；**不写**"怎么用"）；③ **使用说明/边界**（什么时候适用、什么时候不适用、易误用点）；④（按需要）示例与注。**"定义"与"使用说明"必须分列**（SKOS 的 `skos:definition` 与 `skos:scopeNote` 是**两个属性**）——把"什么时候用"混进"这是什么"，会让定义随用法漂移。
* **反膨胀（L1）**：字典**按作用域分档落点就是为防膨胀**。故**不得**把只在某文件/某模块成立的名称收进更高档的落点（"反正顺手"正是膨胀的入口）；上游落点**不得**收录只在某一处成立的名称。**判定标准（任一命中即违规）**：① 全局/项目全局落点里出现"只有某模块/某文档才用得到"的名称；② 同一作用域的内容被拆到多处（同一档出现第二个落点）；③ 上游落点因收录了下游名称而**单独显著变大**（判据是"这一条放这里，谁会读到它"——读不到它的人也在为它付上下文，即放错档）。单个字典文件的体量提醒口径与项目对规范文件的软阈值一致（该阈值属**维护方自己**的判据化取舍，按各项目自身规范执行），本规范不另设第二套阈值。
* **新增与调整内容时都须判定（L1）**：**每次**新增或调整内容（含新增规则、改措辞、重构、迁移落点）时，都须对该内容**走一遍**该判定：① 有没有已入字典的名称（必须有则引用、不重复定义）；② 本次**引入的新名称**该归哪一档（按上表判据）、该档的唯一落点在哪；③ 本次**调整掉的名称**须同步其定义（改名称即改定义处的名称，删名称即删定义，不得留孤立的定义或孤立的引用）。**判定标准（任一命中即违规）**：① 新增内容引入了新名称却没有任何一处给出定义；② 新名称只写在引用处、没有归入任何一档；③ 调整/删除名称后定义处与引用处不再一致（改了 A 处、B 处仍指旧名）。
* **图书馆等"不在默认引用面内"的落点按其自身规则走（L2）**：依据图书馆**没有体量上限**，其定位靠**依据名**与入口主题登记表、文件名只取短名（不承担定位）——故图书馆里的名称**登记在入口的主题表里、定义放短名主题文件**、**不复制规则本体**。公共内容引用图书馆只给"依据名 + 判据"、**不给可点开的路径**（图书馆不在默认引用面内，给路径即死链）；判据自身在 `specs/general/source.adoc`「外部引用」。
* **与既有规范的关系（引用不复制）**：本条**不改写**既有条目，只补上"定义按作用域归档、只引名称"这一层——`specs/general/encoding.adoc`「术语统一」管**叫法唯一**，`specs/general/doc-design.adoc`「信息归属」管**同一信息只写一处**，本条管**名称的定义归档在哪一处**。三者同向、互不替代。
