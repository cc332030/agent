= 通用编码规范·界面（通用层，跨语言）

本文件是通用编码规范的一族之一（**按主题拆分**，其余见同目录 `coding.adoc`、`coding-shape.adoc`、`coding-objects.adoc`、`coding-runtime.adoc`、`coding-source.adoc`、`coding-file-role.adoc`）：界面与样式、界面的性能、同一件事只有一个来源；形状与交互取值见 `specs/general/ui.adoc`。

== 界面与样式（任何语言、任何端）

**任何语言**都适用：只要产出**给人看的界面**（网页与前端应用、桌面窗口、移动端页面、服务端渲染的模板、终端 UI 等），无论用什么语言与 UI 技术写。本集合不列框架名与库名（各生态可选者众、会随时间换代），只给判据与判定标准。

**识别判据（先认是不是界面）**：由**布局与外观**承载信息、需要人**看得懂、点得动**的产出即本节所指的界面。**边界**：只输出数据的接口、日志与命令行的一段输出不属本节；纯样式文件（主题、设计令牌）属界面的一部分。

**为什么界面排在最前**：本节这一档是**唯一没有可执行判据**的一类——外观与观感没有测试，同一形态各写一套后跑什么都不报错，只有人看出来；故它先按本节与下节「同一件事只有一个来源」处置，其余各档见下节。

* **优先取现成 UI 框架与开源样式方案，不从零写一套（L1）**：**新写**界面时，先取**项目已引入**的 UI 组件库/样式方案，其次取**该生态通用**的开源方案（组件库、设计系统、无障碍与主题方案）；**不得**在没有先例、也没有取舍理由时，从零手写一套组件与样式。**判定标准（任一命中即违规）**：① 新增界面里出现与现成框架成员**同形**的基础件（按钮、输入框、弹窗、表单、表格、分页、提示条等），而项目或该生态已有现成方案；② 以「自己写更可控」「AI 写得快」「样式更贴合」为由从零手写，而未落到下面「从零写的唯一正当情形」。
* **同一形态只许一个样式来源（L1）**：**视觉形态相同**的元素——业务上本就是**同一套东西**（同一种按钮、同一种卡片、同一种表单控件）——在项目内**只许有唯一一处样式与结构来源**（框架组件、公共组件、公共样式类之一），其余位置取用它、不得各写一份。**判定标准（任一命中即违规）**：① 同一形态在两个及以上位置各写一套样式或结构（复制样式、就地重写同名组件）；② 同一形态在项目内并存两种外观（大小、圆角、间距、颜色、交互态不一致），而形态本身相同；③ 以「这块页面特殊」为由就地改框架外观，而未把差异收回一处。
* **框架默认外观与主题只在一处改（L2）**：对框架的默认外观做**全局**调整（主题变量、设计令牌、框架样式的覆盖层）须落在**唯一一处**；**不得**在每个使用点逐个改框架内部结构或重复覆盖同一属性。**判定标准**：同一视觉属性在两个及以上使用点各自覆盖，而无统一落点。
* **`!important` 是最后一步，不是常规手段（L1）**：它是**优先级**的手段，本身不表达任何来源关系——用它压下的不是某一条样式，而是**这处选择器与其余所有选择器的关系**（谁先谁后不再有意义），于是同一项目里只能靠**逐处再加更强的 `!important`** 去覆盖，改一处必漏一处，直到没人说得清哪种写法会生效。故取用的**次序是**：① **提高选择器本身的优先级**（层次与形态已由结构表达时，改在唯一落点的选择器上）；② **收进来源那一处**（公共组件/公共样式类/主题变量，见本节上两条）；③ **第三方库或内联样式这类取不到来源时**，**收在一处覆盖层**（框架样式覆盖层或全局样式落点，只此一处）并**写明理由**；任何一处都走不通、且不写就达不到目标时，`!important` **只落在那一处**、**须写明理由**。**判定标准（任一命中即违规）**：① 同一处（同一样式落点、同一段样式内的相邻规则）出现**两处及以上** `!important`，或为覆盖一处 `!important` 又写了一个——**以 `!important` 覆盖 `!important` 即违规**，无论分几处写作；② **判定只在写它的那处算、不看调用点有多少**——同一个 `!important` 被二十个页面取用**不算频繁**（它是唯一来源），而在二十处各自写一个、或同一段里连写多个，即使各自都"只写了一次"也算；③ 新写的样式里出现 `!important`，却没有上文第 ③ 步那条**收在一处的覆盖层与理由**——以「临时压一下」「框架改不动」为由就地加，即便只加一处也不算。**边界**：`!important` 落在项目自己写的覆盖层里属①的正确形态，本条的靶心是它**散在使用点、或在同一处层层加码**；存量按存量边界随动迁移，不发动全库清理。
* **无障碍与语义属性取框架所给（L2）**：现成方案的**语义结构、键盘可达、焦点与读屏属性**按其所给使用，**不得**为局部外观把它剥掉（如把按钮换成可点的容器、去掉标签与焦点样式）；需要的差异走框架提供的扩展点。
* **从零写的唯一正当情形：与既有界面对齐（L1）**：**可以**从零写，但**只在**下列情形之一成立时：① 项目与该生态都取不到满足需求的现成方案（判据取「**本机、目标版本、目标形态上实际试过取不到**」，不凭印象，并写明试了什么、卡在哪）；② **被测对象就是既有的那份界面**——**逆向/复刻**（还原既有页面或产品）或按固定设计稿实现，外观须与参照一致，此时**以对齐参照为准**（按设计令牌与结构对齐，不引入与参照冲突的框架外观）；③ 项目自身规范明确要求。**判定标准（任一命中即违规）**：① 以上三种情形都不成立，仍从零手写；② 以「逆向/复刻」为由把**同一项目的其余页面**也一并手写（该情形**只覆盖需要对齐的那个范围**）；③ 把「取不到」说成结论而未实际试过。
* **从零写也须收在一处、只此一份（L1）**：**无论**用框架还是从零写，**同一形态的实现只许存在一处**——基础件走公共组件/公共样式的唯一落点，页面只组装、不各写一套；**跨端**（同一产品的网页与桌面/移动端）复用同一份设计令牌与形态定义，不以「端不同」为由各造一套。**判定标准（任一命中即违规）**：① 从零手写的同一形态在第二个位置被复制或重写；② 以「这次先就地写」为由留下第二套基础件。
* **存量边界（L1）**：本条**只管新增界面与本次改到的部分**，**不发动全库改造**（不批量替换既有组件、不为统一外观重写既有页面）（随动迁移，见 `specs/core/execution.adoc`）。
* **内容多的页面按分组组织，不把各分组隔成互不相关的块（L1）**：同一个页面里的内容多到需要**分组**时（设置页、配置页一类），各分组**同处一页**、由**分组标题与分组内的顺序**组织，**不得**把分组拆成互相隔离的块（并排的独立卡片/面板、各分组自带边框与背景、分组之间空出整块间隔、二级标签页各藏一部分）——分组之间本可对比与跳读的关系，被这些边界切断后读的人只能逐块翻过去、也读不出整页有哪些设置。分组的内聚与顺序取**使用流程**（被依赖的在前、同一件事的归一组），不取字母序或改动追加序。**判定标准（任一命中即违规）**：① 新增或改到的页面里，分组以上述任一隔离形态呈现，而非分组标题下的顺序内容；② 页面出现二级标签页/折叠区，仅为把分组彼此隔开；③ 分组与其下条目的关系只由间距与边框表达，没有分组的标题（或读屏可读的分组名）。
* **分组须能被检索到（L1）**：页面做过分组、或单页条目到**扫读不现实**的量（判据取形态：要逐条读一遍才能找到目标，而非一眼扫过即可）时，须提供**页面内检索**——**检索面向的是页面上起名可见的各项（分组名与条目名），命中即可一步定位到该项**（所在分组随之可见），**不按关键词猜内容**。**判定标准（任一命中即违规）**：① 页面已分组或条目量已到上述量级，而没有页面内检索入口；② 检索要用户先逐组展开或逐组切过去才能看到结果——检索没有落到全页那一层，等于让用户先自己分组再找。
* 依据（标准名/编号）：ISO/IEC 25010（可维护性与一致性：同一形态两份来源即改一处漏一处）、ISO/IEC/IEEE 29148（判定须单一、无歧义、可验证）、ISO 9241-110（符合预期与可控：同一形态外观一致，用户才不必重新辨认）、W3C WCAG（语义结构与键盘可达属无障碍的基线取向）、ISO 9241-112（信息呈现：按使用者的任务与预期组织信息、呈现须自洽且可预期）、ISO 9241-143（表单：分组须有序且各组有可辨的标题）、WCAG 2.2 SC 3.2.3/3.2.6（同一产品内的导航与帮助位置保持一致）、Nielsen Norman Group 关于设置页分组与页内检索（业界实践、非标准）；**「框架优先、同一形态只留一处样式来源、从零写的唯一正当情形＝对齐既有界面 / 实际取不到、`!important` 只作最后一步且须收在一处、内容多的页面同处一页按分组组织而不隔离各分组、分组与超量条目须提供页面内检索」是本集合的判据化取舍**——各组件库与设计系统的官方文档只给**机制**（主题变量、扩展点、设计令牌），**未**规定「该不该从零写」「哪些形态必须来自框架」，也**未**把 `!important` 列为禁忌（浏览器各家规范只定**机制**：它抬高声明的优先级、并让一条声明压过其余所有选择器）。

=== 界面的性能（任何语言、任何端）

**识别判据**：由**布局与外观**承载信息、需要人**看得懂、点得动**的产出即本节的界面，**不限语言与端**（Java、Python 一类写的桌面/内嵌界面同样在内）——识别判据与 `specs/general/coding-ui.adoc`「界面与样式」同一份、不另定。

**界面的性能不止「数据多不多」**：界面**能用**（打开就看到、点得动）与**好用**是两件事，而**开发期看不出来**——机器快、数据少、操作次数少时，界面并不慢，与后端接口一样，**只有跑到真实的规模与机器上，才知道哪一处慢**（第一轮的教训正是：**数据量大了才发现卡**，而“拖起来卡”是同一类失效的另一处）。故本节不取单一情形（**「一万行的表格拖动调整大小」只是这一类里的一个点，不以此为限**），而按**界面会慢的全部维度**分成六档，每档只给可核对的形态：

* **规模**：数据与选项长起来之后，打开、滚动、筛选还快不快（取数边界、逐项各取一次、全量类操作的生效范围）。
* **交互与绘制**：一次拖动、缩放、滚动、输入、动画里，**跟着动的那一步**是不是每帧都在做重活（形态五六）。
* **常驻成本**：不用它的时候它还在不在花资源（轮询、定时器、监听、订阅、未释放的句柄——形态七）。
* **起步**：首屏与进入一个页面要多久才**可操作**，而不是"多久才画出来"（形态八）。
* **时效**：操作进去到看得见反馈、到能继续操作的**延迟**（形态九）。
* **降级**：慢或失败的时候有没有出路（加载态可取消、失败可重试、慢不拖垮其余——形态十）。

**为什么按维度列而不按场景列**：按场景列（"大表格拖动怎么优化""图表卡怎么优化"）只能覆盖写进清单的那几个场景，**没写进去的一律照旧**；按维度列，任何一处界面都落在某一档里，判据不会因为"这一种没人提过"而失效（「举例不是面」的方法论见 `specs/general/planning.adoc`「举例不是面」）。

* **形态一（规模）：列表与表格按需取数，不把整份集合一次画出来（L1）**：可增长的集合（表格、列表、树、下拉、时间线）在**打开与切换时**只取与只渲染当前需要的量——取数侧走分页/按需加载/游标，渲染侧走虚拟滚动、分页、折叠之一；**不得**把整份集合一次取回、一次渲染成 DOM/控件/行。**判定标准（任一命中即违规）**：① 界面里出现「把集合整个取回来再交给表格/列表」的取数形态；② 渲染侧一次性生成与数据量同阶的节点或控件；③ 以「现在数据没那么多」为由不设取数边界——**判据取形态，不取当前数据量**。
* **形态二（规模）：同一次展示里不逐项各取一次（L1）**：界面里逐行/逐项拼装内容时，**不得每项各发起一次取数或计算**（选中项、名称、状态、格式化结果这类**同一次展示用得上**的东西，一次性取回或在一次渲染内批量取得）；**判定标准（任一命中即违规）**：① 循环/渲染回调里出现取数调用；② 同一份输入在渲染路径上被反复重算而未共享结果。
* **形态三（规模）：只在会用到时才画、才取（L1）**：重区块（图表、编辑器、地图、预览器）与首屏用不到的区块**按需加载**（用户走到那里才加载代码与数据）；**判定标准**：入口或共享布局的静态引用图里能走到该重区块即违规（前端的具体载体见 `specs/stack/web.adoc`「分包与按需加载」）。
* **形态四（规模）：只加载可视区时，全量类操作要说清对哪一份生效（L1）**：按需取数与虚拟滚动只解决**画**与**取**，**全量聚合类操作**（总数统计、跨页全选、导出、全局搜索、批量操作）仍要有落点——① 对**全量**生效的（总数、导出、全局搜索、跨页选中）走**服务端/数据源侧**的聚合与筛选接口，**不得**在前端逐页拉取扫全表；② 只对**已加载范围**生效的，须在**界面上显式标示该范围**（「已选已加载的 N 条／全选全部 M 条」这类可点选的区分），**不得**让用户以为已作用于全量。**数据不在前端不等于不存在**——数据在数据源侧（服务端、库、磁盘）就有，差的只是**由谁来聚合**：前端只加载可视区，聚合交给有全量数据的那一侧。**判定标准（任一命中即违规）**：① 全量类操作以「循环调用分页接口直到最后一页」的方式在前端凑出全量；② 全选、计数、导出的结果**只覆盖已加载范围**而界面未标示该范围；③ 以「用了虚拟列表所以不卡了」为由，不给全量类操作留落点。
* **形态五（交互与绘制）：跟着一次操作动的那一步，把重活挪出这个动作（L1）**：拖动、缩放、滚动、输入、动画**跟着指针/滚轮/按键连续变化**时，每一次变化只允许做**改一个已算好的值**这类轻动作；**度量、重新取数、全量重排、重算布局**这类重活须挪出这个动作——按驱动方式取其一：① **只在动作结束时做一次**（松手、滚动停、失焦）；② **在帧内按需做并复用结果**（测量一次缓存、下一次直接取）；③ **交给渲染管线自己的帧**（让框架/引擎批量绘制，不逐次触发同步布局）。**判据取形态、不取"卡不卡"**：开发机上不卡不算通过——机器快、数据少时这一处照样无感。**判定标准（任一命中即违规）**：① 连续事件（拖动、缩放、滚动、输入）的回调里出现**读布局再写样式**的交替（取元素尺寸/位置之后立刻改尺寸/位置，迫使同步重排）；② 该回调里发起**取数**或**全量重算**（逐行重新格式化、重新排序整份集合、重新生成整张图）；③ 以「就几行数据」「机器上挺顺」为由不做区分。
* **形态六（交互与绘制）：一次变化只重画该重画的那一块（L1）**：一份状态变化只驱动**用到它的那一块**重画，**不得**让整页/整个列表重建；动画与动效只改**不会引起重排的属性**（能改透明度/变换，就不逐个改尺寸与位置），且**须能在系统要求减少动效时降级**。**判定标准（任一命中即违规）**：① 改一个单元格/一行值，触发整表重建（选中态丢失、滚动位置跳动，或引用整体被替换）；② 动画逐帧改尺寸/位置，把整棵子树拖进重排；③ 系统声明了减少动效而界面照旧播放。
* **形态七（常驻成本）：不看不用的东西不花资源（L1）**：界面不处于使用态时**不得**继续花资源——不可见的页面不轮询、不刷新、不监听、不订阅；定时器与轮询**只在有观察者时存在**（切走、隐藏、关闭即停或降到低频，并与数据陈旧度的展示对齐）；监听、订阅、句柄、后台任务在退出该页面/组件时**释放**。**判定标准（任一命中即违规）**：① 页面已切走或窗口隐藏，仍按原频率轮询/拉取/重绘；② 定时器、事件监听、订阅在组件销毁后仍在跑（重复进入即累积一份）；③ 以「数据要新」为由让不可见的页面常驻高频轮询，而界面上并无"多久前"的标识。
* **形态八（起步）：首屏与进入可用的时间以「可操作」为准（L1）**：首屏与进入一个页面，只**先做能让人开始操作的那一部分**——骨架/占位先出、主区可交互，其余区块随用随取；**不得**让整页的呈现等待最慢的那一处（大图、图表、重列表、次要统计）。**判据是可操作时刻，不是"画面出现时刻"**：先画一堆不能点、不能滚的占位不算达到要求。**判定标准（任一命中即违规）**：① 首屏的渲染被一个非首屏必需的请求/重区块阻塞（要等它回来才渲染任何东西）；② 用整页遮罩/全屏 loading 覆盖本可先操作的部分；③ 以「反正一起回来」为由把多个互不依赖的请求串成一个再渲染。
* **形态九（时效）：操作进去要有即时的可视反馈，慢的那一步不得锁死界面（L1）**：任何操作触发后，界面须在**当次交互内**给出可视反馈（按下态、行内忙态、进度），**不得**等结果回来才动；超出即时的一步须**可取消**（或至少不阻塞其余区域继续操作），并把耗时的那一段与随后的呈现分开（先回执、再出结果）。**判定标准（任一命中即违规）**：① 点击后到结果回来之前界面毫无变化、且整块区域不可操作；② 长任务没有取消/离开的出路；③ 输入类交互（筛选、搜索、调整）采用「每敲一下都发一次请求并丢弃前一次响应」的形态而**不**做取消，**且**旧响应回来会覆盖新结果（乱序覆盖）。
* **形态十（降级与可感知）：慢或失败要有出路，且要能看出慢在哪（L1）**：慢/失败时给出**可操作的出路**（可重试、可取消、可降级到不含该区块的形态），并**标明正在等什么、等了多久**（与成功、空、加载、错误四态成套的判据见 `specs/general/ui.adoc`「组件的通用形态」与 `specs/general/feedback.adoc`）；一处慢**不得**拖垮其余区域（互相独立的区块各自出各自的状态）。**判定标准（任一命中即违规）**：① 一处请求失败即整页不可用，而其余区块本可正常显示；② 长时间等待没有进度/已用时，用户无法判断是还在跑还是卡了；③ 缓存与本地的数据没有来源与时间标识（这属 `specs/general/coding-runtime.adoc`「缓存（统一管理、先缓存后在线）」的判据，本处只要求它在"慢"的场景里不缺位）。
* **什么时候要做性能结论（引用）**：本条只定**形态**；要不要为某处界面做带取样与离散度的性能结论，按 `specs/general/testing.adoc`「性能测试」的触发特征判（界面的数据量可增长、重区块、重计算、首屏与常用交互、**连续交互**已列入该处特征），本处不复述其判据。
* **存量边界（L1）**：本条**只管新增界面与本次改到的部分**，不发动全库改造（随动迁移，见 `specs/core/execution.adoc`）。
* 依据（标准名/编号）：ISO/IEC/IEEE 25010（性能效率是产品质量特性之一，须**可度量**且与**使用条件**绑定；时间行为与资源利用都是它的子特性——故"响应多久""常驻花多少"与"能跑多快"同属性能）、ISO 9241-110（对话的符合预期与可控：响应及时、等待有进度、用户不必等待重操作）、ISO/IEC/IEEE 29119-4（判据须可复现、可核对）、WCAG 2.2（2.3.3 动画可由用户关闭、2.2.2 可暂停/停止/隐藏的自动更新——支撑「减少动效须可降级」「常驻轮询须可停」）。**「按维度而不是按场景列」「判据取形态、不取当前数据量与当前机器」「跟着一次操作动的那一步把重活挪出动作」「常驻成本、起步的可操作时刻、时效与降级各立一条」是本集合的判据化取舍**——通行前端与桌面框架文档只给机制（分页、虚拟滚动、懒加载、批处理 DOM 写入、取消请求、Web Worker），**未**规定"界面性能该覆盖哪几档""哪些形态必须成立"。

=== 同一件事只有一个来源（不限界面，任何语言）

**界面只是这套判据的一层皮**：底层失效是**同一件事在项目里长出多份实现**，而后果按这件事有没有判据分出两档。

**两档后果（这就是"为什么先提界面"）**：① **没有判据的那一档＝只能靠人眼**——外观、观感、交互手感这类产出**没有可执行的测试**，同一形态各写一套后，改一处漏一处、页面之间长得不一样，**跑什么都没有声音**，只有人看出来；② **有判据的那一档＝不一致会自己冒出来**——功能、工具类、数据契约、配置这类产出一旦多份，**分支与参数只要有一点不同，结果就不同**：走错分支即报错、行为悄悄变、断言与快照对不上、编译或类型检查直接红，**能查出来**。故执行顺序是**先治没有判据的那一档（界面与样式，见上一节）**，再把同一套判据铺到有判据的那一档——**能查出来不等于会收敛**：没人替它做决定，底层仍按各自为政的方式各长一套。

**识别判据（先判这是不是"一件事"）**：**业务上同义**（做同一件事、产出同一份结果、回答同一个问题）的产出一律算同一件事——**同义取业务语义，不取代码相似度**：两处写法长得像但不是同一件事不算，写得完全不同但业务上同义（两个名字各叫一套、两处各判一遍同一个状态）仍算。**边界**：本条管**新写与本次改到的部分**；纯数据对象的多份副本按 `specs/general/coding-objects.adoc`「数据契约的载体」判，依赖与版本的唯一来源按 `specs/general/dependency.adoc` 判，名称本身（同一个东西叫法不一、定义被复述多份）按 `specs/general/terminology.adoc`「数据字典」判；**会被两处用到的取值**（路径、地址、清单、阈值、超时一类）按本文件「取值的唯一来源」判——那一节是本条里"同一个取值只有一处定义"那一支的**完整判据**（本条只管"代码各处各写一份"，取值散进**文档、注释、规则数据、清单**的那一半由它管）。名称那一支与它们同源：**一处定义、其余取用**；本条不重复要求。

* **同一件事只许一个来源（L1）**：业务上同义的能力**只许有唯一一处来源**——一个函数、一个工具方法、一个组件、一个数据契约、一处配置、一处校验规则——其余位置**取用它**，不得各写一份。**判定标准（任一命中即违规）**：① 同一件事在第二个位置被复制或就地重写（复制一段函数体、各写一个同名同构的工具方法、各判一遍同一套校验、同一份配置抄两处）；② 同一件事并存两种写法或两份来源（一半用它、一半用另一份），而后来的读者无从知道该以哪份为准；③ 以「这块场景特殊」「这次先就地写」为由留下第二份。
* **第一处就该是能被取用的那一处（L1）**：**写第一次时就把来源放在别人取得到的位置**——同一件事在第二个位置用得上，它的来源须是**公共落点**（公共模块、工具类、公共组件、公共配置），页面/调用方只组装与取用；**不得**先就近写死、等第二个位置出现再挪一遍。**判定标准（任一命中即违规）**：① 明知会有第二个使用点，仍把它写成某处的私有实现，第二个位置只能复制或重写；② 以「还没人用到」「先跑通」为由把它留在使用点里。
* **实现已存在时不得另写一套（L1）**：项目或已引入的依赖**已有等价能力/先例**时**一律复用它**，不得另写一套（判据与动手前先查的口径见 `specs/general/coding.adoc`「既有实现与先例优先」与「不得以语言内置写法绕过既有能力」；本处**只把「另写一套」单列为违规形态，不另定查法**）。
* **定下唯一来源时一次收敛，不逐处漂移（L1）**：确定某件事有了唯一来源后，**改写其余位置去取用它**（改调用点、删副本），**不得**只加新的、把旧的留下——两套并存正是本条要治的形态。
* **判据与自证：重复要有办法自己冒出来（L1）**：同一件事的两份来源，**须有能自动发现它的手段**——按该产出所属的那一档取：有判据的一档（功能、工具类、契约、配置）用**测试/类型检查/静态检查**发现（两份走不同分支、参数不同、结果不一致时须报红）；没有判据的一档（外观与观感）用**可 diff 的快照或清单**兜住（同一形态的样式与结构只在一处，第二处出现即报红或由复核点出）。**判定标准（任一命中即违规）**：① 新增的同一件事没有任何能发现第二份的手段（既无测试也无校验），只靠"记得改两处"；② 以「人眼看得见」为由不给没有判据的那一档留可 diff 的落点。
* **例外（L2，须写清理由并说明用了哪一条）**：① **两侧分属无法共享的运行边界**（前后端、跨进程、客户端与服务端各一份）：**判据是契约不是代码**——两侧各实现可以，但**契约（字段、常量、校验规则）只有一处来源**，另一侧由它生成或对照核验，不得各写一份再靠人同步；② **被测对象就是参照物本身**（逆向/复刻、按固定设计稿实现，见上一节「从零写的唯一正当情形」）；③ **项目自身规范明确要求**（如某些分层约定要求两层各有一组对象）。
* **语言只定载体、不定判据，也不给某门语言开例外（L1）**：上面的识别判据与判定标准对**任何语言**一律成立（函数式、脚本、面向对象、前端、SQL 与模板语言同样在内）。**语言与生态只决定"这个唯一来源落在哪种载体上"**——静态方法、模块级函数、公共组件、共享常量与类型声明、项目自有的配置与校验定义之一，**判据不因语言变**。**判定标准（任一命中即违规）**：① 以"这门语言没有工具类""它不是面向对象的""动态语言就这样"为由，放过同一件事的第二个来源；② 把某门语言里"有两个现成入口"当成例外——那是取值口径，替代关系只在一处定；③ 只给一门语言写落点，就当成"本条只对那门语言成立"（栈层只**举例式**给载体，不是判据的适用面）。
* **存量边界（L1）**：本条**只管新写的与本次改到的部分**，**不发动全库改造**（不批量抽公共方法、不批量合并重复实现）（随动迁移，见 `specs/core/execution.adoc`）。
* 依据（标准名/编号）：ISO/IEC 25010（可维护性与一致性：同一件事两份来源即改一处漏一处）、ISO/IEC/IEEE 29148（判定须单一、无歧义、可验证）、ISO 10007（配置项与变更须有单一、受控的来源）、The Twelve-Factor App（同一份构建产物跨环境复用，不在各处分叉）、Martin Fowler《Refactoring》（重复代码的收敛前提是"第一次出现重复时才收敛、不预先抽取"）；**「先治没有判据的一档（界面），再把同一判据铺到有判据的一档（功能与工具类），并要求重复须有能自动发现它的手段」是本集合的判据化取舍**——通行材料只给"不要重复、抽取公共实现"的方向，**未**规定按"有没有可执行的判据"分档处置，也**未**把"能发现第二份的手段"列为规则。
