= 文档规范（通用层）

以下规范适用于文档、注释的通用编写原则，以及文档格式与编码。设计文档与测试设计文档的编写规范见 `specs/general/doc-design.adoc`；业务系统（从立项到上线的完整项目）的全生命周期文档组织见 `specs/general/doc-lifecycle.adoc`。某语言/技术栈的注释细节（如 Java 的 javadoc 规范）见 `specs/stack/` 对应文件。

== 注释与文档

* 注释与文档：不写死常量数值，用抽象描述或引用常量名；代码注释仅记录局部决策与要点（如初次设计、反复修改、有争议时的方案依据与设计思路：为什么这样做、为什么不做其他方案、接受了什么边界），不追求完整设计叙述——完整设计（功能怎么设计、用例考虑、兜底、适用范围等）统一写入设计文档（见 `specs/general/doc-design.adoc`），避免注释东一块西一块不完整；常规小改动不强制备注；总纲：一切有价值的内容都需记录——设计决策、方案取舍、约束边界、兼容性考量、测试设计、问题处理等，按内容性质写入合适的持久位置（设计文档、代码注释、README、规范文件等），不遗漏、不依赖记忆，临时产物除外（见执行原则「临时产物」条目）

== 文件格式与编码

* 文件格式与编码：除入口 AGENTS 文件外，其他文档优先使用 AsciiDoc（.adoc）格式；所有文件一律 UTF-8 编码，除非明确不是 UTF-8（如特定二进制格式、明确指定其他编码的文件）
* 文档代码块：md/adoc 文档中代码块的语言标识须与实际内容匹配——代码块虽不要求编译通过，但必须满足所标识语言的基本语法（避免 IDE 语法检查报红）；无法保证语法正确时标识为无格式类型（如 `text`），优先使用带格式的准确语言标识；伪代码/结构描述等非语法内容不得标注具体语言
* 文档问题：注释、README 等纯文档性缺陷，发现后直接修复，无需问询
