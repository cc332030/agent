= 验证规范（通用层）

以下规范适用于编译/运行验证、多步骤任务的分步验证等验证活动。某技术栈的编译/测试验证细节见 `specs/stack/` 对应文件（如 Maven 的 surefire 统计见 specs/stack/maven.adoc）。

== 编译/运行验证

* 验证执行：编译/运行验证耗时较长，不滥运行——仅当确需验证（用户明确要求，或存在仅能靠运行确认的行为）时才执行；多个待验证项能合并时合并为一次执行，不逐项独立验证；运行命令时优先将完整输出重定向到文件（如 `mvn ... > build.log 2>&1`、`npm run build > build.log 2>&1`，`2>&1` 为 cmd/bash 语法，PowerShell 下请用 `*>&1` 或按 execution.adoc「命令执行」约定选择对应 shell），避免终端/IDE 输出截断或命令中断后无法恢复而需重试；日志文件等临时产物写入 `tmp/` 文件夹（见执行原则「临时产物」条目）
* 以真实结果为准：不得仅凭命令 exit code 判断成败，须依据对应工具的实际统计结果（如测试的 run/failures/errors 统计、构建的成功日志等）判断；获取统计须一步直接到位——从重定向的日志文件中过滤统计行（同一命令内串联完成），一次拿到结果，禁止两段式"先运行、再提示后单独读取报告"的流程，也不得反复附提示性说明

== 分步验证

* 分步验证：设计、开发、写用例测试等多步骤任务，每个步骤执行完须对涉及的部分做一次隔离上下文的 code review，确保每步正确——前面方向错了，后面做再多也是无用功
