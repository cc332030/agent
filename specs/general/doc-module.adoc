= 模块级文档规范（通用层）

适用于**多模块项目中，模块内部文档的组织与归属**。全局文档（跨模块、规划性、阶段级）与根 `doc/` 目录的组织见 `specs/general/doc-lifecycle.adoc` 与 `specs/general/doc.adoc`；模块内设计文档/测试设计文档的编写格式见 `specs/general/doc-design.adoc`。

**本规范是总体大纲，只限定必要规则，不限制项目自主性**——模块名、模块 doc 内部按功能模块分类的目录组织、文件命名由各模块按其实际代码结构自行确定。

== 全局文档与模块文档的分界

* **全局文档（放根 `doc/`）**：跨模块、规划性、阶段级、长期稳定描述系统的内容——系统架构与技术选型、模块划分、部署架构、数据库、接口、需求、生命周期各阶段产物。全局文档不应描述某个具体类/文件/函数粒度的实现细节。
* **模块文档（放 `<各模块>/doc/`）**：**该模块的**总结性、规划性内容——模块职责与边界、模块内功能的总结与方案规划、模块内专属约定、模块内复用的注意点；**类级与方法级描述不另建文档、写在代码内的文档注释中**。模块文档不应描述跨模块、系统全局的规划性内容。
* **归属判定**：内容描述的范围属于"某个具体模块内部"（模块内功能/组件，总结与规划层面）记入该模块的 `doc/`；描述范围跨越多个模块或描述系统整体记入根 `doc/`。无法确定归属时参考"能否定位到单一模块"——能则入模块 doc，否则入根 doc；**类/方法/字段级细节不参与归属判定——它一律进代码内的文档注释**。

== 模块文档目录结构（大纲）

模块文档根目录为 `<各模块>/doc/`，**位于模块目录内、与源码同层**，保证离开代码就近可查。要求：

* **模块 doc 目录与模块源码结构对应/可定位**：以模块内功能模块/组件建立目录，能由文档定位到对应功能/代码、由功能/代码定位到对应文档。
* **目录结构具体多深、如何按功能模块分类**由各模块按自身代码规模自行确定，不写死（规模小可平铺，规模大再按功能模块分类）。
* **模块间依赖关系**按 `specs/general/doc-design.adoc`「依赖关系文档」执行：多模块项目在**项目根 `doc/dependency.adoc`**（不在模块 `doc/` 内——它描述的是模块**之间**的关系）。
* **模块 `doc/` 下按需放 `README.adoc` 作模块文档索引**（索引页"该不该建"的判据见 `specs/general/doc.adoc`「索引页的触发判据」）——**"按需"的判据是模块 `doc/` 下是否已承载实质文档**：
** 已承载模块内功能/组件文档 → 放 `README.adoc` 作索引，列这些文档的入口；
** 模块 `doc/` 下无任何实质文档（或将不建 `doc/` 目录）→ **不建** `doc/README.adoc`——不得"为每个模块都补齐索引页"而批量新建空壳索引；此时模块 → 文档的导航由**模块自身 `README`** 承担。

示例结构（仅示意，非强制）——正常项目按**功能模块**分类组织文档，而非镜像包路径：

[listing]
----
<module>/
├── src/.../<包路径>/<组件>.java     # 代码（类级描述写在代码文档注释中）
└── doc/
    ├── README.adoc                 # 模块级索引（仅当 doc/ 下有实质文档时需要）
    └── <功能模块>/                 # 按功能模块分类
        └── <功能>.adoc …           # 模块内功能的总结与规划（非逐类文档）
----

== 模块内引用与代码↔文档互引

* **模块 doc 内的链接**：与其他文档一致，用**相对当前文件所在目录的相对路径**，保证浏览器/站点与各工具的 ide 相对语义一致。
* **模块 doc 引用根 `doc/` 的全局内容**：从模块 doc 向上（`../` 到模块根，再 `../` 到仓库根）后进入根 `doc/`；以"相对当前文件"统一推导即可，不引入独立的"模块根相对"基准。
* **代码↔文档双向可定位**：遵循 `specs/general/doc-design.adoc`「类间关系与双向引用」；**注意两类引用的路径基准不同**——AsciiDoc 的 link 引用用"相对当前文件所在目录"，而 **javadoc `@see` 等由 IDE/javadoc 解析的代码注释引用以"模块根"为基准**，不要混用。
