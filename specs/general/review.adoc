= code review 规范（通用层）

以下规范适用于 code review 活动。

== 问题记录

* code review 问题记录：分级用 P 前缀，P0 最高、数字越小级别越高；序号以 Q 开头跨分级连续编号（如 P0 编 Q1~Q3 则 P1 从 Q4 开始），级别仅作分类不影响编号；每个问题浓缩一句话标题；问题需有明确状态（待处理/已修复/已备注/待评估等），已备注问题写明处理方案，便于人工更新（适用于所有有状态、需人工确认的问题记录）；废弃方法、字段及待完成占位代码（TODO、空实现、未引用方法等）不作问题提示；过于细节、无实际影响的问题不作提示（矫情原则）；上述不作问题提示的规则同样适用于测试类

== 问题修复

* 修复 review 问题：只做最小目标改动，修复前后自查，不得引入新的行为变更或缺陷；修复前先声明该功能的"不可违反的约束"（不变量），候选方案必须全部满足；候选方案做正常路径与异常路径双检查（正常路径行为不得改变、异常路径资源须释放）；修复后反向自查：本次修复会让哪个原本正常的场景失效？答不上来视为未自查；修复完补充测试用例且验证通过
