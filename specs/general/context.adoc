= 上下文与读取范围规范（公共内容，任务开始时即加载）

以下规范适用于**所有语言、所有项目**的 agent 执行过程。它解决两个问题：**"这件事该读多少"**（读取范围）与**"会话变长了怎么办"**（长会话治理）。

阅读范围与长会话治理的**逐条判据**的**完整正文在本文件**（见下「读取范围」）；必加载层 link:../core/execution.adoc[]「范围控制」只放这三条底线：**改动范围的边界（最高关注项，判据见 link:scope.adoc[]）**、**读取按最小必要（含长会话里简单任务在干净上下文执行）**与**判断不了就问、不靠多读猜**——两处不得各自漂移（重复会各自漂移，且常驻层体积每次会话都要付）。

== 读取范围（逐条判据）

* 读取范围（**最高关注项、不可降级；条款本身按 L1/L2 取值**）：改动任务须控制信息读取范围；**读取按最小必要、长会话里简单任务在干净上下文执行**。逐条判据如下（**级别即条款强度**）：
** **读取按任务定界（L1）**：开始读任何东西前，先按用户要求定出本次任务**必须知道的最小信息集**（要改什么、要什么证据），只读该集合内的内容——不因"顺手、反正便宜、了解下没坏处"而多读；读完后自检"读的这些是否都用到了"，未用到即属越界读取。
** **定位优先，避免全库扫描（L1）**：文件名/路径已知、或可由 glob/grep 直接定位的文件，必须用**精确定位**（glob/grep/read 精确取文件）读取，禁止启动 explore 类子 agent 做全库扫描；禁止借修改小需求之机对整个项目做 code review/全量摸底。只在"位置未知、命名未知"的开放性查找时才用 explore，且派发指令须限定目标、不得要求"列出所有文件/读取全部源码/读取全部文档"。
** **分层渐进、按需深入（L1）**：按"元数据 → 入口/目录 → 目标文件 → 必要片段"的层次递进读取，每层读完再决定是否深入，不一次读到底。命中检索结果时**先核对是否命中、命中位置是否真的是目标**，只读命中片段附近必要内容，不把整文件/整目录读入。
** **先查导航与索引，再读正文（L2）**：优先读项目的索引/总览（README、AGENTS 入口、`doc/` 索引页、规范调度器）来定位，再读对应正文；避免靠"逐个文件试读"摸索结构（有代码索引/符号跳转时优先用索引能力，其一跳定义胜过"grep + 读多份候选文件"）。
** **委派重型读取给子 agent（L2）**：跑测试（含按类别的测试执行，见 link:../stack/java-testing.adoc[]「测试分类与执行边界」）、读长日志、拉外部文档、大范围调研等**输出量大**的读取，优先委派子 agent（或先用 grep/head 等预处理只留关键行），让冗长内容留在子 agent 上下文里，只把结论/摘要带回——子 agent 自身可大量读取，返回的浓缩摘要通常仅千余 token（委派边界与调用量控制见 link:collab.adoc[]）。
** **读取结果落盘、不靠记忆（L2）**：大范围检查与多步骤任务的进度、结论写入 `tmp/` 下临时文档（见 link:../core/execution.adoc[]「临时产物」），供后续步骤/后续会话读取；不要求把大段原文常驻上下文，也不靠"记得住"。
** **判断不了就问，不靠多读猜（L1）**：需求存在歧义、命名与位置均不确定时，先按 link:../core/execution.adoc[]「指令执行」提问澄清，不得用"把相关的东西都读一遍"来代替澄清；此时对照"用户明确声明要扫描整个项目"的解禁条件判断是否已被授权扩大读取范围。
** **任务切换即清洁上下文（L1）**：一次会话内切换**互不相关**的任务时，先把通用规范入口与项目自身规范**重新读取/重新确认**（规范是常驻前提，不是历史噪音），再开始新任务；不得依赖"上文已经读过规范""记得住约束"而带着旧任务上下文直接干新活；已放弃/已中断的任务上下文不得再作为判断依据（见 link:../core/execution.adoc[]「任务放弃与中断」）。
** **长会话降级自保（L1）**：发现当前会话已执行多个任务、上下文明显变长时，**主动降低读取范围**——简单任务按最小必要读取，不沿用上一任务的探索路径、不重复上一任务读过的文件；若一次简单任务仍需要读大量文件，先停下来说明"需要更多上下文的原因"，而不是直接开读。
** **结论交给持久文档与规范（L2）**：任务产生的**持久结论**写入代码注释/设计文档/规范/`tmp/` 记录（见 link:doc-design.adoc[]），使其可被后续会话**重新读取**；不要把"结论要靠本次会话的上下文记住"当作机制——会话上下文是易失的、且越大越不可靠。
** **简单任务优先另起会话（L1）**：执行环境支持新开会话/清空上下文、且任务与当前会话历史无依赖时，简单任务**优先另起会话或清空上下文后再执行**，收益是确定的（简单任务在干净上下文下更准确、更快、更省）；判断依据是"本次任务是否需要历史的细节"——需要的是**规范与持久文档**（可重新读取），不是历史对话本身。执行环境不支持时，按上两条在会话内降级处理，并**在结果中说明"建议下次在干净会话中执行此任务"**。
** **阶段结论即时落盘（L1，长会话底线）**：每完成一个阶段/里程碑，**立刻**把结论写入持久位置（`tmp/` 记录、设计文档、代码注释），不等上下文逼近上限才整理——届时可能已无空间写清；这是"会话可随时被清空/压缩"的前提（见 link:../core/execution.adoc[]「临时产物」）。
** **超长任务的分段（L2）**：单任务确实跨越多轮、上下文逼近窗口上限时，按业界手段分段：先压缩（保留决策、未决问题、接口约定，丢弃冗余工具输出）或把阶段结论落盘，再继续；需要并行探索的调研类任务改用子 agent 隔离（见 link:collab.adoc[]）。**压缩或清空前必须先把关键约定与结论落到持久位置**，避免"压缩完就丢"。
** **读前自检（L1）**：动手读之前确认两点——①本次任务的目标与范围是否已明确（未明确先澄清）；②这批读取是否落在最小必要信息集内（不在则说明理由或缩小范围）。
** **读后自检（L1）**：读完后确认两点——①读到的内容是否都与任务相关（有无关内容即停止继续读）；②是否已具备完成任务的充分信息（不足时再按上节判断"该补哪一层"，而非扩大为全量扫描）。

== 运行契约（公共内容被未知项目加载时的可控性）

本节的**完整正文与判据**在 link:verify.adoc[]「运行契约」——公共内容（入口 + `specs/` + `prompts/` + 会被引用方加载的工具）不是在某一个项目的上下文里生效，而是**被未知项目加载**（看不到它的项目结构、已有规范、依赖与工具链），故"加一条规则"还要问"**它落到一个未知项目里会发生什么**"。判定按**三维**逐维过（判据、逐维要点与标准出处见该节；依据：ISO/IEC Directives Part 2、ISO/IEC/IEEE 29148、ISO 9241-110）：

* **① 影响面**：会改变引用方的哪些既有行为；**与引用方自身规范的冲突次序**是否写明（以引用方项目自身规范为准）；**不得"静默推翻引用方既有约定"**。
* **② 成本**：加载面体积（每次会话都加载的部分须有可机械核对的上限，只写"要注意体积"不构成上限）、时延/token 开销、引入的依赖或工具链要求（含不可用时的降级路径）；**不得以"不贵"含糊带过**（ISO/IEC/IEEE 25010）。
* **③ 可控性**：能否预期、能否关闭、能否自行执行——不默认改动/格式化引用方文件、不默认代为提交、不默认清理其临时产物；不得让引用方依赖本仓库私有物；不得阻断其正常路径（无降级路径的硬性前置一律不合规）。
* **接纳面须留证（L1）**：新增/调整公共内容时，须在改动说明（提交说明或汇报）中逐维写明"影响面 / 成本 / 可控性"的核对结论；**未核对不得计入验证通过**。

本节的**规则本体只写一处**（link:verify.adoc[]「运行契约」）——本节只留三维的**索引**（哪些维度、判定哪些事），逐维判据与依据名一律以该文件为准，不重复表述（重复会各自漂移）。
