= 通用工具/库类项目文档规范（项目类型层）

以下规范适用于**通用工具/库类项目**（以可复用组件/库/工具为主、要求每个类在设计时保证绝对正确与绝对可维护性的项目）的文件/类粒度文档组织。**仅在项目自身规范中主动声明为"通用工具类项目"时才加载**（声明方式与检测见 `AGENTS_COMMON.adoc`「分类与懒加载」项目类型层）。普通业务项目不适用，不加载本规范。

== 粒度

* 文档目录只放总结性、规划性内容（**不另建逐文件/逐类文档**）：类级描述（定位、能力目录）与方法/字段细节写在**代码内的文档注释**（javadoc / docstring / JSDoc 等，按语言实际机制；见 link:../general/doc-design.adoc[]「信息归属」），类间关系（源文件、测试、性能测试）在代码文档注释中互相引用；文档目录承载模块/功能的**总结与规划**（总览、方案与取舍、关键约定、复用注意点等），规模小可平铺、规模大按功能模块分类。**此为承载位置变化、不减少内容要求**（见 link:../general/doc.adoc[]「文档内容不得因承载位置迁移而减少」）；确需成篇的类级文档时才按「文档命名须与源文件一致」命名，并与源文件同模块就近存放（link:../general/doc-module.adoc[]）。

== 示例结构

文档目录结构示意（仅示意，非强制）：

```
<module>/
├── src/.../<包路径>/Foo.java     # 代码（类级描述写在代码文档注释中）
└── doc/
    ├── README.adoc               # 模块级索引（总览模块职责、关键文档）
    └── <功能模块>/               # 按功能模块分类
        └── <功能>.adoc …         # 模块内功能的总结与规划（非逐类文档）
```
