= 设计文档规范（通用层）

以下规范适用于**设计文档与测试设计文档**的编写维护。设计文档记录核心功能的方案、取舍、兜底与适用范围；测试设计文档记录测试行为本身的设计与验证规格（测试是功能的验证规格，二者一体）。业务系统（从立项到上线的完整项目）的阶段级文档组织见 link:../general/doc-lifecycle.adoc[]。注释/记录的通用原则见 link:../general/doc.adoc[]。

== 设计文档

* 设计文档：核心功能的新增、重构（含行为变更、方案选型、有取舍的设计）必须编写或更新设计文档，记录当时考虑到的所有东西：功能设计（方案是什么、为什么这样做、备选方案及不选原因）、测试设计（测试行为本身的设计：测试架构与组织、测试手法与参考实现、覆盖哪些场景、为什么这样测、测试边界与取舍）、兜底（有哪些兜底、兜底触发条件与边界）、适用范围（适用场景、不适用场景、已知限制与取舍）；功能设计与测试设计放在同一设计文档内（测试是功能的验证规格，二者一体，避免文档分散）；文档按模块建立子目录存放：业务系统中置于设计阶段目录下的 `<模块>/` 子目录（如 `doc/<设计阶段>/<模块>/`，见 link:../general/doc-lifecycle.adoc[]），非业务系统可直接用 `doc/<模块>/`；模块名取核心功能/组件所属模块（如 `core`/`web`/`feign`/`log`，以各项目实际模块划分为准），功能设计文档与测试设计文档成对放在同一模块子目录下（`<模块名>.adoc` 功能设计、`<模块名>-tests.adoc` 测试设计）；AsciiDoc 格式；文档随代码演进同步更新，新增、重构时必须处理
* 代码与文档互相引用：代码与设计文档必须**双向可定位**——文档须写明所对应功能的模块与类/方法（从文档能找到代码），代码（类/方法的注释）也须显式引用对应的设计文档相对路径（从代码能找到文档），二者任一处都能顺利跳转到另一处；注释写法见 `specs/stack/` 对应语言文件的注释规范；新增/重构代码时同步补齐双向引用，缺失引用的旧代码发现后直接补，不遗漏
* 设计文档须记录已知缺陷与不足：设计文档除记录设计本身，还须**显式记录当前工具类、方法、字段的已知缺陷、不足与注意事项**——包括但不限于：
  ** 易误用点：调用方可能踩坑的入参/出参假设、线程安全、可变状态被共享修改等
  ** 边界与异常：异常未处理/吞掉、空值/超长/超大输入等
  ** 默认值：字段/参数的默认值及其语义（如"0 表示未测量 / null 表示未采集"等易混淆约定），默认值可能引发的行为差异与误判
  ** 可能引发的问题：如拼接日志时异常静默导致主流程中断、字段不同步、序列化兼容等
  ** 性能瓶颈：大对象/循环内分配、正则/反射/序列化开销、阻塞 IO、复杂度隐患等
  ** 可能影响的功能：当前缺陷/不足/默认值变更会波及的其它功能、调用方或下游逻辑，须列出受影响范围以便评估改动
  ；记录粒度到"类→方法/字段"层级，按类/方法/字段分段标注，能定位到具体代码；缺陷内容随代码演进同步更新（修复后标注已解决或删除），不遗漏、不依赖记忆

== 文档版本与变更日志

* 文档版本与变更日志（**适用范围：仅设计文档、测试设计文档；规范文件不适用，见下**）：**设计文档、测试设计文档**（即 `<模块名>.adoc` 与 `<模块名>-tests.adoc`）头部必须包含 `Version` 与 `LastModified` 字段（置于标题之后，如 `Version: 1.0`、`LastModified: 2026-08-21`）；文档须维护**变更日志**小节（`== 变更日志`），按时间倒序记录每次变更：版本号、日期、变更摘要（改了什么、关联代码/需求）；初始落地版本从 `1.0` 起，代码有行为/接口/默认值/已知缺陷等任何变更时，Version 递增（如 `1.0`→`1.1`，重大重构可 `1.x`→`2.0`）、LastModified 更新为当前日期、并在变更日志追加一条
* 适用范围界定：本机制**仅适用于设计文档、测试设计文档**（业务文档，随代码演进记录版本）。**规范文件（`specs/` 下各 .adoc）不适用、不要求维护 Version/LastModified/变更日志字段**——规范变更由其 git 历史承载，并须按规范管理（specs/core/management.adoc「规范调整」）执行"调整后子 agent 验证"。二者不得混淆。**测试阶段文档**（如测试计划、测试报告）同样不适用，是否维护版本由各阶段自行确定（见 doc-lifecycle.adoc）。
* 变更日志位置（文末，时间倒序）：放在**文档最末尾**，作为独立小节 `== 变更日志`，按**时间倒序**记录（最新变更在最上方、最旧在最下方，即追加时总是插到小节顶部）；头部 `Version`/`LastModified` 字段仍固定在标题之后，不随变更日志移动
* AI 强制约束（仅对设计/测试设计文档）：修改代码前，必须先更新此文档的 Version 与 LastModified 字段、并在变更日志追加对应条目，**否则禁止提交代码**；缺失头部字段的旧设计/测试设计文档发现后直接补，不遗漏
* 头部字段与变更日志位置参考（设计/测试设计文档通用）：
  ```
  = <模块名> 功能设计

  Version: 1.1
  LastModified: 2026-08-21
  ...

  == 1. 功能设计
  ...

  == 变更日志

  - 1.1 | 2026-08-21 | 本次变更摘要（最新在上）
  - 1.0 | 2026-08-16 | 初始落地
  ```
