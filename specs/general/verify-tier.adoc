= 验证力度分档（通用层，跨语言）

本文件是「验证」一族的第二份：**验证做多深**的判据。**做哪几件事的清单**、验证的适用边界、效力等级与三态台账、验证总纲与改完规范后的定式都在 `specs/general/verify.adoc`；本文件只管**按改动性质取力度**这一问。

== 本族怎么加载（按问句取，不整族读完）

[cols="2,3", options="header"]
|===
| 份 | 命中就加载

| `specs/general/verify.adoc`（族入口） | 验证做不做、做什么、怎么算过：适用边界、效力等级与三态台账、验证总纲、改完规范必做的五件事
| `specs/general/verify-tier.adoc`（本份） | 验证做多深：这次改动属 A/B/C 哪一档、哪几件可以免做
|===

* **按问句取、不预读（L1）**：要判"这次要不要验、验到什么程度"取 `specs/general/verify.adoc`「验证的适用边界」；要判"这一档免做哪几件"才取本份。
* **族内互指用全路径（L1）**：指到另一份的节时写**目标全路径**——族内节序会变，靠"上一节"指路在分份后必然指错。
* **本份是族内登记点（L1）**：本份在族入口 `specs/general/verify.adoc` 与本表登记；未登记的份永不加载、规则实际失效。

== 验证力度分档（同样一件事，按风险取力度，不一律顶格）

**力度是成本，不是虔诚**：把"每次改完规范都做全量 + 三视角 + 干净子 agent"当成唯一形态时，真实后果是**每一档都按最贵的方式付**——改一个错字与新增一道防线付一样的价钱，久了只会得到两种结局：要么执行者开始"形式上做一遍"，要么干脆不做。故验证力度**按改动性质分档**（与业界可调力度分级同向：评审深度随风险取值，不随文件数量取值）。

**分档判据（先判档、再决定做哪几件；判档结论写进台账第一行）**：

[cols="1,3,3", options="header"]
|===
| 档 | 命中条件（任一） | 本次"五件事"要做到哪一步

| **A 档（机械够用）**
| 改的是**表述与登记**：措辞、错字、节序、链接与路径、引用的节名、登记表与清单同步、随规范分发的脚本里的纯注释——**判据本体一个字节没动**（既没改取值、也没改判定标准、没增减条目）。**「措辞」只指不改变读法的改写**（同义改写、错字、语序）：把「必须」改成「应当」、把一段判据压成一句口号、把一个例外面换个说法而覆盖面变了，都**不属**这一档——它们在下一档及以下按语义改动判（见本条末句「措辞小不等于语义小」）
| ① 机械手段（跑全、报红就地修）＋ ④ 三态台账（**逐项写清"为什么判为 A 档"**）。②③⑤ **免做**：语义复核的对象（判据是否被压成口号、机制还成不成立）在本次改动里没有任何可能变化面。

| **B 档（单视角够用）**
| 改到**一条判据**：某条的取值/判定标准/例外面/依据名调整，或把一条从某份搬到同族另一份——**不新增、不删除判据**，不改变加载面
| ① 机械手段 ＋ ② 语义复核（**单视角：完整性 + 有效性合并一次**，可由执行者在本次执行内串行做、**如实标注独立性边界**）＋ ④ 三态台账。③ 接纳面只在**动到会被未知项目加载的内容**时才做（判据：改的那条引用方能不能感知到差别）。

| **C 档（三视角顶格）**
| 任一命中：**新增或删除判据/防线**；改判据的**语义**（同一句读法变了）；改**加载面**（调度器、族内分份、父子关系）；改**流水线与校验链**；跨多份规范的重构；改随规范分发且会改变行为的脚本
| ① 机械手段 ＋ ② 干净子 agent 的**三视角**（一次读取、分栏列）＋ ④ 三态台账 ＋ ⑤ 不可用时的降级与留证。**一件都不能少**。

|===

* **判不准取更严一档（L1）**：档位拿不准时**按更高一档办**——档位是"少做哪几件"的依据，判错方向只会少做；反过来把 C 档判成 A 档，等于把"这条规则还成不成立"这件事整个跳过。**判定标准（任一命中即违规）**：① 台账里说不清本次是哪一档、为什么；② 按 A 档交付，而改动里实际动了取值、判定标准或条目数；③ 以"改动小""只是一个词"为由把 C 档压成 A 档（措辞小不等于语义小：把"必须"改成"应当"只有一个词，是 C 档）。
* **档位不改变"跑全"（L1）**：① 机械手段**任何档都跑全**——它是确定项，成本按秒计，没有按改动面取巧的余地（"只跑改到的那几个检查"是这条唯一被明确否掉的省法）。
* **档位可随时上调、不可下调（L1）**：复核过程中发现改动实际触到了更高一档的判据（例如以为只是改措辞、实际把例外面收窄了），**就地升档并补做**；不得因为"已经按 A 档开头了"就把结论写成 A 档。
* **分档不是评审门槛（L1）**：分档只决定**验证做多少**，不决定**要不要验证**、也不决定交付是否通过——A 档同样要跑机械手段与留台账，“A 档”不是「可以不验证」的同义词。
* 依据（标准名/编号）：ISO 10007（配置管理与变更控制：变更的验证深度按其影响面取）、IEEE 1028（评审的严格程度按对象风险分级，非一律同深度）、ISO/IEC/IEEE 12207（验证过程按被验对象选取）。**「三档的档位定义与每档做哪几件」是本集合按现场用量判据化的取舍**——上述标准给的是"按风险取验证深度"这一方向，**未**给出档位如何切分。

* **与族入口的分工（L1）**：本份只给**档位怎么判**；「五件事」逐项的要求与判定标准在 `specs/general/verify.adoc`「改完规范必做的五件事（机械手段必跑，干净子 agent 复核不可漏）」，免做哪几件的理由须写进那个台账——两处各写一半、不各写一份。
