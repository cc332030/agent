= agent 协作规范（通用层）

以下规范适用于所有拆分 agent（含主 agent）协作的场景。

== 资源限制与感知

* 调用次数限制：agent（含主 agent）调用 AI 次数有限（约百次量级），超限后自动停止并要求人工接入；主 agent 自身也要控制调用量，避免超限后需人工接入
* 拆分原则：拆分 agent 不能只按模块拆分（模块大小不均会导致任务量失衡），应按任务量分批拆分子 agent，使每个 agent 的调用次数低于限制
* 失联感知：子 agent 超限停止后主 agent 无感知，任务会永久挂起；须建立感知机制（如定期探活、设定超时视为失联并接管/重建）

== 协作方式

* 大任务优先使用子 agent：项目级检查（测试检查、code review、全量修改等）优先拆分给子 agent 执行，主 agent 只做任务编排、结果汇总与最终验证；子 agent 的执行边界须在派发指令中写明（如禁止并发构建、只写文件不验证等），避免多 agent 相互冲突；子 agent 不执行构建验证时，由主 agent 统一串行验证
* 步骤隔离：多步骤任务（调研、设计、编码、写用例、用例验证、文档等）步骤间无依赖时，优先各自用干净的子 agent 独立完成——子 agent 上下文隔离，避免前序步骤的上下文影响后续步骤；主 agent 负责编排与汇总
