= 脚本规范（通用层，跨语言）

以下规范适用于**所有脚本语言**编写的脚本文件（bash/sh、Python、Node.js、PowerShell、Perl 等）的格式与编写。脚本泛指用于执行一次性或自动化任务的程序文件（区别于作为项目主体的应用代码）。某语言/技术栈专属的脚本规则见 `specs/stack/` 对应文件。

== 文件格式与编码

* 编码与换行：脚本文件一律 UTF-8 编码（通用编码要求见 link:../general/doc.adoc[]「文件格式与编码」）
* 可执行标识：Unix/Linux 下的脚本文件须在首行写明 shebang（如 `#!/usr/bin/env bash`、`#!/usr/bin/env python3`），明确解释器；须设置可执行权限（git 中 `chmod +x`），确保可直接以 `./脚本名` 方式运行
* 行尾与缩进：统一行尾符，不混用 LF/CRLF；缩进风格随脚本语言惯例统一，同一文件内保持一致

== 文件命名

脚本文件名**默认使用中划线**（kebab-case，小写 + 连字符 `-`），如 `ai-review.sh`、`check-specs.py`。仅当某脚本语言**机制上不支持中划线**时（如 Python 的模块名/标识符不能含连字符，会导致脚本无法被 `import` 复用、无法被 `unittest discover` 自动发现），才回退使用**该语言自身的命名规则**（如 Python 用下划线 snake_case，`check_specs.py`、`clean_tmp.py`）——即「默认中划线、语言不支持则用语言自身规则」，不再逐一列举各语言脚本该用何种命名。

* 命名须**自洽**：测试文件命名（link:../general/testing.adoc[]「后缀式」`foo.py → foo_test.py`）与被测文件名保持同一套字符规则，避免同一语言内出现两套命名风格或需靠「例外」绕开
* 脚本内部变量、函数、模块名等标识符仍遵守语言/编码规范（如 Python 用下划线 `snake_case`，见 link:../general/coding.adoc[] 与对应技术栈文件）
* 脚本对应文档命名与脚本文件一致：文档命名（脚本文件名 + `.adoc`、测试文档加 `test` 后缀、命名风格跟随脚本）遵循 link:../general/doc-design.adoc[]「文档命名须与源文件一致」

== 脚本头部注释（文档头）

* 头部注释必须说明脚本的**定位、用法与关键约定**，让读者（含 agent 与后续维护者）无需阅读源码即可掌握使用方法。建议在文件开头以块注释形式写明：
  ** 脚本名称与用途（一行概括做了什么）；
  ** 用法：调用方式、命令行参数（含参数含义与示例）；
  ** 环境变量（如有）：每个环境变量的含义、是否必填、默认值；
  ** 行为/副作用：脚本会做什么、写入/生成哪些文件、依赖哪些外部命令或资源；
  ** 安全保证或重要边界（如删除类脚本须写明"只操作某范围、绝不越界"）。
* 头部注释使用脚本语言自身的注释语法；注释内容遵守文档规范（link:../general/doc.adoc[]「注释与文档」）：记录决策、边界与用法要点，不追求完整叙述

== 参数处理

* 统一使用脚本语言标准的参数解析机制（如 Python 的 `argparse`、Node 的 `commander`），避免手写脆弱的字符串解析
* 参数须有默认值或显式必填校验：必填参数缺失时输出清晰错误并退出非 0，不静默使用空值
* 提供 `--help`/`-h` 能力（由标准解析机制自带或手动实现），说明全部参数用法
* 帮助类/未知参数：解析到未知参数时提示并退出非 0，不忽略

== 退出码约定

* 退出码 0 表示成功，非 0 表示失败；不同失败类型可用不同非 0 退出码区分（如参数错误、执行失败、未满足前置条件），并在头部注释或文档中说明各退出码含义
* 脚本被调用方依赖退出码判断成败（尤其被 CI、流水线或其他脚本调用时），不得"失败也返回 0"
* 出错时向标准错误（stderr）输出错误信息，正常结果输出到标准输出（stdout），便于区分与重定向

== 错误处理与健壮性

* 关键步骤失败须显式检查并处理：依赖外部命令/资源时检查其成败，失败即按约定退出非 0，不继续执行后续依赖步骤
* 脚本应尽量"安全失败"：出错时不留下半成品或破坏性结果；涉及删除、覆盖、写外部资源等有副作用操作时，先校验边界并（必要时）要求显式确认
* 抑制非必要输出：日常无参数运行时保持安静，仅在 `-v/--verbose` 或显式请求时输出详细过程

== 安全

* 路径处理：脚本处理文件路径时，须校验目标位于预期范围内，防路径穿越（`../`、绝对路径、符号链接指向外部等），尤其对删除类、写文件类脚本——先校验边界再操作，越界即拒绝
* 不信任外部输入：参数、环境变量、文件内容等外部输入不可直接当作命令或路径拼接执行，须校验/转义；禁止把未经处理的用户输入直接拼入 shell 命令
* 临时文件：脚本产生的临时文件优先放入目标项目 `tmp/` 目录（见执行原则 specs/core/execution.adoc「临时产物」），用完即清理；不把临时产物写入项目正式目录或提交

== 与编码规范的关系

* 脚本中的具体编码规则（命名、注释、代码结构、禁止控制台打印等）遵守 link:../general/coding.adoc[]，不在此重复；某语言脚本的专属写法见 `specs/stack/` 对应文件（如 link:../stack/bash.adoc[]、link:../stack/python.adoc[]、link:../stack/powershell.adoc[]）
