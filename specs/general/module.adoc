= 模块边界规范（通用层，跨语言）

适用于**所有语言、所有项目**：一个功能的实现落在**一个模块**里，不跨模块拼装。模块的划分粒度、模块间的依赖方向与依赖视图见 `specs/general/doc-design.adoc`「依赖关系文档」；单文件做几件事见 `specs/general/coding.adoc`「源码文件的规模」；分层内的职责（哪一层能调哪一层）见技术栈层对应文件（Java 见 `specs/stack/java.adoc`「持久化访问」）。

**模块**指项目自己划定的**功能单元**——判据是「这件事归谁管」，**不是**构建工具里的子项目：一个包、一个目录可以是一个模块，**一个文件同样可以是一个模块**，小功能常常就是**一个文件一个模块**。构建工具的多模块（Maven 的 `<modules>`、Gradle 的 `include`、npm 的 workspaces）只是模块的**一种**形态，**不是**本条的适用前提；本条对**没有任何构建模块的单文件项目**同样成立。第三方库与语言自带的划分方式不在此列。

依据（标准名/编号）：ISO/IEC 25010（可维护性：模块化与可复用性、可分析性）、ISO/IEC/IEEE 29148（需求单一、无歧义、可验证）、David L. Parnas《On the Criteria To Be Used in Decomposing Systems into Modules》（模块按信息隐藏划分）、Martin Fowler《Refactoring》。**"功能实现不得跨模块"是本集合的判据化取舍**——通行材料给的是"高内聚、低耦合"这条方向与上述两条坏味道，**未**规定"一个功能的实现不得由两个模块各写一半"这一处可核对的边界。

== 功能不跨模块（同一功能的实现只有一处落点）

* **一个功能只由一个模块实现（L1）**：用户或调用方能看见的**同一件事**（一个功能、一条规则、一种输出形态），其实现须落在**同一个模块**里——**多数时候就是一个文件**，这时本条要求的正是「别拆出去」；**不得**由两个及以上模块各写一半——一半在这里算、另一半在那里拼，或同一份规则在两个模块各写一遍。**判定标准（任一命中即违规）**：① 一处功能的完成需要**跨两个及以上模块来回调用**，去掉其中任一处这段功能就不成立（不是"调用下游能力"，而是"两边各实现一半"）；② **同一条规则/取值在多个模块各写一份**（同一条判据见 `specs/general/coding-ui.adoc`「同一件事只有一个来源」）；③ 一个模块的实现里**直接读写另一个模块的内部数据或中间产物**，越过对方给出的入口。
* **唯一落点由"这件事归谁"定，不由当前位置定（L1）**：发现同一功能的实现散在两处时，**先判这件事本质归哪个模块**（谁拥有这份数据、谁对它负责），再把实现**收敛到那一处**、其余改为取用；**不得**为省一次搬动而保留两份，也**不得**按"哪一份行数少/哪一份先写的"来决定。收口后原位置**只留取用与装配**、不留副本。
* **出口与入口成对（L1）**：模块只通过**自己声明的入口**对外提供能力；调用方**不得**依赖对方未声明为入口的内部结构（内部方法、内部字段、内部目录里的文件、中间产物）。判据：把对方模块的内部实现整体重写、只保留其入口，调用方仍应照常工作——做不到即为越界。
* **边界内聚、边界之间少耦合（L1，判据取改动形态）**：判边界划得好不好，**不看模块大小与数量，看改动落在哪里**——**发散式变化**（改一个需求要在同一模块里改多处互不相干的实现）说明这个模块装了几件事；**霰弹式修改**（改一处功能要在多个模块里各改一遍）说明这件事被切散了。判定标准（任一命中即违规）：① 本次改动里，同一处行为变化在同一模块的**多处**实现里各改一遍；② 本次改动里，一处功能变化散落在**多个模块**里，且各模块改的是"同一件事的一半"；③ 以"分层就这样""历史上一直如此"为由不判边界。
* **小功能不为凑模块而拆文件（L1，防误伤）**：功能**小到一个文件写得下**时，那个文件**就是**它的模块——**不得**以「分层」「解耦」「职责单一」为由把这段实现拆到几个文件里再互相调用，也**不得**为了「看起来像个模块」而加一层转发。判据：**抽掉其中任何一个文件，这段功能就残缺**，即属把一件事拆成了两半。
* **调用下游不算跨模块实现（L1，防误伤）**：一个模块**取用**另一个模块的入口、或使用公共模块/工具与语言标准库来完成自己的功能，属正常依赖，**不构成**跨模块实现；本条禁的是**同一件事被拆成两半各写**，不是禁"模块之间有依赖"。
* **存量边界（L1）**：本条**只管新增与本次改到的功能**——新功能一开始就落在一个模块里；已散的存量**改到哪一处就顺带收敛该处**（随动迁移，见 `specs/core/execution.adoc`），**不发动全库重划模块**，也**不得**在一次无关改动里顺手大改既有模块结构。
* **判定标准（本节可整体核对）**：抽掉某个模块后，属于它的功能**整块消失**（不会被别的模块"补上一半"）——做不到，即该功能横跨了模块。
