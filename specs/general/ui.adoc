= 界面与交互规范（通用层，跨端判据本体）

适用于**任何语言、任何端**的界面：网页、桌面客户端、移动端与平板应用、内嵌界面的桌面工具。加载特征：要设计或改动**布局、样式、字号、间距、颜色**，要在**多个端**上承载同一功能，要定**鼠标 / 触摸 / 键盘**的交互方式。已有的三条界面判据（框架与样式方案优先、同一形态只有一个来源、界面的规模与性能）在 `specs/general/coding.adoc`；本文件是**它们之外的第四组判据**——**形状、色彩、尺度与交互**该取什么值、按什么顺序判。取值清单（令牌、分端方案、参照应用、风格族与文案词表）不写在这里：它们是模板文件，见 `specs/general/ui-tokens.adoc`、`specs/general/ui-targets.adoc`、`specs/general/ui-styles.adoc`、`specs/general/ui-voice.adoc` 与 `specs/general/ui-patterns.adoc`（容器形态、表单排布与分组、结构化值详情、表格列宽的决策路径）。**反馈面本身**（成功、错误、警示、提示、进度五类怎么分类、由哪一层产生、走哪个通道、什么算打扰、哪些必须留痕）不在本文件：判据本体在 `specs/general/feedback.adoc`，取值表在 `specs/general/ui-feedback.adoc`；本文件只给**它们长什么样**（颜色、对比度、字号、命中区）与**文案怎么写**。

== 本文件的字典（本文件使用的名称，定义写在本文开头）

[[term-end]]
**端**：承载界面的运行环境与输入设备的组合——同一份功能在不同端上的**输入方式**（鼠标 / 触摸 / 键盘）与**观看距离**不同。判定时按**输入与视距**分，不按技术栈分：网页跑在平板浏览器里、触摸加视距近，按移动端判而不是按桌面端判。

[[term-design-token]]
**设计令牌**：界面里**会被两处以上用到**的取值（颜色、字号、间距、控件高度、圆角、层级）所对应的**具名常量**。取值落在项目自己的一处，页面只按名取用。

[[term-scale]]
**字号尺度**：正文、次要文本、标题各占一档的固定**字号序列**，档数少而跨度清楚；不按页面逐处微调。

[[term-density]]
**密度**：同一屏内可容纳的信息量，由控件高度、行高、间距共同决定。它是**端的属性**（触摸端更松、鼠标端更紧），不是页面的属性。

[[term-contrast]]
**对比度**：前景色与背景色的相对亮度之比，按 WCAG 的相对亮度公式计算，取值以「最小值」与「增强值」两档为准。

[[term-style]]
**风格族**：一组**成套出现的取值取向**（色阶饱和度、字号跨度、间距节奏、圆角档位、层次表达、动效幅度、图文比例、装饰密度）——判"是不是同一族"，看这八项是否自洽，不看名字。**判定标准**是"换族要改的是令牌那一处"，不是"设计稿看起来不一样"。

[[term-voice]]
**界面语气**：界面文字对用户呈现的**人称、正式度、活泼度与术语密度**四项的固定取值。它是**产品的属性**（一处定义、各端一致），不是页面的属性。

[[term-affordance]]
**可供性**：控件外观**自身**表达"这里能不能点、能不能拖、值不值钱"的可见线索（层次、分隔、指针形态、按压反馈）。判定标准是**不读文档也看得出来**。

== 三件事与既有判据的分工（先读，防两套判据并存）

本文件只补「形状、色彩、尺度、交互」这一层；另外三件事**判据本体不在本文件**：

* **取哪套现成方案、同一形态放哪一处** → `specs/general/coding.adoc`「界面与样式」
* **数据长起来之后会不会卡** → `specs/general/coding.adoc`「界面的规模与性能」
* **两处是不是同一件事的第二份来源** → `specs/general/coding.adoc`「同一件事只有一个来源」
* **这个提示该不该出现、走哪个通道、会不会打扰人、要不要留痕** → `specs/general/feedback.adoc`（本文件只管它的形态与文案）

三者的**取值落点**仍按本文件：取的颜色、字号、间距、控件高度一律走**设计令牌**那一处；「同一形态只有一处」在视觉层就是「同一令牌只有一个取值」。

== 总纲与颜色（什么该一致、什么才允许不同；选什么色、怎么配、对比度要多少）

* **一个可访问的基线、一套令牌、一处分端差异（L1）**：同一产品在**所有端**共用**同一套令牌与同一套组件形态**；端与端之间**只改密度、版式与导航形态**，**不改**颜色语义、字号档数、组件职能、文案语气。**判定标准（任一命中即违规）**：① 同一个语义色（危险、成功、主操作）在不同端取了不同的值；② 同一个组件（按钮、输入框、列表项）在不同端有各自的实现文件且外观靠复制调整；③ 以「手机上不一样才好看」为由把某一端整套换成另一套体系，而未说明哪几项是端差异、其余为何随之改。
* **先定令牌、再拼页面（L1）**：新增界面先落令牌取值（色阶、字号尺度、间距序列、控件高度、圆角与层级），页面只按名取用；**不得**在页面里出现颜色字面量、裸像素字号与间距。**判定标准（任一命中即违规）**：① 页面/组件里出现十六进制或 `rgb` 颜色字面量而非令牌名；② 字号、间距、控件高度写成逐处数值（而非取某一档）；③ 以「这一处特殊」为由就地写值。
* **令牌按「共用 / 分端」两档分文件，不按端各抄一份（L1）**：令牌的**文件落点**由取值范围决定，不由端数决定——**端间相同的取值（颜色语义、字号档、间距序列、圆角、层级、动效时长）落共用的那一份**；**只在某个端才取不同值的（控件高度、行高、命中区、断点）落该端自己的那一份**。**不得**把产出的文件数等同于端数：一端一份全量令牌，等于让颜色与字号在每一端各有一份副本。**判定标准（任一命中即违规）**：① 同一个令牌名在**两个及以上**端文件里各自定义（共用那份里已有，端文件里又给了取值）；② 共用那份里出现**只在某一端成立**的取值（如把某一端的控件高度写成全局值）；③ 以「各端一份好维护」「端差异一眼看得见」为由按端复制全量令牌。

* **颜色按语义命名、不按色相命名（L1）**：令牌名取**用途**（主操作、危险、成功、警告、表面、边界、正文、次要文本），**不取**颜色（不叫「蓝色按钮」「灰色字」）。**理由**：按色相命名时，一次主题改动（暗色模式、品牌换色）会让名字与实际取值对不上，改一处必漏其余；按语义命名才使"同一职能在所有端同一个入口"。**判定标准**：出现以颜色词命名的语义令牌、且该令牌被当作职能使用。
* **中性色为主、语义色为标记（L2）**：界面主体取**中性色阶**（背景、表面、边界、正文、次要文本），语义色**只用于标记状态与主操作**；**不得**用大面积饱和色承担版面分隔或信息分组。判定标准是：把界面去色后，**信息层级仍然清楚**。
* **对比度取两档、并按文本大小分（L1）**：正文与小号文本按**增强值**判（WCAG 2.2 的 7:1），大号文本（不小于 24 px，或粗体不小于 18.66 px）与图形化控件边界按**最小值**判（WCAG 2.2 的 4.5:1 与 3:1）；**禁用态**、纯装饰元素不受本档约束，但仍须能看出"这里有个东西"。**判定标准（任一命中即违规）**：① 正文/次要文本与背景的对比度低于增强值而未在令牌处标注该处属"大号文本"；② 输入框边界、开关轨道、图标按钮这类**必须被看见才能操作**的图形低于最小值；③ 用透明度压暗文字来"分层级"（这一手法最容易跌破对比度，见下条）。
* **层级用色阶、不用透明度（L1）**：次要文本、边界、分层表面的层级一律取**已经算好对比度的色阶档位**；**不得**用调整 `opacity` / 透明度叠色的方式做出"次要"外观——叠色的最终对比度取决于底下是什么，**判不出来也改不回来**。**判定标准**：出现以透明度降低前景色或边界色的写法。
* **两套主题要成对给出、并各自判一次（L1）**：浅色与深色主题**成对定义**（同一组语义令牌各给一份取值），**各自**按上一条判对比度；**不得**只把浅色的值反相当成深色。**判定标准**：深色主题里出现"白底反过来即黑底"导致的饱和色刺眼或对比不足。
* **色彩不承担唯一信息（L1）**：状态、告警、校验结果**不得只靠颜色**表达——须同时有文字、图标或形状（WCAG 1.4.1）。**判定标准**：去掉颜色后，错误项与正常项无从区分。
* **焦点态必须可见、且属于令牌（L1）**：键盘焦点环的颜色、粗细、偏移取**同一处令牌**；**不得**在组件里 `outline: none` 后不补替代。**判定标准**：出现移除了默认焦点样式的写法而没有同一处定义的替代焦点样式。

== 排版与尺度（字号、行高、间距、控件高度）

* **字号只取一档序列（L1）**：字号从**一套固定的尺度**里取（正文一档、次要文本一档、标题若干档），**不随页面微调**；同一份产品在**同一端**内，同一层级的文本必须是同一档。**判定标准（任一命中即违规）**：① 同一层级文本（正文、表格正文、表单标签）在不同页面取了不同档；② 出现尺度外的数值字号；③ 端与端之间把**档数**改了（不是改每档的绝对值）。
* **正文不小于端的下限（L1）**：触摸端的正文不得小于该端可读下限；桌面端同理。**取值见 `specs/general/ui-tokens.adoc`**（本文件不复述数值——令牌取值的唯一落点在那里）。**判定标准**：把移动端正文按桌面端最小值直接套用。
* **行高跟字号成比例、不手写单处（L1）**：行高取**相对字号的倍数**（紧凑/常规/宽松三档之一），随字号自动变化；**不得**逐处写固定行高而产生"字大了行高没跟"。**判定标准**：同一段文本里字号变了而行高不变。
* **间距用序列、不用任意数（L1）**：间距取**等比或等差序列**（同一套令牌），**不得**出现序列外的数值。判定的可核对形态：全项目间距取值去重后能落进那一条序列；否则即违规。
* **控件高度按端取值、且只有一处来源（L1）**：按钮、输入框、列表行的高度取**分端的令牌**（触摸端更大、鼠标端更紧）；**同一端内**同一类控件高度一致，**不得**按页面改。**判定标准**：同一端内出现两种高度的同类控件，而差异无职能理由（如"主操作更大"必须有变体名）。
* **可点击目标不小于端的下限（L1）**：任何可点击目标的**实际命中区**（不是外观）不小于该端下限；相邻目标之间保留间隔。**取值见 `specs/general/ui-tokens.adoc`**。**判定标准**：图标按钮外观小于下限且未用内边距/伪元素扩大命中区。
* **层级用一套有限的层叠（L1）**：背景、表面、浮层、遮罩的层级取同一套**具名层级**，`z-index` 不写任意大的数字；**判定标准**：出现魔法数字层级，或同一层内出现两处不同取值。

== 分端：形状该不一样，标准不该不一样

* **端差异按「类别」给、不按端复制整份（L1）**：允许不同的只有**密度、版式、导航**三类，落成**一份端差异表**——每类各端取一档，其余一切取共用那一份；**不得**让某一端拥有一份与本端同构的完整取值清单（那是"每端一套体系"的隐蔽形态：看起来仍是三类差异，实际已经各写一份）。**判定标准（任一命中即违规）**：① 端差异表之外还有一处按端取值的完整副本；② 新增一个端时，改动的是"复制一份"，而不是在那唯一一张表里加一列；③ 端差异表里出现三类之外的项。
* **端差异只许落在三类（L1）**：端与端之间的差异**只有三类**——① **密度**（控件高度、间距、行高）；② **版式**（单列/双列/三栏、列表是否分栏、是否常驻侧栏）；③ **导航形态**（底部标签栏／顶部标签／侧边栏／命令面板）。**颜色语义、字号档数、组件职能、文案语气、图标语义不得端间不同**。**判定标准（任一命中即违规）**：① 差异落在上述三类之外（例如某一端把"删除"从危险色改成中性色）；② 三类之内也没有取值依据，各端随手定；③ 同一端内同时出现两种导航形态而无层级理由。
* **每个端一套骨架（L2）**：桌面端取「侧栏 + 主区（+ 可折叠辅助区）」、平板取「按宽度在单栏与双栏间切换」、移动端取「单列 + 底部导航 + 推入式详情」。**判定的不是长得像谁，而是：进入某一层内容需要几次导航动作、返回路径是否唯一可预期。**
* **响应式按内容断、不按设备断（L1）**：宽度断点按**布局撑不住的位置**定（放不下两栏、侧栏挤压主区宽度），**不按设备型号或品牌**；断点取值落在令牌一处，页面**不各写一套**。**判定标准**：出现按设备名（"iPad 竖屏"）判定的分支，而同一宽度在不同设备上表现不同。
* **同一功能在各端都要有、且能完成（L1）**：不得因为"这一端不好做"就缺一个功能，而用"请到桌面端操作"代替——**除非该功能本身就是桌面专属能力**（多窗口、本地文件批处理、全局快捷键），此时须在缺它的那一端**给出替代路径与说明**。**判定标准**：同一任务在一个端上无可达入口、也没有说明。
* **进入即知在哪、怎么回（L1）**：多级界面须**始终可回答两问**——当前在哪一层、返回去哪；移动端用返回栈与标题、桌面端用选中态与面包屑各取其一，但**每端内只有一种**。**判定标准**：同一端出现两种返回语义（一处返回上一级、一处回到首页）。

== 交互（按输入设备定，不按端定）

* **指针类与触摸类分两条判据（L1）**：交互规则按**输入设备**判，不按平台判——**有精确指针**（鼠标/触控板/笔）时按「指针类」写；**只有粗指针**时按「触摸类」写；两者都支持的端须**同时满足**。**判定标准**：把"悬停才出现"的关键操作放到触摸端。
* **指针类：高频动作要快、命中要准（L1）**：① 常用操作的可点区域按指针端下限，**允许更小但不得小于下限**；② 高频操作要有**键盘等价物**；③ **悬停可以出现辅助信息，但不得承载唯一入口**——凡只能靠悬停发现的入口，须另有可见或键盘可达的等价路径；④ 右键/上下文菜单是**加速器**，不是唯一入口。**判定标准（任一命中即违规）**：① 关键入口只在悬停时出现；② 高频操作只能鼠标完成，键盘无法到达（WCAG 2.1.1）。
* **触摸类：手势只做加速、不做唯一入口（L1）**：滑动、长按、双指这类手势**可以**是快捷方式，但**每个手势动作都要有一个可见的等价控件**；**不得**把删除、归档这类**破坏性或不可见后果**的操作只挂在手势上。**判定标准**：某一功能只能通过手势到达，或手势产生不可撤销后果而无确认。
* **目标要够大、间隔要够开（L1）**：触摸端可点目标与相邻间隔按该端下限（见令牌）；**判定标准**与「可点击目标不小于端的下限」同一条。
* **反馈要即时、且与输入方式匹配（L2）**：按压/悬停/焦点三种态**各自**要有可见变化，且不共用同一种外观（否则键盘用户看不出焦点）。**判定标准**：三种态在界面上难以区分。
* **危险操作按可逆性分档，不按弹窗多少（L1）**：可撤销的操作用**撤销**替代确认框；**不可撤销**的才要确认，且确认里要写清**作用对象与范围**（"删除 3 条"而非"确定吗"）。**判定标准（任一命中即违规）**：① 每个操作都弹确认（用户很快学会盲点确认，等于没有）；② 不可逆操作只有"确定吗"。
* **键盘与读屏是基线、不是加分项（L1）**：所有交互都能被键盘到达并按顺序前进、焦点可见、语义结构（标题层级、表单标签、按钮与链接职责）正确、图标按钮有可读名称。判据按 WCAG 2.2 的对应条取。**判定标准**：Tab 走不到某个操作，或读屏读出"按钮"而无名称。
* **动画只表达因果、并且可以关（L2）**：动效用于表达"从哪来、到哪去、什么变了"；同一动作时长取令牌一处；**系统声明减少动效时关掉非必要动画**（WCAG 2.3.3 的取向）。**判定标准**：动画成为完成操作的前置（等动画放完才能点）。
* **等待有形状（L2）**：短等待给**就地**反馈（控件自身进入忙态），长等待给**可中断**的进度与取消入口；**不得**用整屏加载遮罩盖住已经能用的部分。**判定标准**：一屏没取完就整屏锁死。

== 通用件与参照（借用现成方案时，什么可以借、什么必须留成本项目自己的）

* **借用外形可以，借用体系要留成自己的一处（L1）**：可以取现成的主题包、品牌色板、组件皮肤当**起点**，但它们只作为**取值来源**落进本项目那一份令牌；**不得**让两个以上的现成体系各承担一半界面（一半取这套的主题、一半取那套的组件默认外观），也不得在页面里直接取用某个外部体系的名字/类名当成本项目的形态来源。**判定标准（任一命中即违规）**：① 同一职能（按钮、输入框、卡片）的外观来自两个体系，且各自生效；② 页面层级出现外部体系专有的类名或令牌名，而未落到本项目自己的令牌；③ 以「这套主题好看」为由整页引用外部主题而不落令牌。
* **抄一份清单不算落地：清单之外还要有"落到本项目"的落点（L1）**：现成设计规范给的是**清单**（颜色、尺度、组件、状态），抄进来只是**原料**；本项目须各自回答"**这个组件在本项目里长什么样、什么时候用它、什么时候不该用它**"。**判定标准（任一命中即违规）**：① 项目里只有一份抄来的令牌/清单，没有任何"这个组件怎么用"的落点；② 组件有多个同族候选（普通按钮/主按钮/图标按钮、普通弹窗/确认弹窗），而没有任何一处说明该选哪个；③ 「怎么用」散在几十个页面里，各页各写一遍。
* **外部体系不得成为第二个可编辑落点（L1）**：观感只能由**本项目那一处**决定——外部包升级、换主题、改配置都**不得**直接改变本项目的观感（否则同一次视觉改动有两个操作入口，事后无从核对是哪一个生效）。**判定标准**：升级外部依赖后界面观感变了，而本项目一处都没改。
* 依据（标准名/编号）：ISO/IEC 25010（可维护性与一致性）、ISO/IEC/IEEE 29148（判定须单一、可验证）、ISO 10007（配置项与变更须有单一、受控的来源）、各平台设计规范与无障碍规范的**机制**（主题变量、设计令牌、组件变体）。**「令牌按共用/分端两档分文件、端差异只落一张表」「借用外形可以、体系要留成自己的一处」「清单之外必须有"怎么用"的落点」是本集合的判据化取舍**——各家设计系统与 AI 编码规范项目普遍给的是**组件契约、清单与使用规则**的形态，**未**规定「多个端的令牌该按端分文件还是按类别分文件」，也**未**把「抄来的清单」与「落到本项目的用法」分成两件事。

== 组件的通用形态（自建件按这类东西本该长成什么样）

* **一个组件一个外观来源（L1）**：同一组件的外观与行为**只有一处实现**，差异一律开成**变体**（尺寸、层级、状态各一档），**页面不复制组件再改样式**。判据本体在 `specs/general/coding.adoc`「抽象与接入成本」，本条只补**形态取值**：变体名按"职能 / 尺寸 / 状态"分三档，不按页面名取（不叫「首页按钮」）。**判定标准**：出现以页面或场景命名的变体。
* **状态要全、且成套（L1）**：每个可交互组件定义齐**默认、悬停、按下、焦点、禁用、加载、错误**（适用的那些）七态；**判定标准**：出现未定义的态（例如提交中按钮还能点第二次）。
* **空、加载、出错三种界面是组件、不是特例（L1）**：列表与表格须成套给出空态（有引导动作）、加载态（骨架或就地忙态）、错误态（可重试）；**不得**让空白页代替其中任何一种。**判定标准**：任一状态缺失或以空白呈现。
* **表单：标签常驻、错误就地（L1）**：标签不靠占位符代位（一输入就消失）；错误提示挂在**该字段处**并说明**怎么改**；分组有可辨标题（ISO 9241-143 的取向）。**判定标准**：只用占位符当标签，或错误只在页面顶部汇总而无字段定位。
* **图标与文案一套语义（L2）**：同一动作在同一产品里用**同一个图标与同一个词**，不因端或页面换词（"删除/移除/清除"三选一）。**判定标准**：同一动作出现两个词或两个图标。

== 承载与呈现（同一个操作开成什么、一条数据怎么看、一列多宽）

前四节定的是「一个界面内部的取值」。本节定**界面与界面之间**的那层选择：同一个动作该开成什么容器、一条有结构的数据该显示原始内容还是格式化后的形态、一张表里每一列取多宽。三者的**决策路径与取值口径**在 `specs/general/ui-patterns.adoc`（**模板文件**，给的是可复制的判读顺序与取值），判据本体在本节。

* **容器按「进入与返回的成本」判，不按内容多少判（L1）**：同一个操作在**就地、浮层提示、弹窗、抽屉/检查器、常驻侧栏、整页、新窗口**之间取值，判据是**进入这一层要几次动作、返回路径是否唯一可预期、以及「背后内容要不要继续可操作」**；同一层级里**同一类动作只用一种容器**，换了要说明理由。**判定标准（任一命中即违规）**：① 同一类动作（看一条详情、改一处配置、做一次确认）在同一层级用了两种容器而无理由；② 详情开成新窗口或整页，而它没有「与主界面并排对照」或「多文档并存」的用途；③ 破坏性确认被放进抽屉或整页（确认必须是**最短路径**）；④ 容器嵌套超过两层（第三层起改成就地或侧栏——层数一多，用户就不知道自己在哪、按返回会回到哪）。
* **「背后是否还能操作」决定模态，不决定外观（L1）**：打开后**不该继续操作背后内容**的用**模态**（并把焦点陷阱与焦点归还做全）；**要与背后数据边看边改**的用**非模态**（抽屉、侧栏），且它**不夺焦**。**判定标准**：模态里没有焦点陷阱或关闭后焦点丢失；非模态一旦打开就把背后内容挡住或锁死。
* **结构化值：原文与读法并存，编辑不得重新序列化（L1）**：凡内容本身有结构（JSON、XML、YAML、SQL、表达式、富文本、含控制字符的长文本），界面上须**同时**回答两件事——**原文（存了什么字节，复制与回传的唯一来源）**与**结构视图（这是什么、错在哪，只读的读法）**；编辑走**整份粘贴覆盖**或**逐处片段替换**时，都**只改被改的字节**，**不得**因为「保存」而重新格式化、重排键序或统一转义；美化必须是**显式且可撤销的编辑**。校验失败须给**位置**（行号、偏移或路径）而不是只给「格式不对」。**判定标准（任一命中即违规）**：① 只有格式化视图，用户无法确认原文；② 保存动作顺带重写格式；③ 校验失败只给一句「格式错误」而无位置；④ 界面上「看起来一样」的两份值被判成「没有改动」而实际字节不同。
* **表格列宽：自适应为默认、用户覆盖优先、上下限都有一处（L1）**：列宽**自适应**（按列名与采样内容估宽并夹在**下限与上限**之间），**下限**由「列名可读 + 排序/筛选入口可点」定、**上限**由「单列绝对上限 + 视口占比上限」两重约束定；**用户拖动过的宽度优先**并按对象记住；标识列（行号、勾选列）在横向滚动时固定。**判定标准（任一命中即违规）**：① 列宽写死且长值一律截断；② 自适应没有上限，一条长文本把整行撑到要横向滚三屏；③ 用户拖过的宽度重开就丢；④ 列宽/行高在三处各有一份取值；⑤ 列被隐藏到一张都不剩时不给回退入口。

== 界面状态的保留与恢复（关掉再打开，该回到哪）

上一节定的是「一次操作开成什么」。本节定**两次会话之间**的那一层：用户关掉窗口、切到别的应用、隔一天再来时，界面该**记得什么、不记得什么**。判据落在**恢复的后果可不可接受**，不落在「记不记得住」。

* **「回到上次」按后果分两档（L1）**：**位置类状态**（窗口位置与尺寸、最后打开的标签或文档、列表滚动位置、当前选中的视图与排序）恢复是**默认**——它们不产生动作，错了也只是再点一次；**动作类状态**（上一次查询自动重跑、上次未提交的编辑自动提交、上次的危险操作被续做）**默认不恢复**——它们会产生**用户没有再次表达过的副作用**。**判定标准（任一命中即违规）**：① 恢复动作类状态而用户没有显式要求（重开即执行上次的 SQL、重连即重发上次的写入）；② 位置类状态每次重开都丢（列宽、标签、窗口尺寸退回默认）；③ 用同一个开关同时控制两档（关掉「记住查询」把窗口位置也一起关了）。
* **保存的是「上次可用的那份状态」，不是「刚才那一瞬」（L1）**：状态落盘只落**能自行恢复到可继续使用的**那一份——引用了已经不存在的对象（连接、表、文档被删）、读不回来的视图，须**降级到上一档可用状态并说明**，不得留在无法操作的状态里。**判定标准（任一命中即违规）**：① 重开即报错、或打开一个指向已删对象的空壳；② 静默地把失效项替换成别的东西（用户以为还是原来那一条）；③ 恢复失败既不说明也不给「从默认开始」的出口。
* **状态落在本机、按对象记忆、可清（L1）**：这类状态属**本机偏好**（按账号与本机存），不写进服务端的共享状态；按对象（连接 / 表 / 文档）各记一份；须有**一处**「清掉记忆」的入口，且清掉后与首次打开一致。**判定标准（任一命中即违规）**：① 换个窗口大小或换个屏幕就再也摆不回原样；② 用户在某台机器上拖过的布局跟着账号跑到别的机器上（视口不同，恢复后反而不可用）；③ 没有清掉记忆的入口。
* **恢复要能看出来发生过（L2）**：恢复不是「凭空出现的内容」——该说明「这是上次留下的」并给一步回退（重新加载、清空、从默认开始）。**判定标准**：用户无法判断眼前的内容是刚刚取到的还是上次缓存的旧内容（与 `specs/general/coding.adoc`「缓存」的「先给缓存再换在线、各标来源与多久前」同源）。

== 新增或改界面时的核对清单（按序判，命中即改）

. 令牌在不在：要用的颜色、字号、间距、控件高度有没有落在令牌一处？该落共用那份的（颜色、字号、间距）有没有漏到某个端文件里？
. 语义对不对：视觉层级是否来自**色阶与字号档**，而不是透明度与饱和色？
. 对比度够不够：正文 7:1、大号文本与必须可见的图形 4.5:1 / 3:1（值见令牌模板）？
. 端差异是否只落在密度、版式、导航三类？端差异是不是**只在一张表里**加一列，而不是新开一份端文件？
. 输入设备是否被尊重：指针端有键盘等价、触摸端手势有可见等价控件？
. 目标够不够大、间隔够不够开？焦点可见？
. 七态齐不齐？空/加载/出错三态有没有落点？
. 破坏性操作是否按可逆性分档？
. 组件怎么用有没有落点：该用哪个同族候选、什么时候不该用，是不是写在一处，而不是散在各页面里？
. 容器判过没有：这个动作该就地、弹窗、抽屉、侧栏还是整页？同一层级是不是只有一种容器？模态只给了该模态的那些？
. 结构化值的原文还在不在？保存会不会顺手把格式重排了？校验失败给位置了吗？
. 表格列宽有上下限吗（写在一处）？用户拖过的宽度会不会丢？全部列隐藏后能不能回来？
. 关掉再打开回到哪：位置类状态恢复了吗？动作类状态有没有偷偷重跑？引用已失效的对象降级了吗？清记忆的入口在哪？

== 风格与调性（同一套令牌之外，这一件东西整体给什么感觉）

**风格不是一个定语，是一组取值**：说"这个界面走极简"时，它成立的前提是**令牌里已经落下了极简该有的那些取值**（色阶跨度、字号档的对比、间距留白的上限、圆角的档位、层次用边界还是阴影、动效的幅度），而**不是**在某个类名或设计稿备注里写一句"极简"。故本节的判据落在"**风格是否落成了取值**"，不落在"风格叫什么名字"。

* **风格由使用场景与任务定，不由品类与流行定（L1）**：先写**谁在什么光线下、用什么设备、连做几次、出错代价多大**，再由这些事实挑风格族；**不得**由"这是个金融/医疗/教育产品，所以该用某种色"这类品类联想定风格，也不由当前流行定。**判定标准（任一命中即违规）**：① 风格选择的理由只有品类、命名、竞品或"看起来高级"；② 同一个产品里不同模块各走一套风格家族而无职能理由；③ 风格在令牌落地之前就已定稿（先有词、后找值）。
* **一套产品只取一个主风格族，差异可闻（L1）**：主风格族**只取一个**（辅以至多一个受控变体，且写明变体只改哪几项）；**不得**两个风格家族各承担一半界面。**判定标准（任一命中即违规）**：① 两处对照的界面分别属于两个风格族且都在生效；② 一个新页面"换个风格试试"而旧页面不动；③ 变体没有写明只改哪几项。
* **风格必须落成令牌、并且可判（L1）**：每个风格族要写的**必写项**（色阶与饱和度取向、字号档的跨度与字重、间距与留白的节奏、圆角的档位、层次的表达、动效幅度、图文比例、装饰密度）逐项落进**同一处令牌**；**判定标准（任一命中即违规）**：① 风格只以文字描述存在于设计文档，令牌里没有任何取值对应它；② 换个风格时要改的是页面（而不是那一处令牌）；③ 同一风格族内两个页面在同一必写项上取了不相容的值（如一处靠边界分层、一处靠阴影分层，而令牌里没有规定用哪种）。
* **风格族按"任务与场景"取，并按"不要用于"排除（L1）**：可取的风格族与其"适合 / 不适合"的对照见 `specs/general/ui-styles.adoc`（**模板文件**，给的是可复制的候选清单与每族的必写项，判据本体在本节）。选型**先按上面的场景问句判、再回清单找最近的一族**；**清单不是允许列表**——清单外的一族同样可用，但必须同样写全必写项并给出适合/不适合的理由。**判定标准（任一命中即违规）**：① 只写风格名、不写适合与不适合；② 反着清单里的"不要用于"用（例如把极低对比度的柔和风格用在需要长时间读数与无障碍强要求的界面上）而不说明为什么这一条不适用；③ 把清单当"必须从中选一个"的封闭集合。
* **装饰性手法要过三问（L1）**：任何装饰性手法（渐变、玻璃、光晕、扫描线、噪点、霓虹、贴纸、硬投影）在落地前须依次回答：① 它**承担信息或已被场景要求**吗？② 它与**令牌里的取值**一致吗？③ 关掉它，这一屏是否仍然成立？三问里有一问答"否"即不得采用。**理由**：这些手法从"整页装饰"退回"局部质感"时最容易被无限扩张，而它们对对比度、可读性与性能的代价是可测的、收益是不可测的。**判定标准（任一命中即违规）**：① 装饰手法出现在**所有**区块（等于背景）；② 装饰性手法降低了正文对比度而未在令牌处标注可读性代价；③ 用装饰掩盖信息层级不清（层级靠色阶与字号档，不靠发光）。
* **风格的"通用陷阱"是默认值，不是禁令（L2）**：以下是 AI 与模板库最常给出的默认形态——同尺寸的「图标 + 标题 + 一段文字」卡片网格、大数字打头的首屏、每节标题上方的小字引导语（eyebrow/kicker）、渐变文字、装饰性玻璃与模糊、`4px 4px 0` 式硬投影、用 emoji 或 Unicode 字符充当图标、把等宽字体当"技术感"、按品类默认深浅色。**当没有别的理由时，不要取它们**；确实要用，须说明它是被场景要求的那一项。**判定标准**：命中其中一项而没有任何场景理由。
* **观感从哪一层来，只有一处（L1）**：观感的可编辑来源只有**本项目令牌**那一处；风格切换（浅/深、品牌换色、换风格族）**只改那一处**。**判定标准**：换风格要动页面、组件或第三方主题配置的第二处。

== 界面上的文字（文案是界面材料，不是附属品）

* **控件写它会做什么，出错写问题与出路（L1）**：按钮与链接名**写动作与其对象**（"保存草稿"而非"确定"），错误提示**说清发生了什么、可怎么办**，不写"操作失败""非法输入"这类只说结果不说原因的话。**判定标准**：出现无法预测后果的按钮名，或只有结果没有出路的错误提示。
* **用户的话优先于我们的内部叫法（L1）**：界面用**用户认得出的词**，不用内部模型名、表名、缩写与代号；同一个东西在界面上**只有一个叫法**，不因模块或端换词。**判定标准**：界面出现只有实现者懂的内部名称；或同一对象在两处叫两个名字。
* **空、加载、出错、成功、危险五种文案成套（L1）**：每种状态都有**写出来的**文案，且都给出**下一步动作**；空态不写"暂无数据"就完事。**判定标准**：任一状态缺文案、或只有一个词。
* **语气按产品与场景定，一处定义（L2）**：语气（人称、称呼、正式度、活泼度、术语密度）在一处写明，所有页面与各端照它写；**同一产品各端不各定一套**。**判定标准**：同一产品里一处说"您"一处说"你"、一处专业口吻一处卖萌口吻而无场景理由。
* **文案有唯一落点、可被检索与复用（L1）**：面向用户的文案取**同一处文案资源**（键值或组件内的文案属性），**不得**硬写进分支与模板里；同一句话在两处各写一份即第二份来源。**判定标准**：模板/组件里出现面向用户的字面串，而项目有文案资源落点。
* **长度与语言无关地留出余量（L1）**：文案按**最长语言**留位（不按中文或英文长度定宽），**不靠截断**表达；不可腰斩的词标出可断点。**判定标准**：目标语言下出现截断、溢出或被挤压的层级。

**本节只管文案怎么写**：这条提示**该不该出现、走哪个通道、会不会打扰人、有没有留痕**是另一层判据，见 `specs/general/feedback.adoc`——两处各写一套时，最常漏的是后者（文案写得清楚，而每次轮询失败都弹一次）。

== 改动界面时的核对顺序（按序判，命中即改）

. 场景先写出来：谁、在哪、用什么设备、连做几次、出错代价多大——风格与密度都由它推。
. 风格族只有一个，必写项都落在令牌里了吗？换风格只需动那一处吗？
. 装饰性手法过三问了吗？通用陷阱里有没有一项是没有理由就取了的？
. 文案：动作名说清对象了吗？错误给出生路了吗？五种状态成套了吗？术语是不是用户的话？
. 文案落在唯一的那一处资源里了吗？长度按最长语言留位了吗？
. 对比度与可读性：装饰有没有压低正文对比度？风格族本身的反面（低对比、高饱和）有没有被点名并核过？

== 依据（标准名/编号）

WCAG 2.2（1.4.1 色彩不作为唯一信息、1.4.3 对比度最小值、1.4.6 增强对比度、1.4.11 非文本对比度、2.1.1 键盘、2.3.3 动画交互、2.4.7 焦点可见、2.5.8 目标尺寸最小值）、WAI-ARIA Authoring Practices（组件行为与键盘交互）、ISO 9241-110（对话原则：符合预期、自解释、可控、容错）、ISO 9241-112（信息呈现）、ISO 9241-143（表单）、ISO 9241-400/410（物理输入设备的人体工效学：输入设备与交互原则）、ISO 9241-171（软件无障碍）、ISO 9241-9（非键盘输入设备的要求，含目标尺寸与触摸/指针精度）、ISO/IEC 25010（易用性、可访问性属产品质量特性）、Material Design 3 与 Apple Human Interface Guidelines 与 Fluent 2（三家的**触控目标下限、字号尺度、密度分档**口径：Material 的最小触控目标、HIG 的可点击尺寸与动态字号、Fluent 的密度档与 4 px 网格；均为**产品设计规范**、非标准）、W3C WCAG 的补充技术文档（Understanding SC 1.4.3 与 2.5.8）、Google Material 的触控目标与无障碍一节、Microsoft Fluent 2 的密度与网格一节。**「容器按进入与返回的成本判、且同一类动作在同一层级只用一种容器」「结构化值的原文与读法并存、编辑不得重新序列化」「表格列宽自适应且上下限只有一处」是本集合的判据化取舍**——各家给的是本家的容器清单（dialog／drawer／sheet／inspector）与表单、表格推荐用法，没人回答「同一动作何时该换容器」，也没人说「可编辑的格式化视图」有风险、自适应列宽的上限该怎么取。**「界面状态按后果分两档恢复：位置类恢复、动作类不恢复」「保存的是上次可用的那份状态，失效对象降级并说明」「状态按对象记在本机且可清」是本集合的判据化取舍**——WCAG 2.2 与 ISO 9241-110 给的是「可预期、可控、容错」的原则（SC 3.2.6 Consistent Help 一类讲的是跨页一致，不涉恢复），各平台设计规范给的是本家的窗口与标签恢复能力，**未**有人把"哪些状态可以恢复"按**是否产生副作用**分成两档，也**未**规定失效引用该降级而不是报错。**「一个可访问基线 + 一套令牌 + 端差异只许落在密度/版式/导航三类」「对比度按文本大小分两档并取增强值为正文下限」「层级用色阶不用透明度」「差异按输入设备而不是按平台判」「令牌按共用/分端两档分文件、端差异只落一张表」是本集合的判据化取舍**——通行设计规范各自给出本家的目标尺寸与字号尺度，**未**规定「多端之间哪些东西必须一致、哪些才允许不同」，也**未**把「按透明度做层级」列为禁忌（各家只给机制与推荐值）；WCAG 只定下限，**未**规定取哪一档作为产品默认。
