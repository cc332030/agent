= 脱敏规范（通用层，跨场景）

适用于**所有语言、所有项目**。凡是**要写出一份可能被别人读到的内容**、而它可能取自**用户或用户的运行环境**时，本条即生效——落点含**源码与用例、文档与注释、提交信息、日志与报错、对外响应、Issue/合并请求正文与评论、截图与附件、汇报与评审意见**。它与 `specs/general/security.adoc`「敏感信息」是同一条底线（那份管**代码运行时不许泄漏什么**，本文件管**写出来的内容里不许出现什么**），判据形态不同、互不替代。依据：ISO/IEC 29100（隐私保护框架）、NIST SP 800-122（PII 保密性指南）、NIST SP 800-188（去标识技术）、OWASP ASVS「Data Protection」与「Security Logging and Error Handling」、OWASP Logging Cheat Sheet。

== 取值：该换成什么（先判类别、再定换法）

判定顺序固定为：**识别 → 归类 → 换法**。识别问句是「**这个取值是不是来自用户的真实环境，或能落回某个真实的人、真实的内网**」——是则按类别换掉，不是则原样保留（自造的示例名、公共的示例域名、语言与框架自己的字面量都不在此列）。

* **换法按类别取（L1）**：同一份信息在整份内容里**换成同一个虚构值**（前后可对读、不出现两套写法）——
** **标识与名称类**（库名/表名/字段名/服务名/接口路径/项目与模块名/主机名/域名/账号）→ 换成**同类型的虚构取值**，形态照旧（命名规则、层级、长度量级不变）。
** **地址类**（IP、内网域名、地址:端口）→ 换成**约定用途的占位地址**（如按 RFC 5737 的文档用地址、按 RFC 2606 保留的示例域名），不得换成另一个真实可达的地址。
** **人可直接落到某人身上的信息类**（姓名、手机号、证件号、银行卡号、邮箱、精确地址、工号）→ **删掉**（不需要这个取值也能成立的，就别写）；确需展示形态时用**同类型的虚构取值**，不得用「真值只改几位」的写法。
** **凭据类**（口令、令牌、私钥、API Key、连接串里的账号口令）→ **不写**，一律换成**指向来源的引用**（环境变量名、密钥项名），任何脱敏形态都不构成把它写出来的理由。
** **业务与运行事实类**（真实业务编号、订单号、生产数据统计、内部版本与部署细节、内部报错原文）→ 只保留**结构与形态**（位数、格式、量级），取值换成虚构值。
* **判定标准（任一命中即违规）**：① 用环境里取到的真实取值**原样**出现（含只替换其中一段的写法）；② 换的是**位置**而不是取值（真实值挪进注释、文档、提交信息、代码块、示例、测试断言、截图）；③ 换后**丢掉了触发原判据所需的形态**（位数、命名规则、层级被换没了，问题不再被复现）；④ 同一份信息在不同落点用了**互不相同的虚构值**（对读时读成两件事）。
* **边界**：本条只约束**能从用户侧带出来的信息**——公开标准与公开文档里的示例、语言与框架的通用字面量、按通用命名规则自造的示例名（`sys_user`、`demo_order` 一类）都不在此列；也**不放宽**其他规范对真实形态的要求（如 `specs/general/testing.adoc`「用例编写」的「最真实场景优先」）——换掉的只是取值，形态照旧贴近真实。

* **范围：一次全量清扫，不留无主落点（L1）**：发现一份真实信息后，须按**全仓检索**核它出现过的每一处（源码、用例、注释、文档、配置样例、提交信息、Issue/PR 正文与评论、截图与附件），逐处换掉——**只换用户点名的那一处不算脱敏**。判定标准：交付前答不出「这份取值还在哪些落点出现过」，即未达成。
* **用户提供过不构成授权（L1）**：用户把问题连同真实信息贴过来，**不**表示可以把它们写进产物；脱敏的**唯一例外**是用户**主动声明**要按真实取值处理的那一处（声明**只对当次成立**、**不得泛化**到同一份信息的其他落点，也不得延续到下一个任务）。
* **拿不准时按敏感处理（L2）**：判不出「这个取值算不算真实环境信息」时，**按需要脱敏处理**并在交付说明里写一句「此处已按脱敏处理、如需真实取值请声明」——写出去无法收回，多换一处只是麻烦，少换一处是不可恢复的泄漏。

== 落点：每一处都是落点

* **凡会被别人读到的地方都算落点（L1）**：判定标准（任一命中即违规）——① 真实取值出现在**版本控制的文件**里（源码、用例、配置、文档、脚本、模板）；② 出现在**提交信息**或**分支名/标签名**里；③ 出现在**平台上的 Issue/合并请求、评论、评审意见**里；④ 出现在**外发的产物**里（日志、报错响应、导出文件、截图、附件、汇报）。**"删掉再提交"不构成脱敏**——已进提交历史的真实取值须**改历史**处置（改写口径见 `specs/general/version-control.adoc`「脱敏后的历史处置」）。
* **日志与报错按字段脱敏（L1）**：日志、异常信息与对外报错响应**不得**出现凭据、证件号、卡号、手机号一类的原值；确需定位，按字段做**掩码**（保留足以定位的部分，如末四位），且**掩码在写入前完成**——先写全值再事后清洗，全值已经落盘，等于没做。依据：OWASP ASVS「Security Logging and Error Handling」（敏感数据须按保护级别决定可否记录，许可记录时只以散列或掩码形态出现）、OWASP Logging Cheat Sheet（内网名称与地址、连接串、PII 须在记录前处理）。完整口径见 `specs/general/security.adoc`「敏感信息」。
* **对外响应只给必要字段（L2）**：接口响应不得为了省事回整个数据对象——按用途只给必要字段、必要时掩码（依据：OWASP ASVS「Data Protection」的唯一必要数据原则）；数据库实体不进对外契约的判据见 `specs/general/coding.adoc`「数据契约的载体（数据库实体类不进对外契约）」。

== 截图与附件（同样是落点）

* **截图先核后发（L1）**：把画面、日志片段、控制台输出贴到任何地方之前，须先核**画面里有什么**——地址栏与内网域名、账号与用户名、真实数据行、令牌与连接串、内部路径与版本都在其中；能取局部（页面/元素/窗口）就不取整屏，能复现就不贴真实环境的截图。判定标准（任一命中即违规）：① 图里含上述任一类信息而未处理；② 以「看不清」为由跳过核对——缩放后仍可辨认即算泄漏。

== 依据与已知取舍

外部材料只给**方向与下限**——个人信息应最小化、去标识后仍须可用（ISO/IEC 29100、NIST SP 800-122、NIST SP 800-188 均指向此）；日志侧另由 OWASP ASVS 与 OWASP Logging Cheat Sheet 给出「记录前处理、只以散列或掩码形态出现」。**没有任何材料**规定「一个真实标识都不许留」「用户贴过来的也要换」「换位置不算脱敏」「截图也要核」——这些**判据化取舍**是本集合自己收严的部分。
