= Bash/Shell 脚本规范（技术栈层）

以下规范适用于 bash/sh 等 POSIX shell 脚本。跨所有脚本语言的通用格式规则见 link:../general/script.adoc[]，脚本中的编码规则遵守 link:../general/coding.adoc[]；本文件只收录本栈专属规则。换行符（行尾）的权威口径见 link:../general/encoding.adoc[]「换行符」，本文件只重申本栈的取值。

== 行尾

* **LF，不得 CRLF（L1）**：`.sh` 脚本与以 bash/sh 为 shebang 的脚本一律 **LF**，禁止落盘 CRLF（Windows 上编辑后也须存回 LF）——`bash`/`sh` 会把行尾的 `\r` 当作命令或参数的一部分，典型报错 `bash: $'\r': command not found`、`\r': No such file or directory`；Windows 上运行须用 Git Bash/WSL 等提供 `/bin/sh` 的环境，不要改用批处理绕开（依据：POSIX 对文本行以 `\n` 分隔的定义；完整判据与检出配置见 link:../general/encoding.adoc[]「换行符」「跨平台检出」）

== 文件头与解释器

* shebang 用 `#!/usr/bin/env bash`（优先用 env 定位解释器，便于不同环境）；必要时 `bash -eu` 也可在 shebang 中体现严格模式（通用 shebang 与可执行要求见 link:../general/script.adoc[]「文件格式与编码」）

* **无文档注释机制，文档头用多行块注释（L1）**：`bash`/`sh` **没有**专门的文档注释语法（`#` 行注释与块注释都是普通注释），故脚本的文档头按 link:../general/script.adoc[]「脚本文档的承载位置与协作粒度（默认写进脚本自身）」的**第二优先级**承载——用**连续多行注释**（无块注释语法时即一组连续 `#` 行）放在文件开头（shebang 之后），**不得降格成零散的单行注释**（普通注释是第三优先级、只用于补充说明）。**判定标准**：文档头的定位/用法/参数/边界被拆散成多处零散 `#`、或只留一行 "usage: ./foo.sh"——命中即违规。

== 严格模式

* 脚本开头须启用 shell 严格模式（依据：Google Shell Style Guide 与 ShellCheck 的诊断 `SC2086` 等建议），常用组合：
  `set -euo pipefail`
  ** `-e` 遇到错误即退出；`-u` 使用未定义变量即报错；`-o pipefail` 管道中任一命令失败即整体失败
* 对预期会失败的单个命令（如用返回码判断的命令），显式捕获其退出码或在命令后追加 `|| true` 并按需判断，避免 `set -e` 误杀；不得靠关闭 `set -e` 来容忍错误

== 变量与引用

* 使用变量一律加引号（`"$var"`），防止空格/通配符被展开（依据：POSIX shell 的字段分割/路径名展开语义，ShellCheck SC2086）；数组元素、路径等尤其要加引号
* 使用未定义变量是错误：先给默认值再使用（如 `"${VAR:-default}"`），或确保已赋值；避免裸 `$var` 直接进入命令
* 命令替换用 `$(...)` 而非反引号，便于嵌套与阅读

== 参数处理

* 用 `getopts` 或位置参数 + 前置校验处理命令行参数；必填参数缺失时输出 `usage:` 提示并退出非 0
* 对每个位置参数做存在性/合法性校验，解析后再使用；引用参数变量时统一加引号

== 错误处理

* 依赖外部命令时检查其返回码（结合 `set -e`，或在需要时 `if ! cmd; then ...; fi` 显式处理），失败时输出错误并退出
* 临时文件：写入目标项目 `tmp/`（通用规则见 link:../general/script.adoc[]「安全」），bash 中用 trap 在退出时清理（`trap 'rm -f "$tmp"' EXIT`）

== 作为跨环境入口（Windows 与 Linux 并存时）

* **`.sh` 只做薄壳（L1）**：脚本要在多个操作系统上跑时，逻辑**只写一份**放跨平台逻辑代码（见 link:../general/script.adoc[]「跨环境脚本（入口 + 跨平台逻辑 + 实现语言取舍）」），`.sh` 与 `.bat` 只作为**入口**（Windows 侧入口的写法见 link:batch.adoc[]「作为跨环境入口（Windows 与 Linux 并存时）」）——定位解释器、`"$@"` 原样透传参数、以逻辑代码的退出码 `exit`（**不得**在入口里做参数解析、路径拼装、分支判定，也**不得**为 Linux 另写一遍逻辑）。**以逻辑代码的绝对路径调用**（如 `exec python3 "$(dirname "$0")/foo.py" "$@"` 一类形态），不 `cd` 到脚本目录，保留调用方的工作目录。
* **入口的注释只写入口自己（L1）**：`.sh` 的头部注释只写**入口用法与它调用的逻辑代码**，**不得复述**逻辑层的参数语义、默认值、行为与副作用——同一份契约写两处即两处真源（改逻辑不改入口注释，读者按入口注释用会得到错误结论；通用条见 link:../general/script.adoc[]「脚本头部注释（文档头）」）。
* **`.sh` 的位置与命名（L1）**：与逻辑代码**同处一目录、主名相同**（逻辑 `foo.py` → 入口 `foo.sh`），**不另建 `bin/`、`script/`、`linux/` 目录**；开启可执行位并在首行写 `#!/usr/bin/env bash`，使调用方**只输 `./foo.sh` 就能跑**——**不得**要求调用方加 `bash`/`sh` 前缀（那是入口没写明 shebang 或没设可执行位）。
* **入口语言选择（L1）**：Linux/macOS 入口**取 `.sh`**（系统自带 POSIX shell/bash），**不得**用需要另装的运行时当入口（如用 `.ps1` 当入口、或要求先装 PowerShell/pwsh）；入口里**不得**为“让逻辑跑起来”自加命令（先 `cd`/`mkdir`/`chmod`/安装依赖再调逻辑）或给逻辑代码固定塞参数——判据与例外见 link:../general/script.adoc[]「跨环境脚本（入口 + 跨平台逻辑 + 实现语言取舍）」。

== 其他

* 代码结构与命名遵守 link:../general/coding.adoc[]；shell 脚本中避免不必要的子进程与管道滥用，保持可读性

== 系统包源（apt / apk / yum，CI 镜像内）

* **在容器/CI 镜像内取系统包时按次序选源（L1）**：镜像是"未配置过源"的典型场景（多数官方镜像的 `/etc/apt/sources.list`、`/etc/apk/repositories` 指向境外源）——此时按 link:../general/dependency.adoc[]「包源（包仓库/镜像站）的选用」取就近的境内源；**已配置过（如基础镜像已换成境内源）即沿用**，不覆盖、不追加冲突条目。
* **同一级里可互换（实测可用）**：腾讯云 `https://mirrors.cloud.tencent.com/`、阿里云 `https://mirrors.aliyun.com/`（两者均提供 `debian/`、`ubuntu/`、`alpine/` 目录）、中科大 `https://mirrors.ustc.edu.cn/` 等为同级备选；发行版官方源为更远一级的兜底。**条目写法要匹配发行版与版本代号**（`jammy`/`noble`、`stable`/`bookworm` 等）——**先核对基础镜像的版本再改**，改错代号会让 `apt update` 直接失败。
* **改动只落在本次构建内（L2）**：换源脚本**不得**写回仓库（除非项目已有该配置落点）；容器内改动随镜像/任务结束即失效，属一次性装配。
