= PowerShell 脚本规范（技术栈层）

适用于 PowerShell（`.ps1`）脚本。通用格式规则见 `specs/general/script.adoc`；行尾口径见 `specs/general/encoding.adoc`「换行符」；在 Windows 上执行的通用约束见 `specs/stack/windows.adoc`。本文件只收录 PowerShell 专属规则。

== 版本口径：先认运行环境，再选写法

PowerShell 不是"一个版本"：机器上能同时装着 **Windows PowerShell 5.1**（`powershell.exe`，随 Windows 自带、跑在 .NET Framework 上）和 **PowerShell 6/7+**（`pwsh.exe`，跑在 .NET 上、跨平台；其语言版本即 `6`/`7.x`）。两者**语言核心相同、机制与默认值不同**。本文件把这批差异当**跨版本兼容面**处理——不靠"看起来像 PowerShell"判断，按条取值。

* **运行环境取引擎自身的取值，不猜命令名（L1）**：版本与版次一律从引擎取——`$PSVersionTable.PSVersion`（`Major` 即语言版本）、`$PSVersionTable.PSEdition`（`Desktop`＝Windows PowerShell，`Core`＝PowerShell 6+；4 及以下无此变量，**取不到按 `Desktop` 处理**）、以及**特性探测**（该变量/该命令/该参数在不在——用 `Get-Command`、`Get-Variable`、`$PSVersionTable.PSVersion` 的属性直接问引擎）。**不得**按"机器是 Windows 就有 PowerShell 5.1""装了 `pwsh` 就当 5.1 用"这类命令名/系统名推断。**判定标准**：脚本行为依赖版本或版次，却没有一处从 `$PSVersionTable` 取值或做特性探测——命中即违规。
* **凭据与调用面按"哪一版都会被执行"取值（L1）**：同一个 `.ps1` 会被 5.1 与 7+ 分别执行（双击的 `.bat` 走 5.1、CI 镜像里的 `pwsh` 走 7、`Get-Help ./foo.ps1` 又可能来自另一版）。故脚本**默认须在最低支持版本上能跑**；确要用高版本独有能力时，入口处按下面两条取值，不得只在注释里写一句"需 7.0"。
* **要求的最低版本写成 `#Requires`（L1）**：`#Requires -Version <N>.<n>` 是"不满足就不执行"的声明——写上它，低于该版本的引擎直接拒绝启动脚本，而不是跑到一半报语法错。**不得**用注释/文档头写最低版本、却在代码里用更高版本才有的语法（读了注释的调用方会以为能跑）。`#Requires` 全局生效、与所在行无关。
* **跨版本时按特性探测分支，不按版本号硬编码（L2）**：同一功能有两种写法时，用**特性探测**（该变量/该命令/该参数在不在）选分支，而不是写 `if ($PSVersionTable.PSVersion -ge ...)` 一串硬编码阈值——硬编码在补丁版本回移/预览版上会判错，探测则随实际能力走。**判定标准**：出现两个及以上手写的版本阈值判断、且可用探测替代——命中即违规。

== 版本敏感项（同一处代码，两版行为不同）

以下每一条都是"两版都能解析、但结果不同"或"一版直接解析失败"的形态。**跨版本脚本一律按"最低支持版本也能跑"的写法取值**。

* **编码参数取值只取两版共通的那几个（L1）**：`-Encoding` 的**取值集合两版不同**——`utf8NoBOM`/`utf8BOM`/`ansi` 是 PowerShell 6+ 才有的值（`ansi` 更晚），Windows PowerShell 5.1 只有 `UTF8`（含 BOM）、`Unicode`、`ASCII`、`Default`、`Oem` 等。**跨版本脚本不得写 `utf8NoBOM`/`utf8BOM` 一类高版本专有取值**；需要在 5.1 上也精确控制 BOM 时，按"取得字节再自己写"的方式表达，不赌某个取值在两版含义相同（同名的 `UTF8` 一版带 BOM、一版不带）。
* **`>`/`>>` 与 `Out-File` 在两版落成不同编码（L1）**：Windows PowerShell 的 `Out-File`、`>`、`>>` 默认写 **UTF-16LE**，PowerShell 6+ 默认写 **UTF-8 无 BOM**；`Set-Content`/`Add-Content` 又是另一套默认（5.1 下取系统 ANSI 代码页）。故**脚本产出文件一律显式写 `-Encoding`**，不得依赖默认值——同一条重定向在 5.1 与 7 下给出的文件字节不同，调用方（尤其 Unix 工具、`git diff`）会看到不同结果。**判定标准**：向文件写内容时缺省 `-Encoding`——命中即违规（例外：写的是有意留给本脚本自己再读的中间产物，且同处说明了这一点）。
* **版本 7 才有的运算符与语法不得进跨版本脚本（L1）**：`??`、`??=`（7.0 起）、`?.`、`?[]`（7.1 起正式）、三元 `? :`（7.0 起）、管道链 `&&`/`||`（**7.0 起**）在 Windows PowerShell 5.1 上是**解析错误**（整份脚本跑不起来，不是某个分支失效）。跨版本脚本用 `if`/`else`、`-ne $null` 判断、逐条判定 `$LASTEXITCODE` 的写法替代。**判定标准**：跨版本脚本里出现上述运算符——命中即违规（确要用则按上节用 `#Requires` 声明最低版本）。
* **`$?` 的语义在两版不同（L2）**：包裹在 `(...)`/`$(...)`/`@(...)` 里的语句，**PowerShell 7 之前**会把 `$?` 重置为 `$true`（于是"失败了但 `$?` 说是成功"），7 起才如实反映。故**判定成败不要包一层括号再看 `$?`**；要可判定就用 `$LASTEXITCODE`（外部命令）或 `try/catch`（命令出错）。
* **原生命令的成败按 `$LASTEXITCODE` 判定（L1）**：外部程序**不参与** PowerShell 的错误体系——非 0 退出码**默认不**生成 `ErrorRecord`、**不**进 `$Error`、**不**触发 `catch`/`trap`，只在 `$LASTEXITCODE` 里留一个数字。故调外部命令后必须显式判 `$LASTEXITCODE`（`git clone ... ; if ($LASTEXITCODE -ne 0) { ... }`），**不得**把它包在 `try/catch` 里就以为抓得到失败。**判定标准**：调了外部命令却没有一处读 `$LASTEXITCODE` 就继续往下走（或只用 `try/catch` 包外部命令）——命中即违规。
* **`$ErrorActionPreference` 的效力边界（L1）**：它管的是**非终止错误**（`Write-Error` 一类）；`$PSCmdlet.ThrowTerminatingError()` 抛出的错误**不理会 `-ErrorAction`**（`Break` 除外），而 `$ErrorActionPreference` 反过来**能抑制**语句级终止错误。另：`-ErrorAction Stop` 在**非高级**函数里升格为脚本终止错误、在带 `[CmdletBinding()]` 的**高级**函数里只到语句终止——两者"停在哪"不同。故**不要在脚本里靠 `$ErrorActionPreference = 'Stop'` 兜住一切**：需要"这一步失败就停"的地方，就地写 `-ErrorAction Stop` 或 `try/catch`。
* **`Write-Host` 不是标准输出（L1）**：`Write-Host` 写的是**信息流**（信息流与 `6>` 重定向自 PowerShell 5.0 起才有；5.1 能重定向，但仍不等于 stdout），`Write-Output` 写的才是**成功流**（即管道/stdout）。要"让调用方拿到数据或让 CI 读到输出"，用 `Write-Output`/`Write-Verbose`；**不得**用 `Write-Host` 承载结果（在重定向、管道、非交互执行里会丢）。
* **抛错与退出码各按用途取值（L1）**：脚本内部的失败用 `throw`（终止当前脚本、可被 `try/catch` 捕获）；**进程退出码只由 `exit <n>` 决定**——脚本末尾不写 `exit` 时，退出码取**执行到的那条命令**的（与批处理的「不写 `exit /b %errorlevel%`」是同一个失效形态）。故：① 脚本内失败用 `throw` 或 `exit <非 0>`；② 作为跨环境入口调用逻辑代码时，**取 `$LASTEXITCODE` 再 `exit`** 把它原样返回，不得吞掉。
* **`Set-StrictMode` 取显式版本号、不取 `Latest`（L1）**：`Latest` 的含义**随新版本发布而变**（该值被官方标注为"不确定"：同一个脚本在更新的引擎上会被套上更严的规则）——同一个脚本会在新引擎上突然报更多错，属"跑得好好的、换台机器就失败"。严格模式本身可以开，但**版本号须写死**（`-Version 3.0` 一类），让松紧由脚本自己决定。**判定标准**：`.ps1` 里出现 `Set-StrictMode -Version Latest`——命中即违规。

== 解析与传参（AI 实际最常翻车的一层）

* **PowerShell 有两种解析模式（L1）**：命令位置按**参数模式**解析（除 `$`、引号、`{}`、`,`、`()`、`$()`、`@` 之外，一切按可展开字符串处理），表达式位置按**表达式模式**解析。`Write-Output 2+2` 输出的是字符串 `"2+2"`，`Write-Output (2+2)` 才是 `4`——**同一段运算在两种位置结果不同**，这是"算得对、传出去是字符串"的根源。**判定标准**：把需要求值的表达式直接放在命令参数位置（没加括号）——命中即违规。
* **参数里的元字符按语义处理，不靠拼字符串（L1）**：参数模式的元字符是空格、`'`、`"`、反引号、`,`、`;`、`()`、`{}`、`|`、`&`、`<`、`>`、`@`、`#`；其中 `<`、`>`、`@`、`#` 只在**词首**特殊。故**路径与含空格/括号/`&` 的取值一律加引号或作为变量传入**，不拼进字符串再执行。
* **不把 Linux/bash 与 cmd 的写法搬进 PowerShell（L1）**：`$1`/`$@`/`$#`（位置参数与参数个数）、`~` 展开成外部命令参数、反斜杠转义、`VAR=x cmd`、`export`、`>/dev/null`、`2>&1` 之外的 `2>nul`、`&&`/`||`（**7.0 起才有**，5.1 解析失败）、`$(cmd)` 取输出而不管退出码——这些在 PowerShell 里**要么不存在、要么含义不同**。PowerShell 的取值形态：参数用 `param()` 声明、环境变量用 `$env:VAR`、丢弃输出用 `| Out-Null`、重定向用 `2>$null`。**判定标准**：`.ps1` 里出现 `$1`/`$@`/`$#`、`export `、`VAR=` 赋值式、`2>/dev/null` ——命中即违规。
* **续行按"自然断点"写，不用反引号（L2）**：反引号续行容易被尾随空格打断、且看不见（这是"多行长命令莫名只跑了一半"的常见成因）。PowerShell 允许在 `|`、二进制运算符、`,`、以及 `[`/`{`/`(` 之后直接换行；参数很多时用**splatting**（`$p = @{ Name = ... }` + `foo @p`）替代长参数列表。
* **`param()` 须是脚本可执行部分的第一条语句（L1）**：`param()` 之前只允许注释与空行——之前一旦出现别的语句，`param()` 变成语法错或不再是参数声明。**`#Requires` 不受这条约束**（官方明文：`#Requires` 可出现在脚本的任意一行、且一律全局生效），本集合的取值是**仍写在文件头部**——它是给人看的"这个脚本要什么才能跑"，藏在中段等于没有。**BOM 是唯一允许出现在首行之前的东西**。

== 外部命令与跨版本传参

* **传参差异按最低支持版本取值（L1）**：原生命令的参数在 PowerShell 里**先被解析再拼成命令行**，这个拼接自 **7.3 起**由 `$PSNativeCommandArgumentPassing` 控制（`Standard`/`Windows`/`Legacy`），此前是旧行为且有已知的引号丢失问题。故跨版本脚本**不依赖"引号会自动被正确转义"**：含空格的取值、含引号的取值，要么按目标命令的语法自己拼好（并同处说明），要么用 `--%`（停止解析标记，**仅 Windows、且其后不再做 PowerShell 解析、只替换 `%VAR%`**）明确接管。**判定标准**：把含空格/引号的变量拼给原生命令、且没有任何一处说明其拼接口径——命中即违规。
* **原生命令的成败按 `$LASTEXITCODE` 判定**：同「版本敏感项」该条，不重复。
* **`$PSNativeCommandUseErrorActionPreference` 不得当兼容层用（L2）**：它把"外部命令非 0 退出码"接进错误体系（7.4 起稳定），**5.1 没有**。它改变的是"非 0 是否报错"，而 `robocopy` 一类命令**用非 0 表示非错误信息**——故显式判 `$LASTEXITCODE` 才是跨版本、跨命令都成立的做法。

== 注释与文档头

* **`.ps1` 有基于注释的帮助（comment-based help），文档头用它承载（L1）**：PowerShell 的文档注释机制是**基于注释的帮助**——把文档头写成 `.SYNOPSIS`/`.DESCRIPTION`/`.PARAMETER`/`.EXAMPLE` 等关键字块，置于文件开头（`#Requires` 一类语句之后）或函数之前，`Get-Help ./foo.ps1` 即可读出；故脚本的文档头**须用该机制**承载（判据见 `specs/general/coding.adoc`「注释」的「注释的形式与承载位置」一条：有文档注释机制须用文档注释），**不另起普通 `#` 块注释**（两处各写一半＝同一事实两个来源）。**判定标准**：文档头用没有关键字的连续 `#` 行承载、或同一份说明在关键字块与普通块注释里各写一遍——命中即违规。
* **该机制写不成关键字形式时退回多行块注释（L2）**：确实写不成（如几行的临时脚本）时，按 `specs/general/script.adoc`「脚本文档的承载位置与协作粒度」的**第二优先级**用连续多行 `#` 承载，仍不得降格为零散单行注释。

== 启动脚本（同名 .bat）

* **`.ps1` 脚本须配一个同名 `.bat` 启动脚本**（如 `foo.ps1` 配 `foo.bat`）：`.ps1` 无法直接双击运行，且受 PowerShell 执行策略限制、命令行运行（需显式 `powershell -File ...`）也很麻烦，故须提供一个 `.bat` 文件作为启动入口，便于直接双击或命令行运行。
* **`.bat` 启动脚本的落点与写法属批处理栈（唯一落点，本文件不复制）**：编码（纯 ASCII、不写 BOM）、行尾（CRLF）、**块语句/引用/续行的坑**、"启动脚本为何是 Windows 侧入口"、以及 `-ExecutionPolicy Bypass` 的完整条文都在 `specs/stack/batch.adoc`（含"需要 PowerShell 能力时怎么由 `.bat` 承接"那一条，那里同时给出三条齐备的参考形态）。本处**只留与本栈绑定的一句**：`.ps1` 的启动由同名 `.bat` 以 `-ExecutionPolicy Bypass` 调用，**不要求用户手动修改系统执行策略**。
* **同名但格式要求不同**：`.bat` 纯 ASCII + CRLF、`.ps1` UTF-8 + CRLF——**按字节读行尾的 `cmd.exe` 遇 BOM 或 LF 会直接解析失败**，故两者**分别**按 `specs/stack/batch.adoc`「编码与行尾」与本文件「编码与行尾」保存。

== 作为跨环境入口（Windows 与 Linux 并存时）

* **`.ps1` 与同名 `.bat` 只做薄壳（L1）**：脚本要在多个操作系统上跑时，`.bat` 只负责启动、逻辑只写一份（判据属通用层，见 `specs/general/script.adoc`「跨环境脚本（入口 + 跨平台逻辑 + 实现语言取舍）」）——不得在 `.ps1` 里另写一遍 Linux 侧逻辑；参数用 `%*` 原样透传、退出码原样返回给调用方。**`.ps1` 的头部注释只写入口自己**：本栈取值＝文档头按本文件「注释与文档头」的 comment-based help 承载；边界（不复述逻辑层的参数语义与默认值）见 `specs/general/script.adoc`「脚本头部注释（文档头）」的「入口的注释边界」。
* **入口的位置与命名**：取值＝逻辑 `foo.py` → `foo.bat`（需要 PowerShell 能力时再加 `foo.ps1` + 同名 `.bat`），命名与位置的判据一律按 `specs/general/script.adoc`「入口层须与逻辑代码同处一目录、同名不同扩展名」。本栈另有一条：调用方**只输 `foo.bat`（或双击）就能跑**——不得要求调用方加 `powershell -File`/`-ExecutionPolicy Bypass` 一类前后命令（该参数固定写在 `.bat` 内部）。
* **入口语言选择（入口的语言取值）**：取值同上（批处理栈那一条），本栈只补：**需要 PowerShell 能力时**按本文件「启动脚本（同名 .bat）」用 `.ps1` + 同名 `.bat` 承接，不因此要求引用方先改执行策略。**Linux 侧不得把 `.ps1` 当入口**（PowerShell 在 Linux 上要另装，不是默认具备的运行时）。

== 编码与行尾

* **编码（L1）**：`.ps1` 一律 UTF-8 编码；含中文等非 ASCII 字符时，必要时文件头部加 UTF-8 BOM（**BOM 是唯一允许出现在首行之前的东西**——此前不得有空行或注释，否则 `#Requires`/首行注释一类首行声明失效（`.bat` 侧的 `@echo off` 同此）），避免 Windows PowerShell（5.1 及更早默认按 ANSI 解析无 BOM 的 UTF-8）解析乱码。
* **行尾（L1）**：`.ps1` **落盘 CRLF**（与同名 `.bat` 一致）——PowerShell 虽能解析 LF，但带 BOM 的脚本改用 BOM 字符集、CRLF 是 Windows 工具链与编辑器的一致预期；不得为"统一成 LF"把 `.ps1`/`.bat` 改成 LF（`.bat` 改成 LF 会直接失效）。行尾由 `.gitattributes` 的 `*.ps1 text eol=crlf` 与 `*.bat text eol=crlf` 声明，不靠人工逐个文件手动调整。
* **编码与行尾核对（取值形态）**：`.bat` 的取值同 `specs/stack/batch.adoc`「行尾」（纯 ASCII + CRLF）；`.ps1` 的编码取值＝UTF-8(BOM)，行尾同为 CRLF、不得混用。**怎么核对属执行动作，不写进规范**。
* **执行策略**：`.ps1` 的启动统一由同名 `.bat` 以 `-ExecutionPolicy Bypass` 调用，不要求用户手动修改系统执行策略。**执行策略不构成安全边界**（它拦不住有意绕过的人，只是纵深防御的一层）——故不得把"必须过策略"当脚本的安全保证，权限类动作仍按 `specs/general/security.adoc` 校验。
