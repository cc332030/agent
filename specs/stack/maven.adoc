= Maven 规范（技术栈层）

以下规范适用于 **Maven 构建**。加载触发特征：项目存在 `pom.xml`、`mvnw`/`mvnw.cmd`。构建/依赖调整前须加载本文件。Node 等其它构建工具按对应栈文件规范。

== 仓库与镜像

* **未配置过 Maven 仓库/镜像、且外网出口 IP 在中国大陆时（L1）**：**动手构建前**，让 AI 使用 link:https://mirrors.cloud.tencent.com/nexus/repository/maven-public/[`https://mirrors.cloud.tencent.com/nexus/repository/maven-public/`] 作为 Maven 中央仓库。**必须先用这个仓库**，不得自行另挑镜像站；**仅当它不可用**（连不上、代理不到、报错取不到构件，配置后实测确认）才允许改用**其他在境内的镜像站**。**已配置过即不做**：沿用引用方既有配置，不覆盖、不重配。

== 依赖

* 严禁私自调整依赖（依赖声明与传递依赖解析规则见 Maven 官方文档的依赖机制一章）
* 除非有必要（如避免传递依赖版本漂移、传递路径可能失效），否则不重复声明依赖；传递依赖已满足时不显式声明

== 构建与验证

* 同一 Maven 模块禁止并行构建（通用规则见 link:../general/testing.adoc[]「执行与验证」）；多 agent 协作时同一模块分阶段执行（先写测试文件，再串行执行验证），避免构建冲突
* 验证以 Maven 结果为准：Windows cmd 下编译失败 exit code 可能为 0，不得仅凭 exit code 判断，必须依据 surefire 的 Tests run/Failures/Errors/Skipped 统计判断是否通过；输出重定向到文件、"获取统计一步到位"等通用验证规则见 link:../general/verify.adoc[]「编译/运行验证」
