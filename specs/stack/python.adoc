= Python 脚本规范（技术栈层）

适用于以 Python 编写的脚本文件（风格依据：PEP 8 代码风格、PEP 257 文档字符串约定、PEP 20 之"Python 之禅"）。通用格式规则见 `specs/general/script.adoc`；行尾按 `specs/general/encoding.adoc`「换行符」的基准判定。本文件只收录 Python 栈专属规则

== 行尾

* **LF，不得 CRLF（L1）**：`.py` 脚本一律 **LF**（Python 能解析 CRLF、但仓库内统一 LF，避免混用与假变更；shebang `#!/usr/bin/env python3` 在 Linux 下带 `\r` 会定位不到解释器，依据：POSIX 对 shebang 行的解析）。

== 文件头与解释器

* **shebang 用 `#!/usr/bin/env python3`**（明确用 python3，不用 python）。
* **兼容终端编码**：涉及中文输出/读取时，在入口统一按 UTF-8 配置 stdout/stderr（`sys.stdout.reconfigure(encoding="utf-8")`），避免 Windows GBK 等非 UTF-8 终端乱码。
* **文档头写在模块 docstring 里、不另起块注释（L1）**：脚本的定位、用法、参数、环境变量、行为与副作用、关键约定与设计决策、兜底与限制写进**模块 docstring**（shebang 之后的第一个语句），**不另用 `#` 块注释重复**（两处各写一半＝同一事实两个来源）——docstring 是 Python 的文档注释机制，按 `specs/general/coding.adoc`「有文档注释机制须用文档注释」执行（条目清单见 `specs/general/script.adoc`「脚本头部注释（文档头）」）。
* **docstring 里不抄实现取值（L1）**：`TIMEOUT_SECONDS`/`DEFAULT_BASE`/`DEFAULT_WORKERS` 一类取值在 docstring 里写**抽象描述或常量名**，不写"超时 30 秒""并发 4"这类字面数值（改常量不改 docstring 即产生"文档说谎"），默认值以模块级常量为唯一来源。
* **docstring 与实现同改、决策不落进函数体（L1）**：改动使 docstring 失真时在**同一提交内**改过来；文件级的方案取舍、适用范围与已知限制留在模块 docstring，不塞进函数体内（函数体注释只记该函数内部的局部决策与边界）。
* **单打独斗的 `.py` 脚本同样用模块 docstring、默认不另建独立文档（L1）**：作为**单文件脚本**存在的 `.py` 也按本节用模块 docstring 承载文档；它的定位、用法、参数与边界默认写在 docstring 里，**不另建**独立 `.adoc`/`.md`（**唯一例外**是内容确已超出 docstring 容量时的移交，届时在 docstring 里留一行链接）。
* **一次性的临时 `.py` 片段（L2）**：只有一次性、几行的临时命令可省条目化文档头，但仍须在模块 docstring 首行写一行用途说明。

== 入口与结构

* **可执行脚本用 `if __name__ == "__main__":` 作为入口**，逻辑放 `main()` 函数中，避免顶层堆砌过程代码，便于被 import 复用与测试。
* **`main()` 返回 int 作为退出码**，`if __name__ == "__main__":` 中以 `sys.exit(main())` 结束。

== 参数处理

* **命令行参数统一用标准库 `argparse`**，提供 `--help`、参数默认值与类型校验；必填参数缺失时 argparse 自动报错并退出非 0。
* **参数校验**：对路径、枚举值等参数在解析后显式校验合法性。

== 错误处理

* **用 `try/except` 捕获可预期的异常**，出错时输出清晰错误到 stderr（`print(..., file=sys.stderr)`）并返回非 0 退出码；不静默吞异常。
* **临时文件写入目标项目 `tmp/`**，配合 `try/finally` 或临时目录上下文管理器清理。

== 编码与风格

* 编码规则（命名、注释、避免控制台打印）遵守 `specs/general/coding.adoc`。
* 脚本保持纯标准库优先，避免为简单脚本引入重依赖。

== 作为跨平台逻辑层（Windows 与 Linux 并存时）

* **Python 是跨环境逻辑层的并列首选（L2）**：同一功能要在多个操作系统上跑时，逻辑用 Python 3 写**一份**，`.bat`/`.cmd` 与 `.sh` 只做薄壳入口（见 `specs/general/script.adoc`「跨环境脚本（入口 + 跨平台逻辑 + 实现语言取舍）」）。
* **不假设自身所处目录（L1）**：逻辑代码可能被任意目录下的入口调用，**不得**假设当前工作目录是项目根——需要项目根时由入口在调用前约定，或按调用方传入的参数取值；入口侧以绝对路径调用、不 `cd`。
* **纯标准库优先**：跨环境逻辑代码尽量只用标准库（`argparse`/`json`/`pathlib`），不引入重依赖——少一次安装，就少一个平台差异。
* **落点与命名（入口的语言取值）**：本栈取值＝逻辑代码 `foo.py` 与两平台入口（`foo.sh`、`foo.bat`/`foo.cmd`）同处一目录、主名相同（判据属通用层，见 `specs/general/script.adoc`「入口层须与逻辑代码同处一目录、同名不同扩展名」）；**Python 只作逻辑层、不作入口**——让用户敲 `python3 foo.py` 才能跑，正是该条要消除的"前置命令"。

== 包源（pip）

* **pip 源按次序选、先实测（L1）**：未配置过 pip 源（`pip.conf`/`pip.ini`、`PIP_INDEX_URL`、`--index-url` 均无）时，按 `specs/general/dependency.adoc`「包源（包仓库/镜像站）的选用」的次序取源——**同一级里可互换**；境内推荐（实测可取到包）为腾讯云 `https://mirrors.cloud.tencent.com/pypi/simple/`、阿里云 `https://mirrors.aliyun.com/pypi/simple/`、华为云 `https://repo.huaweicloud.com/repository/pypi/simple/`，高校镜像站（如清华 TUNA `https://pypi.tuna.tsinghua.edu.cn/simple/`）为同级备选；**PyPI 官方源**属更远一级的兜底，仅在境内源全部实测不可用时才用。
* **先实测再启用、已配置过即沿用（L1）**：动手安装前先用一次真实请求（或 `pip download --no-deps` 取一个确定存在的包）确认源可用；**不得**覆盖项目/环境既有配置，**不得**每轮重试同一个源。
