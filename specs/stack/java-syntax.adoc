= Java 工具类规范（技术栈层）

以下规范适用于 Java 项目的工具类使用。目标：**优先复用项目自有工具类与已引入工具库**替代重复的原生写法（项目已有先例时跟随先例），统一代码风格，避免重复造轮子。

== 工具类使用优先级

使用工具类时按以下优先级选择（从高到低），**先看项目已有先例再动手**（通用规则见 link:../general/coding.adoc[]「代码复用」）：

* 1. **项目自有工具类**（最优先）：项目已实现/已引入的自有工具库优先使用（如 ctool4j 的 `CList.of(...)`、`CStrUtils`、`CIdUtils.UUID()` 等），避免重复实现——**项目已有等价能力时，不得改用手写原生写法或 JDK 原生 API**（典型反例：已有 `CIdUtils.UUID()` 仍写 `UUID.randomUUID().toString()`、已有 `CList` 仍手写 `new ArrayList<>()`）
* 2. **通用第三方工具库**（项目已引入时优先于 JDK 原生写法）：已引入 hutool 时，用其工具类替代原生重复写法，如：
  ** `cn.hutool.core.util.IdUtil`（如 `IdUtil.fastUUID()`/`fastSimpleUUID()`，替代 `UUID.randomUUID()` 手写）
  ** `cn.hutool.core.collection.CollUtil`（集合，如 `CollUtil.isNotEmpty`/`isEmpty`，替代 `x != null && !x.isEmpty()` 手写判空）
  ** `cn.hutool.core.util.StrUtil`（字符串）
  ** `cn.hutool.core.map.MapUtil`（Map）
  ** `cn.hutool.core.util.ObjectUtil`（对象）
  ** `cn.hutool.core.util.ArrayUtil`（数组）
* 3. **JDK 标准库自带能力**（最低优先级，仅在无项目自有/第三方等价能力时）：JDK 支持时使用，如 `List.of(...)`/`Set.of(...)`/`Map.of(...)`、`Objects`/`String`/`Math` 等原生方法，不为此引入额外依赖

约束：各优先级仅在对应依赖已引入时适用；未引入某库则跳过该层级，不强行引入不必要依赖（依赖调整见 link:../stack/maven.adoc[]）。**同一操作在项目内已有统一入口/先例时，一律跟随先例，不按优先级另选一套。**

== 工具类使用约定

* 统一入口：同类操作优先用统一工具类（如集合用 `CollUtil`/`CList`、字符串用 `StrUtil`/`CStrUtils`），不散落手写
* 判空处理：优先用工具类判空（如 `CollUtil.isEmpty`、`StrUtil.isBlank`、`ObjectUtil.isNull`），避免手写重复判空
* 判空兜底用默认值工具方法：通用判空兜底原则见 link:../general/coding.adoc[]「表达式与调用写法」；Java 中 hutool 提供 `ObjectUtil.defaultIfNull(x, default)`（x 为 null 时取默认）、`CollUtil.defaultIfEmpty(x, default)`（集合空时取默认）、`StrUtil.emptyToDefault(x, default)`（字符串空时取默认）等工具方法，hutool 已引入时直接用，不重复手写
* 工具类自身实现：工具库内部为构建 API 而直接使用原生写法（如 stream、原生集合）属合理实现，不受本规范约束

== 工具类定义（项目自研工具库）

* 项目自研工具库类默认使用 `@UtilityClass`（lombok）：方法、字段不再需要 `static` 关键词，也不再需要手写私有构造方法（lombok 默认生成私有构造器）
