= Web 前端构建规范（技术栈层）

适用于**前端打包产物**（浏览器侧应用与页面，由任一打包器构建）。加载触发特征：项目存在前端应用的包清单与打包器配置（`package.json` 及其 `vite`/`rollup`/`webpack`/`esbuild` 一类构建配置、`index.html` 入口）。通用判据（体积哨兵、按需加载、可达依赖须可静态消除）在 `specs/general/coding.adoc`「分发产物的体积与按需加载」，**界面的判据本体在 `specs/general/coding.adoc`「界面与样式」**；本文件只收录前端栈专属的**载体**与**取值形态**，不另立判据。

== 产物体积告警

* **告警的载体（L2）**：打包器报出的"某产物超过体积上限"属通用层那条**质量哨兵**的一种——它的**默认上限**即该工具的取值，本项目**不改动**它；要改也只按通用层"取值定错"那一档改，并写明依据。**判定标准**：构建配置里出现**调高**该上限的键、或报出告警后只改该键——命中即按通用层那条的违规处理。
* **不把告警当噪音（L1）**：构建输出里的体积告警须在本次改动内**消掉成因**（见下两节），**不得**留在构建日志里"知道就行"。

== 分包与按需加载（载体）

* **路由层按需加载（L1）**：**载体＝路由定义处**——每条路由的页面组件取**按需加载**形态（打包器据此切出独立产物块）；**判定标准**：路由表里出现**静态**引入的页面组件即违规（首屏那一条除外，它本就在入口块里）。
* **重区块按需加载（L1）**：**载体＝使用该能力的那个页面/组件**——图表、编辑器、地图、预览器一类重依赖在其**使用点**按需加载，不写在入口或共享布局里；**判定标准**：入口模块的静态引用图里能走到该重依赖即违规。
* **重依赖按名引入（L1）**：只用到少量成员的库须**按名引入**（取具体成员，而不是整体引入后再取属性），使未用到的部分可被剔除；**判定标准**：入口可达的模块里出现"整体引入后只用一两个成员"即违规。
* **副作用声明（L1）**：包清单里须声明**本包无全局副作用**（本包确实无副作用时），让未用到的模块可被剔除；**副作用只服务于某条按需加载路径时**（样式、polyfill、全局注册脚本），把它**就近**放在**那一条路径**里，不放在入口。**判定标准（任一命中即违规）**：① 本包无副作用却未声明，或声明被改成"全部有副作用"以图省事；② 入口处出现只服务于某条按需路径的副作用导入。
* **独立产物块的拆分（L2）**：把依赖拆成独立产物块时，**取实测算出的依赖构成**作依据（不看配置量、不为"看起来更快"手工堆清单）；判定标准是"该拆分确有收益"，而非"配置里有这一项"。

== 界面（载体）

**判据本体在 `specs/general/coding.adoc`「界面与样式」（框架优先、同一形态只许一个样式来源、从零写的唯一正当情形、存量边界），本文件只给前端的载体与取用入口**——本文件不复述判据、也不另立判据。

* **框架与样式方案的取用入口（L2）**：现成方案的取用先看**项目包清单里已引入的组件库与样式方案**，再看**项目自己的公共组件目录与全局样式落点**；两者都没有时，才按该生态的通用开源方案取，并**把取用入口收进项目自己的一处**（不在页面里各自引一套）。
* **同一形态的唯一落点（载体）**：视觉形态相同的元素，其**样式与结构的唯一来源**是公共组件目录里的那一处（或全局样式/主题文件里的那一处）；页面只组装。**判定标准**：同一形态在第二个文件里出现一份复制或就地重写即违规。
* **改造框架默认外观的落点（载体）**：全局调整取**主题变量/设计令牌/框架样式覆盖层**那一处；使用点上只做框架允许的扩展，不改框架内部结构。
* **`!important` 的落点（载体）**：优先级手段的取用次序与判定标准在通用层，本处只给**落在哪**——选择器在本项目的**哪一处**（公共样式/主题那一处）、覆盖第三方库或内联样式的**覆盖层**落在哪；**判定标准**：`!important` 出现在页面级的就地样式里、或在同一段样式里层层加码——命中即按通用层那条的违规处理。
* **逆向/复刻与设计稿的载体**：需要与参照一致时，**差异清单**（令牌、结构、间距）落在项目自己的样式落点一处，页面按它取用；复刻范围之外的页面仍按上面的取用入口走。

=== 前后端各一份时的契约载体

* **契约的唯一来源（载体）**：前端与后端**各实现一份**的逻辑（字段、常量、状态取值、校验规则、展示格式），其**唯一来源落在契约本身**——接口描述、共享常量、共享类型声明之一，另一侧**由它生成或对照核验**。**判定标准**：同一个字段名/状态取值/校验规则在两侧各写一份、且没有任何一处是另一处的来源——命中即按通用层 `specs/general/coding.adoc`「同一件事只有一个来源」里"两侧分属无法共享的运行边界"那条例外判；该例外只许可两侧各实现，**不许可两侧各写一份契约**。

== 界面的规模与性能（载体）

**判据本体在 `specs/general/coding.adoc`「界面的规模与性能」**——本文件只给**前端载体**，判据本体的措辞不复述、也不另立一套（与同文件「界面（载体）」同一说法）。

* **列表与表格的取数边界（载体）**：取数侧落在页面调用的接口上（分页参数、按需加载、游标之一），渲染侧落在表格/列表组件的**虚拟滚动或分页**上；**判定标准**：页面把整份集合交给表格/列表、或组件标签上既无虚拟滚动也无分页即违规。
* **同一次展示用到的关联数据一次取回（载体）**：选中项、名称、状态这类「同一屏用得上」的字段，随主查询一次带出或一次批量取（批量接口、关联展开），**判定标准**：渲染循环里出现取数调用（同一组件对每一行各发一次请求）即违规。
* **重区块的按需加载（载体）**：图表、编辑器、地图、预览器的导入点落在**使用它的那个组件/页面**，与上面「重区块按需加载」同一处；判定标准同上（入口静态引用图里能走到它即违规）。
* **全量类操作的生效范围（载体）**：总数、导出、全局搜索、跨页选中落在**服务端接口的全量聚合参数**上（总数随分页响应返回、导出与全局搜索由服务端按当前筛选条件执行、全选保留「选中全部」这一形态并交由服务端解析），**选择只在已加载范围生效时**界面上须给可点选的区分（「已选 N 条／全选 M 条」式）；**判定标准**：前端逐页拉取凑全量、或选择状态只存已加载行而界面声称已全选即违规。
* **性能结论的载体**：前端界面的计时取浏览器侧自身的度量（性能面板/性能条目的脚本与渲染耗时、首屏指标），口径与样本量要求按 `specs/general/testing.adoc`「性能测试」执行；**判定标准**：只给「我这里看着挺快」而无度量与条件即不算结论。

== 缓存（载体）

**判据本体在 `specs/general/coding.adoc`「缓存（统一管理、先缓存后在线）」**——本条与该文件其它载体节同一分工：前端**只写落点**（读写入口、取数次序、标识位置），判据本体的措辞**不复述、也不另立一套**。

**两处缓存的载体各在哪一侧**：同一份数据可能既有后端接口缓存、又有界面缓存，**两者不是同一处入口、也不是同一份判据**。前端这一侧只给**界面缓存**的落点；接口缓存的落点（服务端进程内/分布式缓存键与它自己的缓存头）在服务端技术栈那一侧，前端**不得**以「接口已经缓存了」为由省掉界面侧的入口，反过来也一样。

* **缓存入口的载体（L1）**：界面缓存的读写落在**项目自己的一处**（一个缓存模块／组合式函数／store 的持久化插件之一），键的取值规则与失效逻辑也在那一处；**判定标准**：页面或组件里出现第二个 `localStorage`/`sessionStorage`/`indexedDB` 读写点、或第二套键前缀拼法即违规。
* **取数次序的载体（L1）**：应用打开、路由进入、页面刷新这三处触发点上，**先同步读缓存并渲染**，再在异步取数回来后按比对结果决定是否重绘；**判定标准**：首帧渲染依赖在线请求的完成（`await` 请求后再渲染第一屏、或用空白占位等请求）即违规。
* **接口缓存的载体（不属界面）**：HTTP 接口自身的缓存（`Cache-Control`/`Age`/`ETag` 一类缓存头、服务端的缓存读写）**不落在界面缓存的那一处**——前端不代服务端决定接口返回的是哪一份，也不替它写缓存头；**判定标准**：前端以「先给缓存」为由改接口的返回形态（同一响应先后两份、或响应已发出后再替换结果）即违规。
* **来源与时间标识的载体（L2）**：来源（缓存／在线）与时间（缓存写入多久前、在线刷新于何时）落在**页面自己的状态展示区或统一的状态提示组件**一处，不在各页面各写一份；**判定标准**：同一项目内两处用两套写法表示同一件事即违规。
* **缓存与全量类操作的边界（L1）**：缓存只覆盖**已取回的那一份数据**；总数、导出、全局搜索、跨页选中仍按 `specs/general/coding.adoc`「界面的规模与性能」的"全量类操作的生效范围"走服务端——**判定标准**：以"已经缓存了"为由把全量聚合交给缓存出来的那份数据即违规。

== 与通用层的关系（防第二真源）

本文件**只给前端载体**（路由定义处、使用点、包清单、构型键、公共组件与全局样式的落点、前后端契约的来源、列表与重区块的性能载体、界面缓存的读写入口与取数次序）。"为什么不得调高上限""按序判的三类成因""哪些属例外"**一律以 `specs/general/coding.adoc`「分发产物的体积与按需加载」为唯一真源**；界面的判据本体（框架优先、同一形态只许一个样式来源、从零写的唯一正当情形）**以 `specs/general/coding.adoc`「界面与样式」为唯一真源**；界面在数据规模下的取数与渲染判据**以 `specs/general/coding.adoc`「界面的规模与性能」为唯一真源**。缓存的判据**以 `specs/general/coding.adoc`「缓存（统一管理、先缓存后在线）」为唯一真源**（含两处缓存的分工：后端接口只给确定的一份、界面才适用先缓存后在线）。两处本文件都不复述判据、也不另立判据（本节开头第一句即本文件不复述、也不另立判据）。
