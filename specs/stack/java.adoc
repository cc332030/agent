= Java 规范（技术栈层）

适用于 **Java 项目**。加载触发特征：项目存在 `.java` 源文件、`pom.xml`/`build.gradle`、lombok 配置等。Java 项目写代码必须加载本文件及 `specs/stack/java-syntax.adoc`、`specs/stack/java-testing.adoc`。跨语言通用编码规则见 `specs/general/coding.adoc`；本文件只收录 Java 专属规则。

遵守《阿里巴巴 Java 开发手册》；与本规范冲突时以本规范定义为准。命名与代码风格另参考 Google Java Style Guide 与 Oracle Java 命名约定。

== 命名

* **类重名**：除非类全名（全限定类名）冲突不可避免，否则不使用类重名；发现类重名的需调整优化。
* **Feign 接口命名带所属域前缀（L1，本文件是 Java 落点）**：**Feign 声明式 HTTP 客户端接口**按「**前缀 + 接口业务名 + `Api`**」命名，前缀取**该接口所属域/项目**的固定前缀（先例优先；无先例按项目名取词首字母组合）——`user-center` → `UcUserApi`、`open-user-center` → `OucUserApi`。**只约束 Feign 接口**：REST Controller、RPC 服务契约等其他对外接口不适用本条、不据此改名。判定标准、反例与存量口径见 `specs/general/coding.adoc`「命名与代码质量」的「Feign 接口命名带所属域/项目前缀」。
* **工具类命名优先用复数 `Utils` 结尾**：**仅限工具类**（承载通用静态工具方法、提供项目自有功能的类），类名优先以 `Utils` 结尾（参考 Apache Commons/Spring `StringUtils`/`ObjectUtils`），单数 `Util` 仅在既有一致约定等情况下采用，不混用。**非工具类不受此约束**——即使静态使用或加 `@UtilityClass`，下列不算工具类，命名由自身语义决定（跟随所替代/扩展的对象）：
** 常量类（只放常量）；
** **低版本 JDK 替代/补齐类**：复刻 JDK 静态能力为低版本补齐（如 JDK8 无 `List.of`，提供 `CList.of(...)`）；
** **JDK 现有类的扩展类**：JDK 现有静态类亦为静态使用，其扩展/对应类非工具类（如对应/扩展 `Collectors` 的 `CCollectors`）。

== 编码

* **成员与注解排序（L1，本文件是 Java 落点）**：类成员次序、实体类字段与注解次序按 `specs/general/coding.adoc`「命名与代码质量」执行（通用规则已在本层可直接套用，此处只给 Java 落点，不复述判据）——① **静态字段排在类最前**（例外：被某方法直接使用时允许放到该方法紧前面，放与不放都合规）；② **实体类字段跟随映射表列序**（MyBatis-Plus `@TableName`/JPA `@Table`/`@Entity` 标注的类），注解与方法的次序仍按通用规则；③ **注解先按重要性升序**（重要的在下）——**数据库/持久化映射注解（`@Id`、`@Column`、`@TableName`、`@Table`、`@Entity`）一律排在最下面**（如 `@Data` 在 `@TableName` 之前），**重要性相同再按名长升序**（如 `@Id`（2）< `@Column`（6）< `@TableName`（9），三者同属①档）；④ 注解次序不影响语义才适用——Java 注解本身无"后者覆盖前者"的通用语义，故本条在 Java 上无例外。
* **成员与方法次序（L1，本文件是 Java 落点）**：**新增**字段/方法/重载方法时的落点位置按 `specs/general/coding.adoc`「命名与代码质量」的「成员与方法次序」执行——判据本体、判定标准、例外与存量口径见该处，此处**不复述**，**只给 Java 侧的载体**：① **成员**＝字段、方法、重载方法（如 `save(Entity)` 与 `save(Entity, boolean)` 是重载、彼此按流程次序）；② **依赖与被依赖的载体**是**注入的协作对象**（如注入的 `ObjectMapper` 写在依赖它的 `RestTemplate` 之前）；③ **例外载体**是**数据库实体与返回模型的互转方法**（默认写在查询它的那个接口/方法之后）；④ **语义优先的形态**是**静态初始化块与字段初始化顺序**。
* **链式赋值顺序随字段顺序（L1）**：**Java 落点**——在 `@Accessors(chain = true)` 的链式 setter 与 `@SuperBuilder` 的 builder 链里，**赋值环节的书写顺序按字段声明次序**（实体类即映射表列序）；判据本体、判定标准、例外与存量口径见 `specs/general/coding.adoc`「命名与代码质量」的「链式赋值顺序随字段顺序」，此处**不复述**。**取值来源**：本条**不另定一套顺序**——字段声明次序本就在上条的排序规则里定下，本条只管「赋值时按它走」。
* **注解次序与 lombok 共存**：lombok 的生成类注解（`@Data`/`@Builder`/`@Getter` 等）与持久化/契约/校验注解同处一个目标时，按上条的**重要性优先、同重要性再按名长**排——lombok 生成类注解属最低档次（排最上），持久化注解属最高档次（**排最下**）。示例：`@Data`（档⑤，名长 4）、`@TableName`（档①，名长 9）的次序为 `@Data` 在上、`@TableName` 在下；**数据库注解不被名长左右**——`@Id`（档①，名长 2）虽短，仍排在 `@Data`（档⑤）**下面**。
* **强制优先使用 lombok（L1）**：能用 lombok 代替的绝不手写——getter/setter、构造器、builder、toString/equals/hashCode 等一律用 lombok 生成，禁止移除 lombok 的使用。
* **局部变量强制使用 `val`/`var`，且优先 `val`、可变才用 `var`（L1）**：局部变量声明**必须且一律**使用 `val`/`var`（类型由初始化表达式推断），**不得为显式写出类型而放弃**；其中**先取 `val`**（不可变），仅当该变量**确实需要重新赋值**时才用 `var`——两者都优先于显式类型，**不得为「写清类型」而放弃**；`val`/`var` 仅适用于局部变量，字段不得使用。**`var` 是例外档、不是并列选项**：能 `val` 就 `val`，用 `var` 时该变量在后续语句里必有二次赋值。**判定标准（任一命中即违规）**：① 局部变量写了显式类型，而该类型可由初始化表达式表示且不属下条例外；② **用 `var` 声明的局部变量此后从未重新赋值**（本条所指的「可变」落不了地）；③ 同一方法里等价的局部变量一半 `val` 一半显式类型。**例外（L2）**：类型推断结果不清晰（复杂泛型、联合类型、匿名类、以 `null` 字面量初始化）等确需显式类型提示的场景可写显式类型，此类例外须克制使用。**未引入 lombok 时**：JDK 自身只有 `var`（JDK 10 起，只覆盖「可变」这一半）、**没有 `val`**，此时按 `var` 执行、不为 `val` 另引依赖。**依据（标准名/编号）**：ISO/IEC 25010（可维护性：类型声明只有一处来源）、ISO/IEC/IEEE 29148（判定须可验证）、Project Lombok 官方文档、Google Java Style Guide（局部变量类型推断的取舍，以及「可读性优先于省字」的边界）。**「优先 `val`、可变才 `var`」是本集合对 lombok 的判据化取值**（标准只说明 `var` 的语义与推断规则）。
* **`lombok.config` 实时读取**：`lombok.config` 内容可能调整，规范不固化具体配置项；使用 lombok 或涉及 lombok 默认行为时，实时读取项目根目录 `lombok.config`，按当前配置执行。
* **对象创建统一用 builder**：禁止 `new Xxx(参数...)` 创建对象，创建一律使用 builder（优先 `@SuperBuilder` 而非 `@Builder`，支持继承场景）；实体类用 `@Data`、`@NoArgsConstructor`、`@AllArgsConstructor`；`@AllArgsConstructor` 等构造注解仅用于框架注入或序列化等特殊场景，业务创建对象不得依赖其生成的构造器。
* **数据对象模板（新建时整段照抄；存量主动声明才补）**：**新建**一个 Java 数据对象（POJO/DTO/VO/Entity、内部调用接口的请求响应类）时，注解清单整段照抄 `specs/stack/java-object.adoc` 的模板——`@Data`、`@Accessors(chain = true)`、`@SuperBuilder`、`@NoArgsConstructor`、`@AllArgsConstructor`。**模板文件不是规范文件**：那份文件是**要么不读、要么整份读完**的可复制清单，故不把整段并进本文件（内容多、放了又不一定读）；本文件是其判据本体。三处判据如下：
** **新增对象时加 `@Accessors(chain = true)`；给既有对象补注解时按「类是否已提交」取值（L1）**：Spring 的 `BeanUtils` 会**忽略带泛型参数的 set 方法**——链式 setter 返回 `this`（返回类型带类自身的泛型）即被跳过，于是**拷贝时静默丢数据、各个地方都可能出问题**（不是只在某一处）。**补注解的取值分两档，判据是该类是否已提交**：**类已提交**（该类已存在于提交历史、即已发布出去）→ **默认不补** `@Accessors(chain = true)`——它可能已被别处按 `BeanUtils` 一类拷贝使用，补上即让原本可被拷贝的属性静默不再被拷贝；**类未提交**（仅存在于本次未提交的改动里、尚未发布）→ **可以补**——此时还没有任何调用方，补上不产生本条要防的那种丢失。**判定标准（任一命中即违规）**：① 给**已提交**的类补注解时加上了 `@Accessors(chain = true)`；② 新建对象的注解清单缺 `@Accessors(chain = true)`；③ 以"链式看起来多余""存量反正没人拷贝"为由自我豁免；④ 把"类未提交"读成"整个仓库未提交"或"该文件未提交"——判据是**该类本身**是否已进提交历史。
** **`@AllArgsConstructor` 无参数时不加（L1）**：类里**没有任何实例字段**时，全参构造与无参构造是同一个构造——多标该注解生成不出第二个构造，只会让读者以为"这里有个全参构造"。**判定标准**：无字段的类上出现 `@AllArgsConstructor` 即违规。
** **POJO 里的集合字段默认加 `@Singular`（L1）**：除非有问题，否则集合字段一律标 lombok 的 `@Singular`——让 builder 有**单个元素**的入口，而不是每次先造集合再整集合塞进去。**判定标准（任一命中即违规）**：① 数据对象的集合字段在 builder 侧只能整集合设置、没有单个元素入口；② 以"这个集合可能为空/可能为 null"为由不加（该顾虑不影响"单个元素怎么加"）；③ 以"集合字段不多"为由自我豁免。
** **两档生效面，都不发动全库改造**：**新增对象**整段适用；**既有对象不主动改**，只有**主动声明**（代码注释 / PR 描述 / Issue 要求）要求补时才补（补时按上面第一条**按类是否已提交取值**）；**存量不告警、不要求整改**，随动迁移，见 `specs/core/execution.adoc`；**review 时对存量缺这套模板注解不提出问题**（全局口径见 `specs/general/review.adoc`「review 的默认检查面」，本条不复述）。
** 依据（标准名/编号）：Spring Framework 官方文档（`BeanUtils` 的批量属性拷贝按 setter 发现属性）、Project Lombok 官方文档（`@Accessors` 的 `chain`/`fluent`、`@Builder`/`@SuperBuilder`、`@Singular`、三个构造注解）、ISO/IEC 25010（可维护性）、ISO/IEC/IEEE 29148（判定须可验证）。**三处取舍（补注解时已提交的类默认不加 `@Accessors`、无参不加 `@AllArgsConstructor`、集合默认加 `@Singular`）与生效面取值（按类是否已提交分档）都是本集合自己的判据化取舍**——外部材料只给机制，**未**规定这些（本集合取舍的逐条论证见依据图书馆『规范准入与自身取舍』主题）。
* **无参 / 必参 / 全参构造优先用 lombok、不手写（L1）**：构造方法一律由 lombok 注解生成，**不得手写**任何构造方法体或参数列表——
** **无参构造**：用 `@NoArgsConstructor`（需要时配 `@NoArgsConstructor(access = AccessLevel.PRIVATE)` 一类访问级别）；
** **必参构造**（只含必填/不变字段）：用 `@RequiredArgsConstructor`（字段以 `private final` 修饰，或在 `lombok.config` 里另行声明必填判据）；
** **全参构造**：用 `@AllArgsConstructor`；
** **同时需要多个**（如既有无参又要全参）：**同时标多个构造注解**，各自生成一个，不为"合并成一个手写构造方法"而放弃注解。
** **判定标准（任一命中即违规）**：① 类中出现手写的构造方法（写了参数列表或方法体），而该构造可由上述三个注解之一表达；② 同一类里手写与 lombok 生成的构造方法并存（同一构造的来源出现两处）；③ 以"lombok 表达不了"为由手写而未在代码注释写明原因。
** **例外（L2，须写清理由）**：构造期需要**注解表达不了的动作**（参数校验、字段规范化、防御性拷贝、调用父类/其他对象的初始化）时，可手写该构造方法（或改在 `@Builder` 的自定义 builder 方法里承接），须在代码注释写明「哪个注解表达不了、为何」。**存量**：随动迁移，见 `specs/core/execution.adoc`。
** 依据（标准名/编号）：ISO/IEC 25010（可维护性：同一构造写两遍、样板代码遮蔽真实差异）、ISO/IEC/IEEE 29148（判定须可验证）、Project Lombok 官方文档。**"构造一律由 lombok 生成、不手写"是本集合的取向**。
* **字段接口只加 get 方法、不加 set 方法（L1，只约束接口）**：**为字段设计的接口**（承载字段读写契约的接口，其成员就是这些字段的访问器）**只允许声明 get 方法**（含 lombok `@Getter` 生成到接口上的场合），**禁止声明 set 方法**——除非按本条下款**主动声明**。**本条只约束接口（`interface`）**：类（含 abstract class）不适用本条、不据本条改造，类上的 setter 按既有规则（优先 lombok 生成）处理。**理由**：字段接口是**下游**要实现的契约，下游常在自己的实现类上加 `@Accessors(chain = true)`（或手写 `return this`）；一旦接口里已经声明了 `void setXxx(...)` 形态的 setter，**链式方法无法满足该签名**（返回类型不是 `void`、也无法同时满足），下游直接**编译不过**。**get 不受影响**：getter 无入参、只有返回类型，链式风格与它不冲突。
** **判定标准（任一命中即违规）**：① 接口里声明了 `set` 方法（手写方法体、或接口上的 lombok `@Setter`/`@Data` 一类会生成 setter 的注解），而该接口是承载字段读写契约的字段接口；② 以"接口里只有 get 就没法写入了"为由补上 setter，而未走本条的主动声明；③ 以"这个接口本来就不是给下游实现的"为由自我豁免（该理由属下款主动声明要写明的内容、不由执行者自行认定）。
** **例外（L2，主动声明才生效）**：**除非主动声明**（代码注释 / PR 描述 / Issue 要求）明确允许该处接口声明 set 方法，否则一律适用本条。声明**仅对该处生效、不得泛化**（不能据一次声明把同一模块或同类型的接口都加上 setter）。
** **存量边界（L1，用户点名"已经有的不管，也不告警"）**：**既有接口不视为违规、不告警、不要求整改**，改到哪个接口才顺带调整；**不得**据此发动全库改造（批量删 setter、批量加声明）（随动迁移，见 `specs/core/execution.adoc`）。
** 依据（标准名/编号）：ISO/IEC 25010（可维护性：契约一旦发布即被下游实现，签名里的形态会锁死实现）、ISO/IEC/IEEE 29148（判定须可验证）、Project Lombok 官方文档（`@Accessors(chain = true)` 生成的方法返回 `this`、与 `void` 返回类型的签名不兼容）、《阿里巴巴 Java 开发手册》。**「接口只加 get、不加 set」是本集合自己更严的判据化取舍**——可援引的材料只给"接口是对外承诺、改动须向后兼容"这一方向，**未**规定字段接口不得声明 setter。
* **接口实现时字段名与接口 getter 名不一致须手动桥接（L1）**：类实现接口、**两侧类型相同而字段名与接口的 getter 方法名不一致**时，须**手动 `@Override` 桥接出接口要求的那个 getter**，并给桥接方法加 `@JsonIgnore`——桥接方法体**委托到该字段自身的读取方法**。**理由**：访问器按**字段名**生成，字段名与接口方法名不一致时**不生成接口要求的那个方法**，非抽象的实例类因此**编译不过**；手动桥接后接口方法名与字段名各成一个读取方法、**指向同一个值**，桥接方法不加忽略就会序列化出**两个属性**。**判定标准（任一命中即违规）**：① **序列化属性名已被外部依赖**的类以改名迁就接口（字段名即序列化属性名，改名即契约变更）；② 桥接方法上缺 `@JsonIgnore`；③ 桥接方法体另写取值逻辑、而非委托到字段自身的读取方法；④ 以「反正只有一个属性被用上」为由不处理重复属性。**边界（防反用）**：本条只针对「类型相同、名字不一致」这一种不匹配——名字一致（由框架生成）或类型不同（本就无法桥接）不适用；**尚无外部依赖的类不受①限制**（含新建与未发布的类）：把字段名与接口方法名对齐（从而不再需要桥接）不构成问题。**存量**：随动迁移，见 `specs/core/execution.adoc`。**依据（标准名/编号）**：Project Lombok 官方文档（访问器按字段名生成）、Jackson 官方文档（getter 即序列化属性）、Java 官方 API 文档（实现接口须实现其全部抽象方法）。
* **纯数据结构类识别特征（补充通用编码规范）**：除通用编码规范中"以 bean/model/pojo/dto/vo/entity 等命名"的识别外，**仅使用 `@Data`/`@Getter`/`@Setter` 等 lombok 访问器注解的类同属纯数据结构类**，方法中不得出现非字段读写的计算/转换/组装逻辑。
* **配置类识别特征**：除"以 Config/Properties/Options/Settings 等命名"的识别外，**标注 `@ConfigurationProperties` 的类一律属配置类**（无论类名如何）——只放配置项字段与 lombok 访问器注解，**不得含任何逻辑**（无例外），校验注解与绑定注解属声明、不属逻辑（规则与判定标准见 `specs/general/coding.adoc`「类设计」）。
* **定义方法时参数换行**：多参数且整行宽度（含缩进）临近或超过 80 字符时，参数需换行——左括号 `(` 紧跟方法名后换行，每个参数单独一行，右括号 `)` 单独一行收尾；参数较少或整行宽度未达阈值时保持单行。
* **JSON 处理全局统一使用 Jackson**，禁止引入其他 JSON 库（Gson、fastjson）。
* **既有工具类/先例优先（补充通用编码规范「代码复用」）**：Java 项目写代码前先查项目自有工具类（如 ctool4j 的 `CList`/`CStrUtils`/`CIdUtils`）与已引入工具库（如 hutool 的 `IdUtil`/`CollUtil`/`StrUtil`）是否已覆盖该操作，并跟随项目内同类调用的先例；**已有等价能力时禁止手写 JDK 原生写法**（典型反例：已有 `IdUtil.fastUUID()`/`CIdUtils.UUID()` 仍写 `java.util.UUID.randomUUID().toString()`；已有 `CollUtil.isNotEmpty` 仍写 `null != coll and !coll.isEmpty`）。选择优先级与现成 API 清单见 `specs/stack/java-syntax.adoc`「工具类使用优先级」。
* **反射操作优先使用 MethodHandle**：访问字段、调用方法、构造对象等反射操作优先使用项目提供的方法句柄工具，避免直接使用 `Field#get/set`、`Method#invoke`、`Constructor#newInstance` 等原生反射调用；没有现成的方法时可补充后再使用。
* **日志打印**：禁止 `println`、统一 slf4j；静态文本（无参）不属占位符参数化约束范围；异常日志不得拼 `e.getMessage()`，须将 throwable 作为最后一个参数传入（`log.error("msg: {}", arg, e)`）。

== 序列化（`Serializable`）

仅适用于**声明实现 `java.io.Serializable` 的类**。

* **已实现 `Serializable` 的类型须显式声明 `serialVersionUID`（L1）**：**已声明实现 `Serializable` 的类型**（含父类已实现、自身因此成为可序列化类的场合）**必须显式声明** `serialVersionUID`。**取值**：按项目根 `lombok.config` 的**实时取值**（如 `lombok.serialVersionUID` 一类配置项）执行；**既无配置、又需补出默认值时取 `1L`**（`private static final long serialVersionUID = 1L;`）。**为什么取默认值而不是让它自动生成**：不显式声明时该值由 JVM 依类的结构推导——字段增删、方法签名变化、编译器实现差异都会让它变，于是**仅因结构变化就抛 `InvalidClassException`**；显式声明把该值交回作者。
* **`@Serial` 标注（L2，JDK 14+）**：为 `serialVersionUID` 加 `@Serial`——它让**拼写与放置错误在编译期报出**（`-Xlint:serial`），比运行期才发现可靠；JDK 14 以下不适用。
* **不为未实现 `Serializable` 的类型补（L1）**：**不得**为「消警告」给**未实现 `Serializable`** 的类型加 `serialVersionUID`（对不实现该接口的类，该字段不产生作用），**也不得顺手给它加 `implements Serializable`**——那会把该类型变成「可序列化契约」的一部分，是另一件事、须单独判定。
* **显式声明优先于抑制（L1）**：本条给的是 `serialVersionUID` 这类警告的**正当处置**（显式声明），**以 `@SuppressWarnings` 一类抑制代替显式声明不算完成**——`specs/general/coding.adoc`「警告与弃用」要求「新代码不得引入警告、存量须修复或声明」；**显式声明即该条所说的「声明」**。
* **判定标准（任一命中即违规）**：① 声明实现 `Serializable` 的类型没有 `serialVersionUID` 声明；② 为未实现 `Serializable` 的类型添加了该字段、或顺手为其加了 `implements Serializable`；③ 以抑制注解代替显式声明；④ JDK 14+ 下显式声明了却未加 `@Serial`。**存量**：改到即补（随动迁移，见 `specs/core/execution.adoc`）。
* 依据（标准名/编号）：Java Object Serialization Specification（可序列化类的版本化：不显式声明时 UID 由类结构推导，结构一变即不兼容；显式声明使 UID 由作者掌握）、Java 官方 API 文档（`java.io.Serial`：使拼写与放置错误在编译期报出）、ISO/IEC 25010（兼容性、可维护性）、ISO/IEC/IEEE 29148（判定须可验证）。**「默认取 `1L`」是本集合的取值**——标准给的是「显式声明由作者掌握」，「取 1L」只是本集合定下的缺省起点。

== 对象转换（MapStruct）

对象转换按 `specs/general/coding.adoc`「对象转换（多层嵌套对象的转换）」执行——**声明式映射是优先路径、本集合的建议取向**：JVM 下**优先用 MapStruct**（编译期生成映射实现），**建议不手写转换代码**；**无嵌套（单层）的转换不在该条范围内**，本条也不设强制面。

* **多层嵌套对象转换优先用 MapStruct（L2，建议）**：不同层/不同模型（Entity ↔ DTO ↔ VO、Feign 内部调用接口的请求/响应类）之间**一层层**的对象转换，优先用 **MapStruct 的 `@Mapper` 映射接口**声明完成（编译期生成实现、字段名不一致在编译期报错）；建议不手写转换代码——逐字段 `set`/`get` 搬运、嵌套结构逐层 `new` 组装、手写递归/循环展开对象树。措辞是"优先/建议"：**不做强制性限制**（深拷贝/结构复制工具、序列化中转等等价路径同样合规），只要满足通用层的**达标判据**（同一转换只有一处来源、结构变化时不静默漏字段）。
* **嵌套结构由映射声明表达（写法建议，非强制）**：选了 MapStruct 时，对象内含对象、集合内含对象用**映射方法自动调用**（子类型各声明一个映射方法，父映射直接引用）或 `@Mapping` 表达字段对应；集合/列表映射直接声明为 `List<XxxVo> toVoList(List<Xxx>)`。不要求逐元素手写 `for`/`stream().map(...)`——但手写循环**不构成违规**。
* **不并存两套写法（与「代码复用」的先例优先同源）**：项目已有转换工具（MapStruct 生成的 `XxxConverter` 实例，或既有手写 Converter 类）时**跟随先例并在其基础上扩展**，不新增第二套转换写法；注入方式按 `specs/stack/spring.adoc`「注入」。
* **MapStruct 用法（推荐写法，非强制）**：映射接口用 `@Mapper(componentModel = "spring")`（与 Spring 项目一致，按既有先例取值）；**转换方法接收单个源对象、返回一个目标对象**（集合类型由 MapStruct 生成循环）；`@Mapping` 仅用于字段名/来源不一致、常量、默认值、表达式等库自动推断不了的场合；映射接口**独立成文件放转换/映射所在包**（跟随项目既有约定，如 `converter`/`mapper`/`mapstruct`），**不写进纯数据结构类**。
* **例外与边界（L2）**：① 库表达不了的语义（需查库/远程取值、条件分支决定取值、多来源合成一个字段）在映射接口内以自定义方法（`default` 方法或 `@Mapping(expression=...)`）承接，也可按**主动声明**（代码注释 / PR 描述 / Issue 要求）手写；② 无嵌套（单层）的转换不在本条范围内；③ 构建环境无法运行注解处理器时自然不适用——**本条不设强制面**，手写转换**不构成违规**，只是建议：除主动声明外优先声明式映射，确需手写时在**代码注释备注原因**。
* **存量**：改到即迁（随动迁移，见 `specs/core/execution.adoc`）。

== 持久化访问（MyBatis-Plus / JPA 等）

持久化访问按 `specs/general/coding.adoc`「持久化访问（数据库/缓存等）」执行——**三条 L1 的抽象形态（哪三条、各自判据）只在该层写一份**，本文件不复述其取值（通用层不写具体框架类名）；**框架专名与禁止清单以本文件为唯一落点**。

* **MyBatis-Plus 强制使用 `IService` 的成员方法（L1）**：查询/更新一律走 `IService` 的成员方法——`lambdaQuery()`、`lambdaUpdate()`、`ktQuery()`、`ktUpdate()`（Kotlin 用 `kt*`），**不手工 `new` 任何 Wrapper**。**禁止** `new QueryWrapper<>()`、`new UpdateWrapper<>()`、**及其子类**（含 `new LambdaQueryWrapper<>()`、`new LambdaQueryChainWrapper<>()`、`new UpdateChainWrapper<>()`、匿名子类与自定义 Wrapper 子类）；`new LambdaQueryWrapper<>()` 虽同样类型安全，仍属本条禁止面——**强制走 `IService` 成员方法这一统一入口**，保证同一项目只有一种写法。识别特征：Service 实现类已具备统一服务入口的继承特征、却没走其 lambda 成员方法（调用点出现 Wrapper 的 `new`）。
* **`IService` 之外的落点也不得用静态构造器（L1）**：需要 Mapper 专有方法、或统一入口不覆盖的能力（如分页）时，**不得**为此 `new` 任何 Wrapper，**也不得**改走 Wrapper 的**静态构造方法**（`Wrappers.lambdaQuery()`/`Wrappers.lambdaUpdate()` 一类与 `Wrappers.<实体>lambdaQuery()` 形态）——静态构造方法**同样绕过了统一入口**，属禁止面；落点只能二选一：**在 Mapper 接口上用注解/映射文件**声明该查询，或**在 Mapper 接口上以默认方法封装一次**后由业务侧调用。同一操作在项目内已有先例时跟随先例。识别特征：查询构造的起点是 `Wrappers` 这类**静态工厂**而非本 Service 的成员方法。
* **JPA / Spring Data（对照落点）**：走 `Repository`/`EntityManager` 等既有入口，优先声明式查询方法（`findByXxx`）与类型化 Criteria，不用字符串拼列名。
* **例外（L2，须写清理由）**：`IService` 的成员方法**表达不了的语义**（ORM 未封装的自定义 SQL 片段与其他表条件化 JOIN）允许退回 mapper `*.xml`；确需 Wrapper 子类承载领域条件时，**在 Mapper 接口上以默认方法封装一次**、业务侧只调用该方法（**不得在业务代码里 `new`**，**也不得改走 `Wrappers` 的静态构造方法**），并在代码注释写明"为何替代形态表达不了"。**存量**：随动迁移，见 `specs/core/execution.adoc`。
* **判定标准（任一命中即违规）**：① 出现 `new QueryWrapper`/`new UpdateWrapper`/`new LambdaQueryWrapper`/`new LambdaQueryChainWrapper` 一类构造器 `new`（含匿名子类、自定义子类），而同一条件可由 `lambdaQuery()`/`lambdaUpdate()` 表达；② 出现 `Wrappers.lambdaQuery()`/`Wrappers.lambdaUpdate()` 一类**静态构造方法**或 `Wrappers.<实体>lambdaQuery()` 形态，而本 Service 的成员方法可表达同一条件（**只有本子类内确实调不到**——如类里没有该实体的 Service——才落到例外，且须写明理由）；③ 列名/字段名以**字符串**写进查询构造（`eq("user_name", ...)`），而可用方法引用（`User::getUserName`）表达；④ 绕过 `IService` 另起一套访问写法（同一项目内并存两条路径）。
* 依据（标准名/编号）：ISO/IEC 25010（可维护性：字符串列名无编译期校验、重命名即静默失效）、ISO/IEC/IEEE 29148（判定须可验证）；MyBatis-Plus 官方文档给出 `IService` 的 lambda 方法与 `Wrappers` 的静态构造方法，本条**取前者为唯一入口**、把后者一并划入禁止面，属**本集合自己的取舍**。
* **`IService` 的成员方法只许在 `IService` 与 `ServiceImpl` 的本子类中使用（L1）**：`lambdaQuery()`/`lambdaUpdate()`/`ktQuery()`/`ktUpdate()` 这组成员方法**只能在其所属的 `IService` 与其 `ServiceImpl` 的**本子类（即 `XxxService extends IService<Xxx>`、`XxxServiceImpl extends ServiceImpl<XxxMapper, Xxx>`）内调用（**本实体自己的 Service 成员方法即本条要求的落点**）；**其他子类也不行**——在同一继承体系下另起的子类（`ServiceImpl` 的兄弟子类、无关 Service 拿一个 `XxxService` 实例来调、工具类/Controller/其他 Service 里调）同样在禁止面内。**理由**：`IService` 的成员方法以**本 Service 自己的实体与主键**为隐含上下文（`getById`/`lambdaQuery` 都默认操作本类型），跨类调用即"拿着别人的 service 去查别人的表"，让数据归属散落、也让同一张表出现多个访问点。**判定标准（任一命中即违规）**：① 调用点所在类的继承链里出现的不是**该 `IService` 自己的**本子类（如 `XxxServiceImpl` 内调 `otherService.lambdaQuery()`）；② 工具类/静态方法/Helper 里出现这组成员方法的调用；③ 以"持有的是同一个 Service 的接口引用"或"只是个普通查询"为由自我豁免。**正确做法**：把这段逻辑放进**该实体自己的 Service**（新写一个方法），或按本条下一条另建业务服务。
* **实体 Mapper 只由其对应实体的 Service 调用、不在别处调（L2，不建议但不禁用）**：`XxxMapper` 及其查询能力**原则上只由 `XxxService`/`XxxServiceImpl` 使用**——涉及多张表的业务操作时，**优先新建一个业务服务（`XxxBizService` 一类）编排各实体的 Service**，而不是在某个实体的 Service 里直接操作别的实体、也不是在业务代码里直接注入别的实体的 Mapper（`@Resource XxxMapper`）。**实体 Service 的职责边界**：只做**本实体**的持久化与**本实体自身**的业务规则，**不在其中做太多业务编排、也不在其中操作其他表**。**这一条不禁用、不告警**（用户原话："虽不禁用，但是不建议"）：简单的**补充性单表查询**（本 Service 顺带取一次关联的字典表数据）可直接用该 Mapper，不构成违规；判定标准是"**是否越过了实体 Service 去直接碰别的表**"——① 业务类里出现对**非本类对应实体**的 Mapper 的直接注入与调用；② 某个实体 Service 里出现**跨多表**的业务编排；③ 为容纳跨表逻辑而把别的实体的 Mapper 塞进本实体 Service。**与上一条的分工**：上一条管"**哪一层能调 `IService` 的成员方法**"，本条管"**哪张表的访问归谁**"。
* **存量边界（L1，用户点名）**：以上两条**只约束新写的与本次改到的代码**——**已有代码一律不视为违规、不告警、不要求整改**（用户原话："已有的不管，也不告警"），改到哪个调用点就顺带归位（随动迁移，见 `specs/core/execution.adoc`）。**判定标准**：① 本次**未因需求变动**的存量文件保持原样即合规，不得以"存量还没迁完"为由拒绝或推迟新规范生效；② 不得把"存量不管"读成"新写也照存量写"；③ 不得据此发动全库改造（批量改调用点、批量抽服务、批量补判空）。
* **与既有条目的关系（防误读）**：本条**不改写**上面「MyBatis-Plus 强制使用 `IService` 的成员方法」——那条管"**用哪个 API 构造查询**"（禁 `new` Wrapper、也禁 `Wrappers` 静态工厂），本条管"**在哪个类里调这个 API**"（禁跨类调），两条同向、互不替代；违反了本条**不构成**"可以退回 `new LambdaQueryWrapper` 或 `Wrappers.lambdaQuery()`"的许可（即"为了避开成员方法限定而改用具名构造器或静态工厂"同属违规）。
* **判定标准（汇总，任一命中即违规）**：① 出现跨类调用的 `lambdaQuery()`/`lambdaUpdate()`/`ktQuery()`/`ktUpdate()`；② 工具类/Helper/Controller 里出现这组成员方法；③ 以本条为理由改用 `new LambdaQueryWrapper` 一类构造器。**L2 另判**：业务代码直接注入非本类对应实体的 Mapper、或实体 Service 里做跨多表编排（**存量与"补充性单表查询"除外**）。
* 依据（标准名/编号）：ISO/IEC 25010（可维护性：数据归属与访问点集中的可维护性）、ISO/IEC/IEEE 29148（判定须可验证）。**MyBatis-Plus 官方文档只给出 `IService` 成员方法的能力面，未规定"谁可以调用它"**；"限定在本子类内 + 跨表建业务服务"是**本集合自己的更严取舍**（对应分层架构/领域驱动设计中"仓储与其聚合根的服务同属"的通行范式）。
* **分页查询的返回类型与转换方式（L1，用户点名）**：涉及分页查询时，**返回契约与字段转换分两档判**，两条同向、互不替代（本集合自己的取舍，外部材料只给"分页不必自建"的方向）。
** **普通接口返回 `Result<IPage<Rsp>>`（L1）**：本项目自己的**普通接口**（Controller 直接对外提供，不属声明式 HTTP 客户端）做分页查询时，返回类型写 **`Result<IPage<Rsp>>`**——分页容器用框架的 **`IPage`**、响应元素用**该接口自己的响应类**（`Rsp`），**不新建一个自定义分页类来承载**（自建分页类即与框架容器并存两套分页模型，字段增删改一处必漏另一处），也不返回 `IPage<实体类>`（实体类属对外契约的禁止面，见 `specs/general/coding.adoc`「数据契约的载体」）。
** **Feign 接口用 `Result<自定义Page<Rsp>>`，字段转换走 `page.convert`（L1）**：**声明式 HTTP 客户端接口**（Feign 等内部调用接口）**已按项目先例使用自定义分页类**时，返回类型写 **`Result<自定义Page<Rsp>>`**（跟随先例、不为此改成 `IPage`）；**入参分页对象转响应分页对象时，用分页容器自带的 `convert` 完成字段转换**（`page.convert(Rsp::from)` 一类），**不得新建一个 page 再逐个搬运字段**。**理由**：`convert` 由框架在容器内部完成元素替换，**当前页、每页条数、总记录数、总页数等分页元数据原样保留**；新建 page 时元数据要逐项手工搬运，**漏一项既不报错也不提示**，只在运行期表现为"总页数一直是 0、翻页失效"（属最易漏、最难发现的一类缺陷）。
** **判定标准（任一命中即违规）**：① 普通接口的分页查询返回类型不是 `Result<IPage<Rsp>>`（返回裸 `IPage`/实体类分页，或自建分页类承载）；② Feign 接口已用自定义分页类，字段转换处出现 `new` 一个 page 再逐字段 `set`；③ 为"顺手"把 Feign 侧自定义 page 与普通接口侧 `IPage` 改成同一种，或为"统一"把 `IPage` 换成自建类（两侧契约各自的先例不得互改）；④ 以"这个接口不算普通接口""只是内部调用"为由自我豁免。
** **与相邻条目的关系（防误读）**：本条只管**分页包装体的形状与元素转换的走法**——元素类型本身**不得是数据库实体类**（见 `specs/general/coding.adoc`「数据契约的载体」），层间字段转换**优先声明式映射**（见本文件「对象转换（MapStruct）」）；`convert` 承载的 `Entity → Rsp` 映射照旧优先由映射接口声明，本条不改写那两条。**存量**：随动迁移，见 `specs/core/execution.adoc`。
** **依据（标准名/编号）：ISO/IEC 25010（可维护性：分页元数据的单一来源、改一处不漏）、ISO/IEC/IEEE 29148（判定须可验证）；MyBatis-Plus 官方文档给出分页容器（`IPage`）与 `convert` 的元素转换能力。"普通接口用 `IPage`、Feign 接口跟随先例用自定义 page"与"转换一律走 `convert`"是本集合自己的判据化取舍**——框架未规定两种接口各用哪种包装体。
* **方法名与逻辑删除的对应（L1，本文件是 Java 落点）**：查询方法名的删隐面判据（默认面随技术是否自动附加删除标志条件而变、非默认面须带特征词）见 `specs/general/coding.adoc`「持久化访问（数据库/缓存等）」的「方法名与逻辑删除的对应」，本处只给**框架专名与取值**、不复述判据。**MyBatis-Plus 的逻辑删除**：`@TableLogic` 标注实体字段即启用了逻辑删除，框架**自动为查询附加删除标志条件**——**不带特征词的方法名＝只取未删**（`list()`/`getById()`/`lambdaQuery()` 的默认口径），**查询"含已删"须显式绕开该附加条件**（`IService` 的"查全部/含已删"型方法，或按 `IService` 成员方法之外的落点另写），**查询"只看已删"须显式带已删条件**；未启用 `@TableLogic` 的实体默认面相反（**不带特征词＝含已删**，只看未删须显式带条件）。**JPA / Spring Data 的对照**：`@SQLDelete` 只改删除动作、**不自动附加查询条件**，删除条件由 `@Where`/`@SQLRestriction` 一类声明承担——**"自动附加"以声明实际生效为准**（声明缺失或未生效即与未启用同判）。**判定标准**：同 `specs/general/coding.adoc`「持久化访问（数据库/缓存等）」的「方法名与逻辑删除的对应」。**存量边界与判定标准见通用层同条**（既有方法不改名、不告警）。**依据（标准名/编号）**：ISO/IEC 25010（可维护性）、ISO/IEC/IEEE 29148（判定须可验证）；MyBatis-Plus 官方文档给出 `@TableLogic` 与逻辑删除条件自动附加的能力面，**未**规定方法名的命名口径——"默认面随是否自动附加而变、非默认面须带特征词"是这个集合本身的判据化取舍。

== 跨语言执行脚本（SQL / Lua 等）

Java 里要执行**其他语言**的脚本时，须按 `specs/general/coding.adoc`「跨语言执行脚本的落点」执行——**独立成文件放资源文件夹、扩展名取被调语言的扩展名、按资源读取后执行**，不得用字符串拼接、字符串模板或字符串常量内联在 Java 代码里。

* **SQL 写法（L1，用户点名）**：SQL 独立成文件（`.sql` 放 `src/main/resources/`，MyBatis 项目写 mapper 的 `*.xml`）、语句里的表名带库名（`<库>.<表>`，DDL 与 DML 强制）、同表同类操作合并为一条（DDL 强制、DML 优先）三条判据见 `specs/general/sql.adoc`「SQL 写法」——Java 侧只给落点与执行方式，**不复述判据**（真源一处、其余一跳引用）。**Java 落点无例外**：`.sql` 放 `src/main/resources/`、用 `PreparedStatement`（或等价封装）参数化执行；MyBatis 项目的 `${}` 是字符串替换，仅可用于不由用户输入决定的场景、且须对取值做白名单校验，其余一律 `#{}`。
* **Redis / Lua（L1）**：Lua 脚本**写成 `.lua` 文件**放 `src/main/resources/lua/` 下，用 `DefaultRedisScript`（或项目的等价封装）**按资源加载**后执行，禁止把 Lua 内联成 Java 字符串、也禁止在 Java 里拼 Lua 片段（依据：Redis 官方文档的 "EVAL" 与 "Redis Lua API reference"）。
* **加载时机（L1，本文件给 Java 落点）**：classpath 资源打进产物后**发布即成常量**，**不得在每次调用时都读**——
** **性能敏感路径**（如 Redis 操作）：按"读一次、反复用"定性——`.lua` 用 `DefaultRedisScript` 时**按静态常量声明**（`private static final DefaultRedisScript<...> SCRIPT = new DefaultRedisScript<>(...)`，在静态初始化块里 `setLocation`/`setScriptSource` + 载入一次），**禁止在方法内 `new DefaultRedisScript` 后逐次读资源**；`.sql` 若属热点查询，同样把"读一次"与"执行多次"分开（读入后缓存 `String` 或缓存预编译 `PreparedStatement`，按框架能力与并发安全取舍）。Redis `EVAL` 反复把脚本正文送到服务端亦属重复开销，等价的复用手段是 `EVALSHA`/`SCRIPT LOAD`。
** **不敏感路径**（启动装配、一次性任务、低频操作）：每次读取无妨。
** **需求要求内容会变**：如每次渲染前可编辑、需要热更新的 HTML 模板（转 PDF 等场景）——**不缓存**，按"是否需重读"决定，不得为省一次读取而让需求要求的可变内容被冻结在首次读到的版本上。
** **判定标准（任一命中即违规）**：① 热点路径的调用体内出现 `getResourceAsStream`/`ClassPathResource` 读取（如 `new DefaultRedisScript` 在方法内、`ScriptUtils` 每次调用执行脚本读取）；② Redis 热点操作每次都把脚本正文重发服务端且不做 `EVALSHA` 复用；③ 反向误用——把需求要求可变的模板/脚本按静态常量一次性读死。
* **`@Sql` / `ScriptUtils`（L2）**：测试里的 `@Sql`、`ScriptUtils.executeSqlScript(...)` 等同样指向 `.sql` 资源，不内联 SQL。
* 依据（标准名/编号）：OWASP SQL Injection Prevention Cheat Sheet、OWASP Query Parameterization Cheat Sheet、Redis 官方文档、MyBatis 官方文档（Dynamic SQL 的 `${}` 与 `#{}`）、ISO/IEC 25010 性能效率；**SQL 写法**（独立成文件、写库名、同表同类操作合并）的依据见 `specs/general/sql.adoc`「SQL 写法」（MySQL 官方文档、ANSI SQL / ISO/IEC 9075），本文件不复述。

== 健壮性

* **`Enum.valueOf` 与自写枚举工具的空 `catch`（L1，本条是通用层「显式处理失败与边界」的 Java 落点）**：`Enum.valueOf(...)` 抛出的 `IllegalArgumentException` **只有"没有该枚举常量"这一种原因**（因值不匹配而抛），且取不到值时取**默认值**就是业务语义——故此类调用**允许空 `catch`**；**自写的枚举工具**（按值查枚举、按任意取值取默认枚举这类）满足同一条件时同样允许。**判据本体在** `specs/general/coding.adoc`「代码质量（新产出即高质）」的「显式处理失败与边界」（准入三条 + 判定标准；本处不复述，只给 Java 落点与反面清单）。**判定标准（任一命中即不合规）**：① `catch` 住的是**非枚举查询的异常**（`Integer.parseInt`、`Objects.requireNonNull`、反射、IO、远程调用一类）却写空块体；② 枚举工具内部**另有**真失败出口（IO/DB/远程查找、反射失败）却一并空 `catch`；③ 用带默认值的查询**绕开本该做的参数校验**（见 `specs/general/security.adoc`「输入与输出」）；④ 空 `catch` 处**没有写明"异常只有这一种原因"的依据**；⑤ 把本例外扩大到**同一个 `try` 里的其他语句**或类里其他 `catch`。**边界（防反用）**：① **只放宽空块体**——该 `catch` 仍须捕获**具体异常类型**，**不得**写成 `catch (Throwable)`/`catch (Exception)` 这种**类级空 `catch`**；② **工具类自身是正常类**：查不到就返回 `null`/`Optional.empty()` 的**本身就合规**，**此时无需、也不得**为该返回值再补一个空 `catch`（那是把"接口已给默认"重复成"靠异常兜底"）；③ 只约束 Java（`Enum.valueOf` 与枚举工具在此），**替换主语测试**：非 Java 的对应能力按其自身语义另行判定。**存量**：随动迁移，见 `specs/core/execution.adoc`。**依据（标准名/编号）**：Java 官方 API 文档（`Enum.valueOf`：指定名字的枚举常量不存在时抛 `IllegalArgumentException`）、ISO/IEC 25010（可维护性）、ISO/IEC/IEEE 29148（判定须可验证）。**"只此一种原因才允许空 `catch`"是本集合的判据化取值**——API 文档只给出"什么条件下抛哪个异常"，未规定该处是否该吞。
* **公共方法对边界输入显式处理**：null 入参、无匹配结果必须返回空集合/默认值或快速失败（`requireNonNull`/断言），不得让调用方遇到隐式 NPE。
* **持久化访问前先判空（本条是通用层的 Java 落点）**：判空与"集合返回空集合"的判据本体在 `specs/general/coding.adoc`「持久化访问（数据库/缓存等）」；Java 侧的落点与用法——`getById(null)`、`getByIds(空集合)`、`getOne(...)` 一类**在调用前**用 `ObjectUtil.isEmpty`/`CollUtil.isEmpty` 判一次（判空工具的选择见 `specs/stack/java-syntax.adoc`「工具类使用约定」，**不手写裸 `null` 比较**），命中即**就地返回**（单条 `null`、批量 `CList.empty()` 一类空集合），**不得**把判空塞进 `try/catch`、也不得让 Mapper 去承受；Spring Data 的 `findById(null)`／`findAllById(空集合)` 同理。**返回值契约**：查询方法（含自定义查询方法）返回集合时，声明与实际都返回空集合、**不返回 `null`**；`CollUtil.emptyIfNull` 一类是调用侧的兜底、不替代返回值契约本身。
* **禁止修改调用方传入的可变入参**（数组、集合、对象内容）；确需就地处理时，API 契约必须显式声明。
* **消费输入流必须保证后续可用**：读取后重新缓冲再返回，异常路径不得返回已消费且未重缓冲的对象。
* **资源生命周期归属一致**：static 线程池等全局资源不得由实例 `@PreDestroy` 关闭，防止多上下文互相影响。
* **字节数组转字符串必须显式指定字符集**；HTTP 文本内容优先从 Content-Type 解析 charset，未声明才使用默认值。
* **链式字符串替换使用占位符或一次性正则**，避免替换产物被后续规则二次改写；缓存键命名不得与输入空间可能出现的值冲突。
* **按标准协议拼接日志或输出时结构须符合协议规范**（如 HTTP 报文首行即协议行，不得以空行开头、不得插入非协议内容）。
* **需要内存回收（弱引用/软引用语义）的缓存统一使用 Caffeine 的 `weakKeys`/`weakValues`/`softValues`**，禁止手写 `WeakHashMap`/软引用自实现。

== javadoc

注释需满足发布私服 / Maven 中央仓库的 javadoc 检查（doclint）要求：

* **多行注释永远写多行**：`/**` 单独一行、注释内容逐行书写、`*/` 单独一行，禁止单行写法 `/** xxx */`；javadoc 使用完整多行块，包含 `@param`、`@return`、`@throws`、`@since`。
* **所有 public/protected 方法与字段必须有 javadoc（L1）**：每个公共成员一条 javadoc——**方法**含职责说明与 `@param`（与参数一一对应、名称一致；泛型用 `@param <T> 描述`）/`@return`（非 void 必须）/`@throws`（受检异常必须）；**字段**说明含义、默认值及配置方式（无参无返回值，不标注 `@param`/`@return`/`@throws`）；**不得因"编译能过、doclint 不报"而省略**——缺少 javadoc 即视为未完成。**"要记录哪十项"不在此处复述**（那是内容清单，落点在 `specs/general/doc.adoc`「必记录项」）；本文件只给 **Java 侧的逐项落点**：①② 类级 javadoc，③-⑥ 落在**对应成员**的 javadoc（逐个成员、不得只写在类上），⑦-⑨ 跨类/模块级进设计文档，⑩ 版本号用 `@version`、变更摘要归项目统一 changelog。
* **从独立文档迁移时逐方法落位**：原文档"方法列表/功能说明"里的每个方法条目都要落到对应方法的 javadoc（不得只补类级描述，映射清单见 `specs/general/doc-design.adoc`「存量文档收敛」）；**文档并入 javadoc 后移除对应 `@see`**（`@see` 仅指向仍需保留的功能/模块级设计文档）。
* **版本号用 `@version` 维护**：类级 javadoc 用 `@version` 标注源文件版本，随行为/接口/默认值/已知缺陷等变更递增（初始 `1.0`）；**变更摘要统一写入项目根的统一 changelog**，不在源码或设计文档中另行维护变更日志。
* **类型指代写短类名 + import、不写全限定类名（L2，Java 落点）**：javadoc 里提到某个类时先写短类名（`CUnauthorizedException`），需要解析的场合在**代码示例**里写一条 `import com.c332030.ctool4j.core.exception.CUnauthorizedException;`；不得写全限定类名当标识。**"如果有必要"仅三态**：① 同名类冲突（限定到能区分的粒度）；② 无代码示例可承载 `import`；③ 该类型不在本仓库的 classpath 内。**另有三处不属禁止对象、照常写全**：① `{@link ...}` / `@see` 引用的**文件路径**（路径不是类型名）；② `@see` 里按类全名做的**成员引用**（javadoc 标签要求合法引用）；③ 字符串与配置里必须全限定的场合（`@ConditionalOnClass` 的类名、`main-class`、反射按名加载、`import` 语句本身）。**判定标准**：文档内容里出现"包名 + 类名"形态的指代且不属上述情形 / 同一处短名与全限定名并存 / 以"更准确"为由通篇写全限定。通用条与不做一次性存量替换的口径见 `specs/general/doc.adoc`「文档中提及类型优先写类名 + import」。
* **特殊字符必须转义**：`< > &` 使用 `&lt; &gt; &amp;`，或使用 `{@code ...}` 包裹；HTML 标签必须闭合（`<p>` 换行、`<ul><li>` 列表正确嵌套闭合）。
* **构建器 setter 方法注释须标注 `@param`、`@return this`**。
* **代码与设计文档双向引用**：类/方法的 javadoc 用 `@see "..."` 指向对应的设计文档；**路径基准统一为"相对模块根"**（从该源文件所属模块的根目录起算，不受源文件所在包层级影响）；**不写 `../` 形式的"相对当前文件"路径**。这是对通用文档规范「引用路径」的**显式例外**：javadoc `@see` 由 IDE/javadoc 解析，模块根相对使路径不受文件所在包层级影响。**路径以实际存在的文档为准**：有对应设计文档则 `@see`，**没有则不写 `@see`**，也不得以"补 `@see`"为由强制新建文档。注意 javadoc 的 `@see` 标签要求合法引用，故文档路径须用英文双引号包裹（裸 `@see doc/...adoc` 会被当作类/成员引用解析并报错，`failOnError` 会中断构建）。
* **源类与各类测试类在 javadoc 中互相引用**：源类 javadoc `@see` 其各类测试类（`Tests` / `BootTests` / `PerfTests` / `IT`，如有）；各类测试类 javadoc `@see` 源类与同被测类的其他测试类（性能测试类须指向源类与功能测试类，见 `specs/stack/java-testing.adoc`「测试类命名」）。
* **测试类 javadoc 与主类对称**：测试类类级 javadoc 同样"一句话定位 + 用例目录 + 该测试的整体设计思路与覆盖取舍"，方法级 javadoc 写该用例细节——**测试意图、该用例的设计思路与依据、边界与断言取舍、测试数据选择理由**；这些内容须完整进代码、不得因放入注释而省略。
* **非文档注释（`//`、`/* */`）仅限方法体内使用**，用于说明局部逻辑实现；类、字段、方法签名等结构说明一律用 javadoc（`/** */`）。
* **javadoc 等文档性缺陷直接修复**，遵循通用文档规范。

== 依赖与仓库（Clojars）

* **Clojure/Clojars（`clojars`）构件按次序取源（L2）**：Clojars 生态的第三方构件**可能已由中央仓镜像一并代理**——候选源的取值要求＝**该构件在该源已实测可取到**；**取不到时才另加 Clojars 源**。**不得凭镜像名假定某镜像已代理该构件**：`org.clojure/clojure` 一类坐标**本就不在 Clojars**（它来自中央仓）——这是「坐标归属搞错」、不是镜像失效。
