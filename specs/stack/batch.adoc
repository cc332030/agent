= Windows 批处理脚本规范（技术栈层）

适用于 Windows 批处理脚本（`.bat`/`.cmd`，由 `cmd.exe` 解释执行）。跨所有脚本语言的通用格式规则见 `specs/general/script.adoc`；本文件只收录本栈专属规则。换行符（行尾）的权威口径见 `specs/general/encoding.adoc`「换行符」，本文件只重申本栈的取值。**本文件是批处理（`.bat`/`.cmd`）专属规则的唯一落点**——`.ps1` 的规则见 `specs/stack/powershell.adoc`，需要 PowerShell 能力时按该文件「启动脚本（同名 `.bat`）」由同名 `.bat` 承接。

== 编码与行尾

* **行尾 CRLF，不得 LF（L1）**：`.bat`/`.cmd` **一律落盘 CRLF**。`cmd.exe` **按字节读行尾、不做归一化**，LF-only 的批处理会**直接执行失败**（`goto`/标签匹配、`if`/`for` 等复合语句、行尾注释与续行都可能失效；依据：Microsoft Learn 的 Windows 命令参考）。行尾由 `.gitattributes` 的 `*.bat text eol=crlf`/`*.cmd text eol=crlf` 声明，不靠人工逐个文件手动调整。
* **编码用纯 ASCII，不写 BOM（L1）**：`.bat`/`.cmd` 会被 `cmd.exe` 按**系统 ANSI 代码页**（简体中文 Windows 为 GBK/CP936）解析——**带 BOM 的 UTF-8** 会把 BOM 并入首行指令，**含非 ASCII 字符的 UTF-8** 会被按该代码页解析成乱码。故批处理**指令一律用纯 ASCII 写**：路径与参数用 `%~dp0`/`%*` 一类变量表达、不硬编码中文；需要中文提示/输出时由同栈外的同名 `.ps1` 承载。**写入纯 ASCII 的文件天然不带 BOM**（BOM 本身即非 ASCII 字节），故"纯 ASCII"与"不写 BOM"是同一件事的两面；**不得**为了写中文而改用 UTF-8 + BOM——那正是本条要挡的形态。**存量已按本地编码（如 GBK）保存的 `.bat`** 随动迁移——改到该文件时转为纯 ASCII、中文移入同名 `.ps1`，不为此发动全库一次性转换。
* **核对**：`file <脚本>` 应显示 `ASCII` 文本（显示 `UTF-8`/`UTF-8(BOM)` 即说明含非 ASCII 或 BOM、属待改存量）且 `with CRLF line terminators`；`grep -c $'\r' <脚本>` 非 0 即确认为 CRLF。

== 语法与健壮性

* **首行 `@echo off`**：**首行**是字面意义的第一行——之前不得有空行、BOM 或注释（`cmd.exe` 只认首行的 `@` 前缀，首行被让位后每一条命令都会被回显）；不写则每条命令都先被回显，输出里混入命令本身，调用方与 CI 无法从输出判断实际执行了什么；需要临时回显个别命令时用 `@` 前缀而不是去掉 `@echo off`。
* **块语句里不用 `%var%` 取循环变量（L1）**：`if`/`for` 的**括号块**与 `for` 体内，`%var%` 在**解析期**就被展开（不是执行期），在同一个块里刚赋的值取不到——典型失效是循环里累加/拼接得到空值或首轮值。改用**延迟展开**：先 `setlocal enabledelayedexpansion`，块内用 `!var!`。**判定标准**：块语句里出现 `%var%` 形式的变量取值——命中即违规。
* **路径必须加引号、变量须先判空（L1）**：Windows 路径常含空格（`C:\Program Files\...`），`if exist %path%`、`cd %dir%` 一类不加引号的写法在含空格时直接报错；变量未定义时 `%var%` 会被**原样替换成空串**（不是报错），于是命令变成残句——故引用路径/文件一律加双引号，并在使用可空的变量前判空（`if "%var%"=="" (...)`）。**判定标准**：出现未加引号的路径变量、或对可能为空的变量直接取用——任一命中即违规。
* **可选的参数用 `%~1` 去引号后再判空**：`%~1` 会剥掉传给脚本时可能带的引号，`if "%~1"==""` 才能正确判断"没有传第一个参数"。
* **"变量未定义"一律当错误（L1）**：不得靠"取到空串"继续往下跑——未定义的变量与"值就是空"在批处理里无法区分，静默继续会把错误推后到更难定位的地方；可空变量须显式判空并给默认值或报错退出。

== 注释与文档头

* **批处理的注释只有 `rem` 与 `::`**：`rem` 是标准写法、任何上下文都可用；`::`（标签形态）在**括号块内不可用**（`::` 会被当成标签，块内标签会破坏块解析）——块内注释一律用 `rem`。
* **无文档注释机制，文档头用连续的 `rem` 行（L1）**：批处理**没有**专门的文档注释语法，故脚本的文档头按 `specs/general/script.adoc`「脚本文档的承载位置与协作粒度」的**第二优先级**承载——用**连续多行 `rem`** 放在文件开头（`@echo off` 之后），**不得**降格成零散单行注释，也**不得**用 `::` 当文档头（`::` 依赖标签语义、在块内与部分工具链下不可靠）。**判定标准**：文档头被拆成零散 `rem`/`::`、或文档头里出现中文（批处理须纯 ASCII，中文说明应放同栈外的 `.ps1` 或转为英文）——命中即违规。

== 作为跨环境入口（Windows 与 Linux 并存时）

* **`.bat`/`.cmd` 只做薄壳、Windows 入口按「跨环境脚本（入口 + 跨平台逻辑 + 实现语言取舍）」执行（L1）**：同一功能要在多个操作系统上跑时，逻辑**只写一份**放跨平台逻辑代码，`.bat`/`.cmd` 只作为**入口**、原样透传参数与退出码——职责只有三件：**定位逻辑代码、用 `%*` 把全部参数原样转交、用 `exit /b %errorlevel%` 把逻辑代码的退出码作为自己的退出码返回**（外加解释器/运行时找不到时报一句错并退出非 0）。**不得**在入口里做参数解析、路径拼装、分支判定，也**不得**为 Windows 另写一遍逻辑。
* **`.bat`/`.cmd` 的头部注释只写入口自己**：判据属通用层、唯一落点＝`specs/general/script.adoc`「脚本头部注释（文档头）」下的「入口的注释边界（L1）」；本文件的取值＝批处理用 `rem`/`::` 行注释、不另起块注释。
* **`exit /b %errorlevel%` 是必须写的（L1）**：批处理**不写**时，脚本退出码是**最后一条命令**的退出码、不等于逻辑代码的退出码——这是"看起来在转交、实际丢失成败"的最常见形态。参考形态：

[listing]
----
@echo off
python "%~dp0foo.py" %*
exit /b %errorlevel%
----

  `%~dp0` 为当前 `.bat` 所在目录（含结尾 `\`），使**没写 shebang 的可执行位、从任意目录或双击启动**都能定位到逻辑代码；以逻辑代码的**绝对路径**调用、不 `cd`（保留调用方的工作目录）。
* **入口的位置与命名**：本栈取值＝逻辑 `foo.py` → 入口 `foo.bat`（或逻辑 `foo.ps1` → 启动 `foo.bat`），**不另建 `windows/`、`bin/`、`script/` 目录**；判据属通用层（见 `specs/general/script.adoc`「入口层须与逻辑代码同处一目录、同名不同扩展名」）。本栈另有一条：调用方**只输 `foo.bat`、`foo.cmd`（或双击）就能跑**——不得要求调用方加 `cmd /c`、`powershell -File`、`-ExecutionPolicy Bypass` 一类前后命令。
* **入口语言选择（入口的语言取值）**：Windows 入口**取 `.bat`/`.cmd`**（`cmd.exe` 是系统自带）——判据属通用层，见 `specs/general/script.adoc`「入口语言取舍」。本文件的反例面：`.py`/`python foo.py`、`.sh` 当 Windows 入口、或要求先改 PowerShell 执行策略。
* **需要 PowerShell 能力时按本文件写法由 `.bat` 承接**：**`.ps1` 无法直接双击运行、且受执行策略限制**，故**批处理是 Windows 侧的启动入口**——`@echo off` + `powershell -ExecutionPolicy Bypass -File "%~dp0foo.ps1" %*` + `exit /b %errorlevel%` **三条齐备**，`.bat` 与 `.ps1` **同名**、成对存在、**同步维护**（`.ps1` 改名/移动时同步改同名 `.bat` 的对应调用，避免启动入口失效）；**不要求用户手动修改系统执行策略**。
* **不把 PowerShell 语法写进 `.bat`（L1）**：`$LASTEXITCODE`/`$env:VAR`/`Write-Host` 一类写法在 `cmd.exe` 里不存在，混写出来的 `.bat` **一条都跑不通**；需要这些能力就写 `.ps1`、由同名 `.bat` 启动。**判定标准**：`.bat`/`.cmd` 里出现 `$` 开头的变量、cmdlet 名（`Write-Host`/`Get-ChildItem`）、或 PowerShell 的 `-eq`/`-ne` 运算符——命中即违规。
* **多行拼接用 `^`、续行后不留尾随空格（L1）**：`^` 之后若有**尾随空格/制表符**，转义的是那个空格而不是换行，命令会被截断成非预期的一段（这是"多行命令莫名丢失后半段"的最常见成因）。行尾注释用 `::` 或 `rem`；`goto :eof` 亦可作块内提前返回。
* **转义例外（应当遵守）**：`cmd.exe` 无法原样承载某些字符（`%`、`^`、`&`、`|`、`<`、`>`、`!` 在延迟展开下），此时入口**可以**按平台语法转义，但**不得改变参数的值**。

== 其他

* 代码结构与命名遵守 `specs/general/coding.adoc`；批处理可读性天然弱，保持每个 `.bat` 只做一件事（跨环境时即"薄壳三件事"），逻辑下沉到跨平台逻辑代码。
