= 公共任务提示词（入口）

本文件是**公共任务提示词**的统一入口与登记索引。提示词按任务场景组织、复制即可直接使用，用于让 AI 干活时不漏步、不偷懒、高质高效。**提示词不是规范**：不随 `specs/` 分发、不进规范加载链。

== 访问与解析

* 提示词正文存放于本文件所在目录下的 `prompts/` 子目录，与规范 `specs/` 相互独立、互不干扰。
* 引用方无需引入本入口：提示词按需打开对应文档，把其中 `[listing]` 代码块内的文字**完整原样**复制给 AI 作为任务指令即可。
* 提示词措辞通用、不依赖具体技术栈；项目已接入 agent 规范时，AI 读取项目规范入口后自行遵守规范。
* 公共片段与 AI 读取：提示词正文可能用 `include::_common.txt[tag=…]` 引用公共片段（link:prompts/_common.txt[]）——渲染视图下片段已展开、内容完整；**AI 以文本形式读取而该指令未展开时，须先读取 link:prompts/_common.txt[]（远程：https://agent.c332030.com/prompts/_common.txt）取出对应 tag 的内容补齐后再执行，不得因未展开而跳步或漏掉公共步骤**

== 提示词登记（按任务场景）

* link:prompts/review.adoc[] — **项目问题检查修复**：读取规范、同步主分支、全量检查代码/文档/测试问题成清单，**明确无争议的问题与文档/测试问题直接修复**、**不明确或有争议的问题集中确认后处理**，补齐落点、回归自检、最终验证，按执行环境交付。**以检查修复为主、没有问题原则上不重构**（不得夹带重构性质改动）；详细步骤以该文档为准。
* link:prompts/refactor.adoc[] — **项目重构**：读取规范、同步主分支、逐模块检查现状并输出重构方案（含预期收益与取舍）、实施结构重构、补齐文档与用例、性能对比与迭代优化（仅对判定为性能敏感点的代码做性能测试，不乱加也不漏）、回归自检、最终验证，按执行环境交付。**以重构为目标：检查必须做（是重构的前提），产出必须是真正落地的结构改动，不得只检查/只出报告**；详细步骤以该文档为准。

* 公共约定（二者一致，展开见 link:prompts/_common.txt[]）：**交付按执行环境区分**——本地人工场景不提交不推送（改动留本地交人工），CI/CD 等自动化场景必须提交推送（否则随环境销毁丢失）；**最终验证**须全量编译与全量测试通过、无规范违规。
* 二者分工（**重点不同、勿混用**）：link:prompts/review.adoc[] 以"**检查修复问题**"为目标——检查出问题就修，无问题即结束，原则上不重构（明确无争议的直接修，不明确/有争议的先确认）；link:prompts/refactor.adoc[] 以"**重构**"为目标——检查服务于重构，产出必须是结构改动。**review 时不得顺手重构无关紧要的代码，重构时不得只检查/只出报告。**

== 维护约定

* 新增提示词：在 `prompts/` 下新增文件（命名与任务场景对应，正文含文档说明 + `[listing]` 可复制代码块），并同步在本文件登记，文件必须真实存在
* 公共片段（`_` 前缀）：文件名以 `_` 开头者为**提示词公共片段**（如 link:prompts/_common.txt[]）——存放多个提示词之间**完全相同**的段落，由各提示词在代码块内用 `include::` 引用共用，改一处即各处同步；**不是提示词**，不单独复制使用、不在本文件登记。新增/调整提示词时，相同内容一律抽到公共片段并用 `include` 引用，不重复书写
* 完整性要求：抽离共用**不得影响提示词的完整可用**——`include::` 由 AsciiDoc 解析时展开，须保证渲染视图下展开后**步骤齐全、语义连贯**（不得因抽离而缺步骤、断句或丢约束）；以纯文本查看（`include` 未展开）时，按公共片段文件的说明获取对应内容后一并使用
